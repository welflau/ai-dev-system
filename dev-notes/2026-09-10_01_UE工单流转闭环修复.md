# DevNote · 2026-09-10（四）

**类型**: 工单流转修复 —— UE 工单无法自主闭环
**状态**: 已落地，stub 探针 4 组用例全绿（未经真实 LLM / UE Editor 端到端验证）
**触发**: 排查「系统能否自主处理 UE 工单，从需求到开发到测试到完成」

---

## 一、问题

用 stub 替换全部 Agent（不调 LLM / 不编译 / 不起 UE）驱动状态机，发现即使每步都成功，
UE 工单也只能走到：

```
pending → planning_done → architecture_done → development_done
        → engine_compile_passed → play_test_passed → deployed   ← 停在这
```

11 个 SOP 阶段里 **packaged / review_passed / acceptance_passed 三个永不执行**。

生产数据印证：UE 项目 29 张工单，27 取消、1 blocked、**0 通过验收**。
唯一走通 playtest 的 `TK-20260722-8d570f`：

```
10:17:12 TestAgent   engine_compile_passed → play_test_passed
10:17:13 DeployAgent play_test_passed      → deployed      ← 应为 packaged
10:18:58 DevAgent    deployed              → blocked
```

---

## 二、根因与修复

### 1. DeployAgent 状态硬编码撞上硬终态（主因）

`deploy_ue.yaml` 声明 `success_status: packaged`，后接 `packaged → ReviewAgent.code_review`。
但 `orchestrator.py` 的 DeployAgent 分支不区分 action，一律写 `deployed`：

```python
elif agent_name == "DeployAgent":
    new_status = TicketStatus.DEPLOYED.value   # run_ci_deploy 也走这里
```

`deployed` 属于 `_HARD_TERMINAL` → `process_ticket` 直接 return，审查+验收整段跳过。
对比 DevAgent / TestAgent 都有 `if action == ...` 分支，DeployAgent 漏了这层。

**修复**：新增 `_sop_stage_for()` / `_sop_success_status_for()`，按项目 traits + 工单 type
读 SOP 声明的 `success_status`，`default` 兜底。

> 第一版直接写死 `packaged`，改完发现会弄坏 Web —— `deploy_web.yaml` 和 `deploy_ue.yaml`
> 用**同一个** `action: run_ci_deploy`，但 success_status 一个 `deployed`（终态）
> 一个 `packaged`（中间态）。硬编码任一个都会破坏另一类项目。

### 2. UEEditorAgent 是死代码

`ue_content_gen.yaml` 要求 `required_ticket_type: ue_content`，但 `_get_rules_for_project`
硬编码 `compose_sop(traits=traits, ticket_type=None)`，`_fragment_matches` 中
`ticket_type is None` 直接 `return False` → 该 fragment 永不组装，UEEditorAgent 零调度。

**修复**：`_get_rules_for_project` 增加 `ticket_type` 参数（cache key 同步扩成 3 元组），
3 个调用点传入工单实际 type。

`_get_all_actionable_statuses` 另需按 type 展开求并集 —— 否则 type 相关状态
（如 `ue_content_pending`）扫不到，工单卡死不动。

### 3. 只改传参会造成无限循环（连带必修）

`_handle_agent_result` 没有 UEEditorAgent 分支 → 落到末尾 `else: new_status = current_status`
→ 状态不推进 → 同一条 rule 反复命中 → UEEditorAgent 无限重跑。

**修复**：补 UEEditorAgent 分支，success → `ue_content_done`（落 artifact），
否则 → `ue_content_failed`。

### 4. `reject_goto` 写成状态名而非 stage id

`ue_content_gen.yaml` 原写 `reject_goto: ue_content_pending`。
`sop_to_transition_rules` 用 `stages_by_id.get(reject_goto)` 查找，查不到 →
`ue_content_failed` 无规则 → 死路。

**修复**：改为 `reject_goto: ue_content_gen`（指回本 stage 重试，`max_retries: 2` 止损）。

## 三、连带暴露的既有 Bug

改动让 type-gated fragment 首次真正生效，暴露 3 个此前被掩盖的问题：

| 问题 | 现象 | 修复 |
|---|---|---|
| `asset_gen.yaml` 引用未实现的 `ArtistAgent` | 游戏项目 feature 工单卡 `architecture_done` 死循环 | 加 `_disabled:` trait 关停，实现后改回 |
| `smoke_test` 复用 `run_tests`，但 orchestrator 写死 `testing_done`（硬终态） | Web feature 工单在冒烟测试后提前终结 | 同样走 `_sop_success_status_for`；成功分支判据由 `== TESTING_DONE` 改为 `!= TESTING_FAILED` |
| `ux_design.yaml` 的 `insert_after: requirement_analysis` 是 pipeline_view key 不是 stage id | UX/美术阶段被追加到 `deployed` 之后 | 改为 `insert_after: planning` |

另加防御：Agent 未注册时不再只 `return`（状态不变→轮询无限重试刷错误日志），
改为标 `blocked` 转人工。

## 四、验证

stub 探针 4 组用例（临时脚本，验证后已删）：

| 用例 | 断言 | 结果 |
|---|---|---|
| UE_CONTENT | 12 阶段全达 + UEEditorAgent 被调用 | PASS |
| UE_FEATURE | UE 全链路 + UEEditorAgent **未**被调用 | PASS |

| UE_CONTENT_RETRY | UEEditorAgent 首次失败后重试恢复，无死循环 | PASS |

修复后 UE 内容工单实际流转：

```
planning_done → ux_design_done → art_design_done → architecture_done
  → ue_content_done → development_done → engine_compile_passed
  → play_test_passed → packaged → review_passed → acceptance_passed → deployed
```
