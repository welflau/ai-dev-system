## 三层融合 Step 9-10 — OpenSpec Propose + Verify 集成

### Step 9：ArchitectAgent 触发 `opsx:propose`（`agents/architect.py`）

架构设计完成后，自动触发 OpenSpec Propose，生成规范四件套。

**新增方法 `_run_openspec_propose(context)`**：

| 步骤 | 处理 |
|---|---|
| `has_openspec()` 检测 | 未安装 → 静默跳过，不影响主流程 |
| `get_openspec_cli()` 获取命令 | opsx / openspec-cn / openspec |
| 执行 `opsx propose "{title}: {desc}"` | stdin 注入 `\n×5` 自动确认 harness 选择 |
| 成功 | `openspec_stage='proposed'` + 里程碑评论通知 + `layer=spec` 时间轴日志 |
| 失败 | 只记 warning 日志，不阻塞工单继续 |

**执行时机**：`_post_architecture_milestone()` 完成后调用（架构完成 → 里程碑通知 → OpenSpec Propose）。

---

### Step 10：TestAgent 触发 `opsx:verify`（`agents/test.py`）

测试全绿后，触发 OpenSpec Verify，逐条对账 GIVEN/WHEN/THEN。

**新增方法 `_run_openspec_verify(context)`**：

| 条件 | 处理 |
|---|---|
| `all_passed = False` | 不触发（测试未全绿） |
| 项目未安装 OpenSpec | 静默跳过 |
| 无 `specs.md`（propose 未跑过） | `ticket_has_specs()=False` → 跳过 verify |
| Verify 通过 | `openspec_stage='verified'` + 里程碑通知 ✅ |
| Verify 失败 | 工单 `blocked` + error 级通知 + 等人工介入 |

**执行时机**：`run_tests()` 末尾，`all_passed=True` 时调用。

---

### 完整兼容矩阵

```
项目未安装 OpenSpec
  → has_openspec()=False → 全程跳过 → 正常 ADS 流水线

项目已安装 + Propose 成功
  → openspec_stage = 'proposed'
  → specs/design/tasks 写入 openspec/changes/{ticket_id}/

测试全绿 + Verify 成功
  → openspec_stage = 'verified' ✓

测试全绿 + Verify 失败
  → 工单 blocked → 人工介入确认哪条 spec 未满足

无 specs.md（Propose 跳过或失败）
  → ticket_has_specs()=False → 跳过 Verify → 测试通过继续
```
