## 二、把 priority 改成**反向**，让 demo 链自证排序

初版 SKILL.md 的 priority 是 outline=70 / draft=50 / cover=30——**恰好与依赖顺序一致**。

这意味着「拓扑排序生效」在 demo 链里不可观测：只按 priority 排也能得出同样结果。跑了一次反向实验确认：

```python
flipped = {cover:99, draft:50, outline:1}
→ ORDER: ['demo_outline', 'demo_draft', 'demo_cover']   # 依赖仍是硬约束
```

于是把 SKILL.md 的 priority 直接改成 **cover=90 / draft=50 / outline=20**，并在注释里写明「刻意与依赖顺序相反」。

效果立竿见影：注入「拓扑排序退化成纯 priority 排序」→ **6 个 e2e 测试红**。如果 priority 同向，这个注入一个都抓不到。

**可复用的做法**：当 fixture 的某个属性恰好与被验证的性质同向时，主动把它调成反向——让测试数据本身成为证据，而不是巧合。

## 三、新增内置 skill 打破了 14 个测试的隐含前提

加完 demo-* 后 14 个测试红。根因：它们假设「内置目录零 workflow skill」——v0.20 之前那里只有 openspec-*（没有 x-workflow），于是这个前提被当成了常量。

**红得有道理**：往内置目录加一个 skill 就让不相关的测试失败，说明隔离没做够。

加了 `tests/conftest.py` 的 autouse fixture 把 `_BUILTIN_ROOT` 指到空目录，需要真实 skill 的测试用 `@pytest.mark.real_builtin_skills` 显式覆盖（只有 3 处：`load_executable_skill` 回归保护、项目级优先级、e2e 整体）。

12 个自动修好，剩 2 个加标记。

## 四、e2e 测试驱动器的两个 bug（都是我写的）

### a) 从 pending 起步却只处理 SkillAgent

第一版驱动循环见到非 SkillAgent 规则就 `break`，而 `pending` 对应的是 `PlannerAgent`——**第一轮就退出，trace 为空**。

不能直接把工单状态塞成第一个 skill 的 trigger：那会跳过「skill 链接在 base_stages 之后」这个事实，等于绕开 relink 的状态链验证。改成遇到非 skill 阶段就推进到它的 `success_status`，保留完整的状态轨迹。

### b) `await body(...)` 但 body 是同步函数

`RuntimeError: coroutine raised StopIteration`。改成 `asyncio.iscoroutine` 判断后兼容两种。

顺带清掉了 v3 里一段写坏的死代码（`asyncio.run(...) if False else None`）。

## 五、第 10 次假绿：`is_binary` 标记错了但字节完好

注入「`is_binary` 恒 False」→ e2e 全绿。

`test_v4` 只断言「PNG 字节完好」。但 **ArtifactStore 用 `shutil.copy2` 复制文件，根本不读内容**——标记错了字节照样完好。

真实危害在 `text_outputs`：它靠 `is_binary` 决定跳过谁，标记错了就会把 PNG 读成字符串。

补强成三段断言：字节完好 + `is_binary is True` + **`text_outputs` 确实跳过它**。再注入立刻红。

10 的特点：断言的对象（字节）和被测的机制（标记）之间隔了一层不读内容的实现。**要连「这个标记的下游行为」一起验。**
