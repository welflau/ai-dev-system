# DevLog：ue_lint R10 空引用规则

> 日期：2026-11-06
> 关联：`docs/20261105_07_QA日志闭环设计方案.md` 4.3.1（Phase 3b 替代路线）
> 位置：`plugins/ue5/actions/ue_lint/rules.py`

## 目标

延续 R9 的 ue_lint 交互检查扩展，落地第二条：R10 空引用守卫。

## 设计

R10 检查**交互回调**（`AddDynamic` / `BindAction` 绑定的函数）体内是否有 `IsValid` 空引用守卫。

**关键决策**：
1. **warning 级别（非 blocking）**：同 R9，保守不阻塞。
2. **只检查「有无 IsValid」，不分析「访问了哪个对象」**：静态分析对象生命周期太复杂，确定性规则只做"有/无守卫"的判断。
3. **跨文件回调定义跳过**：绑定在本文件但回调定义在别的文件（如 .h 声明 .cpp 定义分离），`_find_func_body` 找不到定义体就跳过，不误报。

## 实现

- `_RE_BIND_ACTION`：正则提取 `BindAction("Name", IE_Pressed, this, &Class::Func)` 的回调名。
- `_find_func_body`：从 `返回类型 类名::函数名(...)` 找到定义，花括号匹配定位函数体。
- `rule_R10_null_guard`：收集回调名（AddDynamic + BindAction）→ 找函数体 → 检查含 `IsValid`。

## 验证（6 场景全过）

| 场景 | 结果 |
|---|---|
| 回调有 IsValid | ✅ 不报 |
| 回调无 IsValid | ✅ 报 1 条 warning，含回调名 |
| BindAction 回调无 IsValid | ✅ 报 warning |
| 跨文件回调定义（本文件只有绑定） | ✅ 跳过 |
| 逃生注释 | ✅ 不报 |
| 无交互绑定 | ✅ 不报 |

## 后续

- R10 与 R9 同框架（确定性正则 + warning 级别 + 逃生注释），可安全上线。
- 可继续加 R11（交互回调递归触发自身），实现方式类似：提取回调名 → 函数体内检查是否调用自身。
