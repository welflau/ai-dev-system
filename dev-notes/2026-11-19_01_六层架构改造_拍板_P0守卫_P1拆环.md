## 三、P1 拆两组小环（提交 080ae51）

### 3.1 checkpoint 环（`checkpoint` ↔ `checkpoint.service` ↔ `git_manager`）

边的构成：`checkpoint/__init__.py:9` re-export service；`service.py:15` `from checkpoint import store` 回指包自身；`service.py:432/497/512` 延迟 import `git_manager`；`git_manager.py:497/526` 延迟 `from checkpoint.service import checkpoint_service`（写盘前拍照）；`git_manager.py:204/386` 延迟 import `checkpoint.context`（叶子，无环）。

方案 §7 原文是「`checkpoint.service` ↔ `git_manager` 改事件」，但 `events.py publish` / `event_bus.py` 是异步队列，会让「先拍照后写盘」异步化、**拍到改后内容**。故改为**同步回调注册**，时序不变：

| 改动 | 说明 |
|---|---|
| `backend/checkpoint/context.py` | 新增 `set_before_write_capture(fn)` / `get_before_write_capture()`，叶子模块持有回调 |
| `backend/checkpoint/service.py:15` | `from checkpoint import store as blob_store` → `import checkpoint.store as blob_store`，消除包自环 |
| `backend/checkpoint/service.py` 末尾 | 注册 `checkpoint_service.capture_from_active_context` |
| `backend/git_manager.py::write_file`/`write_files` | 两处延迟 `from checkpoint.service import ...` → `from checkpoint.context import get_before_write_capture`，仍同步 `await`，异常兜底保留 |

`checkpoint/__init__.py` 仍 import service，因此 `git_manager` 首次 `from checkpoint.context import ...` 时钩子已装配（已验证：只 import git_manager 时钩子非 None）。全仓确认无 `from checkpoint import checkpoint_service`，其余 12 处外部调用都是 `from checkpoint.service import ...`，不受影响。

### 3.2 memory_mcp 环（`memory_record_index` ↔ `memory_record_io`）

`IDX:11` 顶层 `from .memory_record_io import safe_read_text`；`IO:311` 在 `refresh_index_if_exists` 里延迟 `from .memory_record_index import memory_update_index`（写后 best-effort 刷新 FTS 派生索引），形成 2-环。

方案 §7 原文「抽公共 DTO」不对症：IO 唯一 DTO 是 `ParsedRecord`，IDX 完全不用（用裸 tuple），两边交换的是工具函数与业务函数。改为**抽公共工具模块**：

- 新建 `backend/tools/memory_mcp/servers/memory_server/memory_text_io.py`，把 `safe_read_text`（IO:54-86，33 行）搬过去，纯叶子（只依赖 time/pathlib）。
- `IO` 顶部 `from .memory_text_io import safe_read_text` re-export，保 `memory_reader.py:8`、`memory_search.py:8` 等 6 个下游导入方不变；IO 自身 `:332/:421` 调用也照常。
- `IDX:11` 改指向叶子模块。
- `IO:311` 的延迟 import 保留（单向，不再成环；它是 L2→L1 语义上的反向边，属 P3 净化范围，P1 只要求消灭环）。

### 3.3 配置与基线

- `layers.toml`：删掉两条已清零的 `until=P1` 豁免，`phase` 推进 `P1`；保留 `plugins.registry ↔ skills.loader` 的 P2 预留条目。

### 13 条反馈弧归类（探查已逐条定位）

| 类别 | 条数 | 代表边 | 形态 |

| 反向依赖回 orchestrator | 7 | `agents.dev/architect/deploy/test → orchestrator`、`actions.chat.get/pause/resume_requirement → orchestrator` | 全为函数内延迟 import，读单例方法/状态/派单 |

### 收敛判断（如按 SCC→1 推进）

- `agents.*/actions.chat.* → orchestrator` 高度收敛于单例的 3 个方法（`post_milestone_comment` / `_add_layer_log` / `_maybe_openspec_verify`）+ 3 个状态属性（`_sop_config` / `_project_active` / `_processing`）+ `process_ticket` 派单。可仿 P1 手法做一个叶子「运行时状态 + 回调注册」模块，原地换成取 callable / 共享状态，`await` 与同步时序不变。
- `plugins.registry ↔ skills.loader`：把纯函数 `_parse_frontmatter`（`skills/loader.py:774`）抽到叶子 `skills/frontmatter.py`。
- `sop.loader ↔ sop.workflow_composer`：把纯函数 `_fragment_matches`（`sop/loader.py:453`）抽到叶子 `sop/matching.py`。
- **不能用异步事件**（`events.py publish` / `event_bus.py` 是队列）：`_save_chat_message` 等被 `await` 且须先落库再返回，fire-and-forget 会改时序 —— 与 P1 同一结论。
