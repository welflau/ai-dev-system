## 三、修掉的 Bug

### 1. `ue_python_bridge` 查了不存在的列（先决条件）

```python
"SELECT local_repo_path FROM projects WHERE id = ?"   # 实际列名 git_repo_path
```

实测抛 `no such column: local_repo_path`，异常被 `except` 吞掉（且是 `logger.debug`，
日志里几乎看不见）→ `_get_project_hint` **永远返回空串** →
多 Editor 场景无法定位目标 Editor，只能盲取 `nodes[0]`。

验证时正撞上这个场景：两个 Editor 在跑（FOG/S7、OG2/IMMO_Client），
桥接测试连到了 `IMMO_Client`（用户的工作环境）。

**修复**：改查 `git_repo_path`，并优先用 `uproject_path`（能直接匹配 `project_root`）。
修复后 6 个项目的 hint 全部正确返回。

### 2. ue_lint 误报率 100%（核心发现）

真实 UBT 编译（325s，exit=6）给出**真值**：

```
error C2039 SkillManagerComponent.cpp:53  "AddWeakLambda" 不是 FPawnControllerChangedSignature 的成员
error C2665 SkillManagerComponent.cpp:83  BindAction 无重载匹配（TObjectPtr<UInputAction> → const FName）
```

**只有 2 个错，都在同一文件。** 而修复前的 lint 报了 **11 个 blocking**，
两组**完全不重叠** —— 即误报 11 个、漏报 2 个，准确率为 0。

| 规则 | 误报数 | 根因 |
|---|---|---|
| R3 | 8 | 「彻底找不到」分支只扫项目 `Source/`，看不见引擎头（`TimerManager.h`）和插件头（`EnhancedInput*.h`）。UBT 靠模块 include 路径解析，无路径前缀完全合法 |
| R7 | 3 | 只看单文件 include 判类型可见性。UE 的 SharedPCH 已预置 `APawn`/`APlayerController` 等核心类型 —— `FPSCharacter.cpp` 未 include `PlayerController.h` 但**编译通过**（10/13 无错） |

**危害**：这些 blocking 会让 `SelfTestAction` 返回 fail → 工单不进 `engine_compile`
直接走 `fix_issues` 循环 → 反复重写能编过的代码 → `blocked`。
与 01 note 里记录的「`engine_compile_failed` 连续空转 5 次烧 token」同源。

**修复原则：判不了就别判 blocking。**

- R3「找不到」→ 降级 warning，提示语区分「已知引擎/插件头」与「可能笔误」
- R7 → 新增 `_PCH_LIKELY_COVERED_TYPES`（22 个 PCH 高频类型）。
  命中则降级 warning（IWYU 风格问题），未命中（如 `UCapsuleComponent`）仍 blocking

真实存在性/可见性交给下游 `engine_compile` 用真实编译定性 —— 这才是正确分工。
