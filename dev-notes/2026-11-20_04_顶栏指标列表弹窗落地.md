## 调研结论

- 两个按钮此前**不可点**，纯展示计数。
- 「处理中 N」= `len(orchestrator._processing)`（内存工单 ID 集合），明细有现成端点
  `GET /api/agents/orchestrator`（`active_agents` / `queue_preview` / `queue_count` 等）。
- 「异步任务 N」= `asyncio.all_tasks(loop)` 未完成 Task 数（进程内全部协程），
  **无任何明细 API / DB 表**，必须新增端点。之前猜的 image_processor / automation / CI 队列都不对。
- `hooksPanel` 是「点击顶栏徽标 → 锚定下拉列表」的完全同构范式，CSS `.hooks-panel` 系可直接复用。

## 关键设计

- **口径一致**：`/api/metrics` 的 `asyncio_tasks` 与明细端点都是「all_tasks 未完成 task（含当前请求自身）」。
  明细端点**不排除**当前请求，只用 `self:true` 标记，否则列表会比数字少 1。
- **不泄漏**：`get_stack()` 只取 `文件名:函数名:行号`，不读局部变量；逐字段 try/except 兜底。
- **三面板互斥**：`_closeOtherMetricPanels(keep)` 打开一个收起 hooksPanel 与另一个。
- **状态变量前置**：两个 `let` 声明放在 `refreshMetrics()` 之前 —— `refreshMetrics()` 在脚本加载末尾
  立即执行，若 `let` 在后面会因 TDZ 抛 ReferenceError。这是本轮一个隐蔽坑，已修。
- **列表截断**：异步任务明细最多 50 行、处理中队列前 5 条，都有「仅显示前 N 条，共 M 条」提示。

## 实现过程中的两个坑

1. **bash heredoc 里写 JS 模板字符串报 `Bad substitution`**：`${escHtml(...)}` 被 shell 当变量展开。
   改为先用 Write 工具把 JS 块写到临时文件（纯字符串拼接、不用模板字符串），
   再用 python 读文件拼接进 app.js，最后 `rm` 清理临时文件。
2. **app.js 含字面 NUL 字节**（`.gitattributes` 注释里提到过），curl 下来 grep 会报
   "Binary file matches"。改用 python `urllib.request` 读字节再 `.count(b'...')` 核对。

## 边界

- 明细是进程内即时快照，两次请求间数字自然变化，5s 刷新时数字与列表可能差 1~2，属正常。
- 面板打开时每次 5s 轮询会各发一个 GET（两个面板最多 2 个），开销可忽略。
