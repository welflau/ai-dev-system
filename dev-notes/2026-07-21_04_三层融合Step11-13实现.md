## 三层融合 Step 11 — OpenSpec 内容面板

### 后端 `backend/api/openspec.py`

新增端点 `GET /openspec/ticket/{ticket_id}/specs`：
- 读取 `openspec/changes/{ticket_id}/*.md` 所有文件内容
- 返回 `files`（按文件名 key）+ `openspec_stage`（来自 tickets 表）
- 目录不存在时返回 `initialized: false`，前端静默跳过

### 前端 `frontend/app.js`

**`_loadTicketOpenSpec(ticketId)`**（新函数）：
- 调 `/openspec/ticket/{id}/specs` 异步加载
- 有 specs 才显示面板，无则隐藏（零侵入）
- Tab 切换：`📋 Proposal` `✅ Specs` `🏗 Design` `📝 Tasks` `📜 变更记录`
- `openspec_stage` 印章徽章（proposed紫 / verified绿 / archived灰），微旋转 `-1deg`
- Markdown 渲染（复用 `marked.js`）
- 在 `openTicketDrawer()` 的 `drawerBody.innerHTML = html` 后调用

**工单抽屉结构**（有 specs 时）：
```
能力提示横幅
基本信息
[产出文件]
📐 OpenSpec 规范  [📐 Verified ✓]
  [📋 Proposal] [✅ Specs] [🏗 Design] [📝 Tasks]
  ────────────────────────────────────────
  Markdown 渲染内容（max-height: 360px）
进展时间轴
```

### CSS
`.openspec-tabs` / `.openspec-tab(.active)` / `.openspec-content` / `.openspec-md` 样式

## 三层融合 Step 12 — 时间轴三层颜色标注

### `renderLogItem` 扩展

在函数开头读 `log.layer` 字段，按层级着色：

| 层级 | 颜色 | 图标 |
|---|---|---|
| `spec` 规范层 | 紫色 `#a855f7` | 📐 |
| `discipline` 纪律层 | 橙色 `#f59e0b` | ⚡ |
| `harness` 编排层 | 蓝色 `#3b82f6` | 🔧 |

**普通日志**：log-item 加 `.layer-{spec/discipline/harness}` 类（左边框颜色）+ 图标前缀。

**专属 action 快捷渲染**（`_renderLayerLogItem()`）：

| action | 渲染 |
|---|---|
| `openspec_propose` | `📐 OpenSpec Propose 完成` |
| `openspec_verify` | `📐 OpenSpec Verify 通过 ✅` |
| `openspec_verify_failed` | `📐 OpenSpec Verify 失败 ❌` |
| `superpowers_skill` | `⚡ Superpowers 约束已激活` + skills 列表 |
| `phase_reset` | `🔄 阶段重置` + from_phase + reason |
| `change_detected` | `🔍 变更检测` + type + reason |
| `milestone_architecture` | `🔧 架构里程碑` |

## 三层融合 Step 13 — 工单卡片 OpenSpec 印章

**`_buildOpenSpecStampMini(stage)`**（新函数）：
- 仅在 `t.openspec_stage` 有值时渲染
- 印章样式：微旋转 `-1.5deg`，颜色随阶段

  - `verified` → 绿色 `📐✓`
  - `archived` → 灰色 `📐`
- 插入 `renderTicketCard` 的 `.ticket-meta` 行末
