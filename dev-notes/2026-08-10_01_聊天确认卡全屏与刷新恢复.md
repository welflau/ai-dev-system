# DevNote · 2026-08-10（一）

**类型**: 聊天体验修复 — 确认卡 / 全屏 / 刷新记忆  
**状态**: 已落地（需重启后端 + 强刷前端 `?v=20260810c`）  
**相关**: CLI 确认卡推送、`confirm_*` 恢复洪水、回车失效、全屏冲掉会话、刷新跳回全局

---

## 一、问题与根因

| 现象 | 根因 |
|------|------|
| CLI 说「需求草稿已推送」但无绿卡 | CLI 不经 `_ChatToolExecutor`；项目 SSE 常 0 订阅者，前端只见 LLM 文本 |
| 连出多张无关旧卡（地图/移动等） | `_recoverPendingConfirmCards` 扫全会话 pending，刷历史草稿 |
| 回车发送无效 | `sendChatMessage` 在 `let fullMessage` 声明前引用 → `ReferenceError` |
| 切全屏后聊天/确认卡消失 | 退出全屏走 `showProjectDetail` → `_updateChatPanelForContext` 清空会话并刷欢迎页 |
| 刷新后全局聊天空白 | 进全屏后未调用 `loadChatHistory` |
| 刷新总跳到全局 AI 助手 | 无「上次项目/会话/全屏」持久化 |

---

## 二、改动摘要

### 后端

1. **`query_engine/engine.py`**：CLI `cli_tool_result` 对 `confirm_*` 合成 `ActionEvent`（流内主路径）；`MessageDoneEvent` 带 `final_action`
2. **`events.py`**：SSE `publish` 无订阅者时打 warning，便于排查「推了但看不见」

### 前端（`app.js` / `index.html`）

1. **确认卡恢复**：时间窗（本轮发送 ±8s）+ `maxRecover:1` + 与用户话术相关才补；已有卡不刷旧卡
2. **回车**：`_chatLastUserText` / `_chatSendStartedAt` 在 `fullMessage` 构造之后赋值
3. **全屏**：同项目壳层退出只 `remountChatToWorkbench` + 开右栏，不 `showProjectDetail`/`loadChatHistory`
4. **同 context**：`_updateChatPanelForContext` 同项目只改标题；消息区空才补载
5. **打开右栏/面板**：`_chatMessagesHasContent()` 为真时跳过强制 `loadChatHistory`
6. **刷新恢复工作区**：localStorage `ads.chat.lastProjectId` / `lastSessionId` / `fullscreen`；`_restoreChatWorkspace()` 校验项目后恢复
7. **全局历史**：`loadChatHistory` 优先已记住的 session，而非总是最新一条
8. 缓存：`app.js?v=20260810c`

## 三、验收

1. CLI 模式说「创建一个技能系统」→ 流内出现 **1 张**需求确认绿卡  
2. 回车可发送；强刷后仍在上次项目/会话（若曾进入过项目）  
3. 项目内进出全屏，气泡与确认卡保留  
4. 全局刷新能拉回最近（或记住的）全局会话，不是空欢迎页  
5. 后端日志：SSE 无人订阅时有 `SSE publish 无订阅者` warning
