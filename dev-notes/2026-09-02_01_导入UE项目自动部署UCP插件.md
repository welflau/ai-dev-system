# 导入 UE 项目时自动部署 UCP 插件

**日期**：2026-09-02  
**类型**：功能增强

---

## 背景

ADS 侧已有完整的 UE 能力套件（ConfigPack `ue5-dev` / `ue5-prod-skills`、Skills、`ue_call` / `launch_ue_editor` 等），但**已有本地 UE 工程**（如 `GASP-LMM`）的 `Plugins/` 目录不会自动带上 **UnrealClientProtocol (UCP)** 插件。

此前仅 `instantiate_ue_template.py` 在 `install_ucp=True` 时会复制插件；通过聊天路径确认导入已有项目时不会部署，导致 Agent 无法通过 TCP 9876 连 Editor。

---

---

## 触发条件

满足任一即视为 UE 项目并尝试部署：

1. `traits` 含 `engine:ue5` / `engine:ue4` 等 `engine:ue*` 前缀
2. 仓库根目录或一级子目录存在 `*.uproject`

源路径：`backend/ue_plugins/UnrealClientProtocol/`  
目标路径：`{repo}/Plugins/UnrealClientProtocol/`（`dirs_exist_ok=True`，可覆盖更新）

---

## 与套件包的关系

| 层级 | 内容 | 作用 |
|---|---|---|
| ADS 内置 | ConfigPack、Skills、`unreal-client-protocol` 文档 | Agent 知道**怎么**调 UE |
| 工程 Plugins | UCP 实体插件 | Editor 侧**能**收 TCP 指令 |
| Editor MCP | 可选另一路径 | 不依赖项目内 UCP |

**结论**：套件包 ≠ 目标工程已有插件；导入/创建 UE 项目时必须把 UCP 落到工程里。

---

## API 响应字段

```json
{
  "ucp_deploy": {
    "installed": true,
    "skipped": false,
    "path": "F:/.../Plugins/UnrealClientProtocol",
    "message": "UCP 插件已复制到 Plugins/UnrealClientProtocol（请重启 Editor 完成编译）"
  }
}
```

---

## 验收步骤

1. 聊天发送已有 UE 工程路径（如 `F:\A_Works\GASP-LMM`）
2. 确认创建项目卡片 → 点「确认创建」
3. 检查 `{工程}/Plugins/UnrealClientProtocol/UnrealClientProtocol.uplugin` 存在
4. 成功卡 / Toast 显示 UCP 部署提示
5. 重启 UE Editor，编译插件后 `ue_call` 可连通

## 2026-09-02 补充：网页 CLI 误走 WebSearch

**现象**：网页端说「安装 UCP」，助手 ToolSearch → 搜不到 → WebSearch。

**原因**：网页聊天走 CodeBuddy CLI。系统提示写了「调 install_ucp」，模型当成 CLI 工具去搜；ADS 工具实际靠 `[ACTION:INSTALL_UCP]` 文本协议，或本地 `deploy_ucp.py`。

**修复**：
- UE 路由：本地优先（`[ACTION:INSTALL_UCP]` / `deploy_ucp.py`），**仅本地失败后再** WebSearch（不一刀切禁止联网）
- `_tools_to_action_protocol` 触发时机补上 INSTALL_UCP
- 无 `engine:ue*` trait 但有 `.uproject` 时也注入 UE/UCP 路由
- **QueryEngine CLI 路径**：解析到 `[ACTION:…]` 后**真正调用 executor**（原先只塞前端卡片，install_ucp 根本不会跑）

## 2026-09-02 验收：GASP-LMM 上 UCP 安装并编译通过（UE 5.5）

网页 AI 助手对 `GASP-LMM`（`EngineAssociation: 5.5`）完成端到端验证，结论：**UCP 插件已安装并编译通过**。

### 结果

| 项 | 状态 |
|---|---|
| 本地部署 | `deploy_ucp.py --status` → 已安装；`Plugins/UnrealClientProtocol/UnrealClientProtocol.uplugin` 存在 |
| `.uproject` 启用 | `GameAnimationSample.uproject` → `Plugins` 列表含 `"Name": "UnrealClientProtocol", "Enabled": true` |
| UBT 编译 | `GameAnimationSampleEditor`，`exit_code 0` |
| 产物 | `Plugins/UnrealClientProtocol/Binaries/Win64/UnrealEditor-UnrealClientProtocol.dll`（及 Editor 模块 DLL） |

### 做了什么

1. 确认本地已有 UCP（先前 `deploy_ucp` / 自动部署）
2. 将 `UnrealClientProtocol` 写入 `.uproject` Plugins 并启用
3. 用 UE 5.5 的 UnrealBuildTool 编译 Editor 目标

### 关键：UCP 源码面向 UE 5.6+，在 5.5 上做了适配

ADS 内置快照按 **UE 5.6+** 编写；GASP-LMM 为 **5.5**，编译时因引擎未导出 API 报错。助手用 `#if ENGINE_MINOR_VERSION >= 6` 做了 **5 处**条件编译适配（工程内插件副本），其中包括：

| 位置 | 问题 | 5.5 处理 |
|---|---|---|
| `PneumaView/PneumaViewViewport.cpp` | `AdvancedPreviewSceneMenus.h` 等为 5.6+ UI toolbar API | 5.5 下相关 UI 工具栏分支置空 / 条件编译掉 |
| `Niagara/NiagaraOperationLibrary.cpp` | `SetLinkedParameterValueForFunctionInput` 为 5.6+ | 5.5 改用 `SetLinkedValueHandleForFunctionInput` |
| （另 3 处） | 同类 5.6+ 未导出 / 签名差异 | 同样用 `ENGINE_MINOR_VERSION >= 6` 分支 |

### 经验与后续

- **部署 ≠ 可用**：复制插件后还需 `.uproject` 启用 + 按目标引擎版本编译。
- **引擎小版本差**会导致 UCP 编不过；5.5 适配目前落在 **GASP-LMM 工程内副本**，尚未回写 ADS `backend/ue_plugins/UnrealClientProtocol` 快照。
- 可选后续：把 5.5 兼容补丁合回 ADS 源快照，避免下次 `deploy_ucp --force` 覆盖后再次编挂。
