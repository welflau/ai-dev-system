# DevLog：ue_lint R12 Timer 配对规则

> 日期：2026-11-06
> 关联：R9-R11 交互检查规则（Phase 3b 替代路线）
> 位置：`plugins/ue5/actions/ue_lint/rules.py`

## 目标

延续 ue_lint 生命周期资源检查，落地 R12：Timer 配对（SetTimer 应有 ClearTimer）。

## 设计动机

R9（委托配对）的「配对检查」模式可以推广到 UE 其他生命周期资源。Timer 是最典型的一种：

- 循环 Timer 若不在析构 / EndPlay 里 `ClearTimer`，对象销毁后 Timer 仍会触发 → 悬挂指针崩溃。
- 这是 UE 常见 bug，与 R9 的委托泄漏同构。

## 设计

R12 复用 R9 的配对检查模式，按 TimerHandle 名粒度：

- `_RE_SET_TIMER` / `_RE_CLEAR_TIMER` 提取 TimerHandle 名
- 有 SetTimer 无 ClearTimer 的 handle → warning

**关键决策**：
1. **warning 级别**：一次性 Timer（`bLoop=false`）无需 Clear，跨文件 Clear 合法——不阻塞。
2. **按 handle 名粒度**：`SetTimer(A)` 和 `ClearTimer(A)` 配对，不同 handle 互不干扰。

## 实现

`rule_R12_timer_pairing`：提取 SetTimer handle → 提取 ClearTimer handle → 差集 → warning。注册进 `_RULE_FUNCS`。

## 验证（5 场景全过）

| 场景 | 结果 |
|---|---|
| SetTimer+ClearTimer 配对 | ✅ 不报 |
| SetTimer 无 ClearTimer | ✅ 报 warning，含 handle 名 |
| 逃生注释 | ✅ 不报 |
| 非 C++ 文件 | ✅ 跳过 |
| 多 SetTimer 部分 Clear | ✅ 只报未配对的 |

## 收尾

ue_lint 规则集现为 R1-R12（12 条，R5 项目级单独跑）。生命周期资源检查形成完整闭环：委托配对（R9）/ 空引用（R10）/ 递归（R11）/ Timer 配对（R12）。
