`20261015` 那批工作到最后留了一个悬案——**skill_io MCP server 从没在真实
CLI 进程里跑通过**。今天补上了，答案是：**通**。

```

  → LLM 调用 mcp__skill_io__write_output 写 outline.md
  → _collect_outputs 扫 outputs.root 回收

```

## 二、外科测试先证「CLI 会不会真选 MCP 工具」

这是唯一的未知数——之前只验了「工具逻辑」「--settings 注入」「contextvar
进出」，从没验过 CLI 侧行为。先做一个最小测试：手工拼出 `_call_cli_stream`
会拼的命令，直接起 codebuddy 子进程，prompt 让它调 `mcp__skill_io__write_output`
写一个文件。

结果：**会**。23s 内退出码 0，outline.md 精确落盘。

顺带踩了一个坑：Windows 下裸 `codebuddy` 是 POSIX 脚本（`#!/bin/sh`），
`CreateProcess` 起不来 → FileNotFoundError。生产代码 `_resolve_cmd`
（llm_client.py:1088）会经 `shutil.which` 解析到 `.cmd` 再包 `cmd /c`，
但外科脚本一开始直接 `subprocess.run(['codebuddy', ...])` 没走这层，
暴露了「绕过 _resolve_cmd 就起不来」这个事实——以后写 CLI 相关脚本别手拼命令。

## 三、发现三个问题

### 1. demo-outline 的 240s 预算过紧（临界）

第一轮 240s 预算，模型写完 1697 字节大纲但没来得及回调 `done`，243s 被掐。
放宽到 600s 后 171s 优雅完成。**240 太贴边**——内容型 skill 给真实模型
至少留 300s+，或干脆按内容量动态放大。

### 2. 超时被当成 text_delta 上抛 → 状态/消息不一致（疑似假成功）

第一轮的诡异结果：`status="success"` 但 `message="[CLI错误] 调用超时（240s）"`。

根因链：
- `llm_client.py:1687-1690` 超时后**只 yield 一条 text_delta**（`[CLI错误] 调用超时`），
  不走 Error / BudgetExceeded 事件
- `engine.py` CLI 分支把它当普通文本收进 `full_cli_text`，最后
  `MessageDoneEvent(full_text=...)` 正常返回
- `runner.py:324-327` 只查「产物够不够」：`if status=="success" and expected and
  len(outputs)<expected: status="partial"`。产物够了 → 保持 success

所以「超时 + 产物恰好写完了」会被判 success。demo-outline 恰好 expected=1、
产物=1，于是成功；但语义上这一轮是**被掐断的**，不是优雅收尾。

严重性有限：`expected_output_count` 声明了的话，缺产物仍会降级 partial；
真正的洞是「expected 未声明」或「超时发生在最后一个产物之后、收尾之前」时，
下游无从知道这一轮没走完。**建议修**：超时 yield 一个 `cli_timeout` 事件
而非 text_delta，engine 转成 BudgetExceededEvent，runner 自然落到
budget_exceeded。暂缓（见 §五）。

### 3. skill body 的「调 done 结束」在 CLI 模式下是空指令

demo-outline 的 body 写着「3. 调 `done` 结束」，但 `done` 只在 API 模式的
tools 列表里（runner.py:268 `+ [_DONE_SCHEMA]`），CLI 模式不传 tools、
skill_io MCP server 也没有 done 工具。第二轮模型自己发现了：

> CLI 模式下无独立的 `done` 工具（`done` 仅在 API 模式的 tools 列表中注入），
> 本轮结束即视为完成，框架会扫盘回收产物。

**模型自己绕过去了**，但 body 里的「调 done」在 CLI 下是误导。应该改 body
措辞：CLI 模式直接结束回复即可，无需调 done。

## 四、本轮验证的边界

- 验的是 **demo-outline 单个 skill**（write_file 单工具、单产物）。demo-cover
  的 gen_image（出图）、demo-draft 的 read_repo_file 消费上游，还没在真实
  CLI 里各跑一遍。
- 没跑 orchestrator 整条链（三个 skill 顺序接），那需要真 DB 工单 + 真调度，
  本轮只证「单个 skill 在真实 CLI 下能产出并被回收」。
