## 一、Plan 2 — 工单 Agent 真 token streaming

**背景**：工单 Agent（DevAgent/TestAgent 等）执行 LLM 调用时（10-30s），前端无任何进展反馈。

### 后端 `backend/llm_client.py`

`_call_cli_stream()` 在 yield `text_delta` 时，检测 `_llm_ctx.ticket_id` 是否有值：
- 有则累积 token 到 `_tok_buf`，每 ~60 字 `await event_manager.publish_to_project(... "ticket_llm_token" ...)`
- 流结束后 `finally` 块 flush 剩余 buffer（带 `done: True` 标记）
- 仅在工单上下文触发，不影响 chat 路径

### 前端 `frontend/app.js`

`connectSSE()` 新增 `ticket_llm_token` 事件处理，三处展示：

| 展示位置 | 元素 | 效果 |
|---|---|---|
| 日志面板（左侧） | `#ticket-stream-{id}` | 顶部插入流式卡片，实时追加 token，宽度限 300 字 |
| 工单 Feed 时间轴 | `#feed-stream-{id}` | 当 `chatMode==='job'` 时在 `.ticket-section-messages` 追加 |
| **工单聊天面板** | `#ticket-chat-stream` | `crp-rounds-panel` 样式，实时显示 reasoning 文本和摘要行 |

`thought_done` 到来时（via `log_added`）：
1. 移除 `#ticket-stream-{id}`、`#ticket-chat-stream`、`#feed-stream-{id}`
2. 延迟 400ms 调 `loadTicketConversations()` 重建完整思考面板

## 二、UI Bug 修复

### 确认工单草稿卡片间距过大

**根因**：`.chat-msg-bubble` 有 `white-space: pre-wrap`，模板字符串缩进的换行符全被渲染为空白  
**修复**：`styles.css` 中 `.chat-action-card` 加 `white-space: normal`

### 工单 AI 对话标题重复叠加

**现象**：每点一次「AI 对话」按钮，顶部多出一行工单标题  
**根因**：`loadTicketConversations` 每次都插入新 `.chat-job-header`，但不清旧的  
**修复**：函数开头 `document.querySelectorAll('.chat-job-header').forEach(el => el.remove())`

### 工单标题出现在左侧而非顶部

**根因**：`#chatPanelBody` 是 `flex-direction: row`，`insertBefore(header, chatMessages)` 把 header 插到了消息区**左侧**  
**修复**：改为 `chatPanelBody.parentElement.insertBefore(header, chatPanelBody)`，将 header 插到 body 之前（chat header 和 body 中间）

### 工单 AI 对话入口恢复单工单视图

**根因**：`selectTicketForChat` 调 `setChatMode('job')` → `loadAllTicketConversations()`，显示全部工单 feed  
**修复**：改为直接调 `loadTicketConversations(ticketId)`，保留标题在顶部的单工单视图；Tab 键切换仍走全工单 feed
