# 历史上下文取「最老 30 条」bug 修复

2026-10-12

## 现象

导入几百条外部会话后，AI 助手「识别不了」导入内容——用户问的是最近内容，AI 拿到的是
会话开头那几句。

## 根因

`_load_session_history`（`backend/api/chat.py`，Session Resume 核心）加载历史时：

```sql
SELECT role, content FROM chat_messages
WHERE ... ORDER BY created_at ASC, id ASC LIMIT 30
```

`ASC` + `LIMIT` 取的是**最老的 30 条**，不是最近的 30 条。普通会话消息少、不超过 30 条
时看不出问题；导入几百条后就暴露了。

> 这个 bug 一直存在——任何超过 30 条的普通会话，AI 其实一直漏掉最近几轮（拿到最老的）。

## 修复

子查询先取最近 30 条，再按正序返回给 Anthropic：

```sql
SELECT role, content, images_json FROM (
    SELECT role, content, images_json, created_at, id FROM chat_messages
    WHERE session_id = ? AND project_id = ?
      AND role IN ('user', 'assistant')
    ORDER BY created_at DESC, id DESC
    LIMIT ?
) ORDER BY created_at ASC, id ASC
```

## 边界（未变）

- 上下文上限仍是**最近 30 条**（token 预算的既有取舍）。导入几百条时 AI 只认得最近 30 条；
  要覆盖更早内容，要么导入时选小范围（如「最近 50 条」），要么后续把上限做成按 token 自适应。

## 验证

`py_compile` 通过。重启后端生效，对所有会话（含导入的）有效。
