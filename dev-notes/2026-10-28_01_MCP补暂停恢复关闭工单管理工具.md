# MCP 补齐暂停/恢复/关闭工单管理工具

2026-10-28

## 起因

内部 ChatAssistant 在 CLI 模式（`LLM_API_FORMAT=cli`）下，LLM 是起 `codebuddy --print` 子进程，原生 `action_classes` 不传给 LLM（`llm_client` CLI 分支不传 tools），只通过 `--mcp-config` 注入 `ads-data` MCP server。而 `ads_data_mcp_server.py` 只封装了 confirm/get/run_command，没有 `pause_requirement` / `resume_requirement` / `close_requirement`。用户让 AI 暂停工单时，AI 如实回答「这些接口没有」。

## 实现

- `backend/ads_data_mcp_server.py`：新增 `pause_requirement` / `pause_requirements_batch` / `resume_requirement` / `close_requirement` 四个 MCP 工具，加 `_resolve_pid`（显式 > 环境注入 > 唯一激活项目）与 `_post_mcp_action` 助手，统一 POST 到 `/api/projects/{pid}/chat/mcp-action`。
- `backend/api/chat.py` `mcp_action_callback`：新增状态变更分支——pause/resume/batch 直接在后端进程里跑现成的 `PauseRequirementAction` 等（复用 `event_manager.publish_to_project` 的 SSE 与 orchestrator 清理）；close 跑 `CloseRequirementAction.run()` 产出 `confirm_close_requirement` 卡片走原有卡片推送，并修了关闭卡片的文案。

## 验证

`py_compile` 通过。前端已能渲染 `requirement_paused` / `requirement_resumed` / `confirm_close_requirement` / `requirement_closed` 四种卡片，无需改前端。
