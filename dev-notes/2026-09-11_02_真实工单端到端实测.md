## 三、编译失败：是我清理过度造成的，非 DevAgent 问题

`LNK2019/LNK2001` 一堆 `UE::CoreUObject::Private::*` 未解析符号。

根因：我在准备环境时执行 `git clean -fd`，把 `Source/TestFPS.Target.cs` 和
`TestFPSEditor.Target.cs` 当"未跟踪的遗留文件"删了 —— 但它们是**编译必需**的。
加上 `TestFPS.Build.cs` 里类名是历史遗留的 `TP_Blank`（与 `TESTFPS_API` 宏对不上），
模块符号链接不上。

**SprintComponent 自身编译是通过的**（.obj 生成成功），只是链接阶段找不到模块。

> 教训：UE 项目的 `*.Target.cs` 即使未被 git 跟踪也是构建必需品，
> 清理前要按文件语义判断，不能只看 git 状态。

已从备份恢复两个 Target.cs。

```
09:55:43  开始

10:14:32  OpenSpec Propose 返回 partial  938s   ← 83%
```

`agents/architect.py` 在主 LLM 出完方案后**另起一次完整 CLI 调用**跑 Propose。
跑了 15 分钟，结果是 `3/4 partial`（不完整），**而且 partial 不影响流转**照样进
`architecture_done`。花 15 分钟换一个不影响结果的部分产物，性价比极低。

DevAgent 也有同样模式（OpenSpec Apply），但快得多（约 1 分钟内）。

**建议**：Propose 设超时上限（如 180s），或改成后台异步不阻塞流转。
