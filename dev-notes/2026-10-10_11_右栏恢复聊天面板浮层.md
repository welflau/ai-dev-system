# 右栏隐藏后恢复异常：聊天面板吊在 body 上成浮层

2026-10-10

## 现象

用户点「隐藏右侧面板」后再恢复，右栏出不来/主工作区上飘着一块聊天气泡（截图：外部会话
Tab 全宽 + 右上角悬浮一条带 UE 截图的用户消息 + 右缘一条窄条），像"卡死"。

## 根因

`#chatPanel` 的 DOM 归属有两套模式：

- 停靠：挂在 `#rwChatPane` 里（`.shell-project .right-workbench .chat-panel` 强制
  `display:flex !important`、relative）
- 全屏：`toggleChatFullscreen` 进入时 `document.body.appendChild(chat)`，靠
  `body.chat-open .chat-panel { display:flex }` + fixed 定位显示

`_mountPanels` 决定 chat 的归属，判定条件是**只看 `_chatFullscreen` 旗标**。这个旗标和
`body.chat-fullscreen` 类名一旦不同步（多条路径各改一头：`enterProject` 只重置、
`closeRight` 两边都不碰、刷新恢复 `_restoreChatWorkspace` 又可能只拉起一边），就会出现：

旗标 true + 类名没了 → `openRight` 恢复右栏时 `_mountPanels` 走全屏分支把 chat **留在
body 上**，工作台照开但 chat pane 是空的；同时 `_syncChatOpenFlag(true)` 加回 `chat-open`
→ `body.chat-open .chat-panel` 让 body 上的 chat 以 fixed 浮层显示，压在主工作区上。
用户看到的就是"恢复了但布局稀碎/像卡死"。

## 修复

`_mountPanels` 的归属判定改成**旗标 + 类名双确认**：

- `chatReallyFullscreen = _chatFullscreen && body.classList.contains('chat-fullscreen')`
  → 才允许 chat 停在 body；
- 否则清掉残留旗标（`_chatFullscreen = false`）并把 chat 搬回 `#rwChatPane`。

自愈性：已处于坏状态的用户，下一次 `openRight`（点标题栏恢复按钮）就会被搬回 pane。

## 验证边界

- `node --check` 过；`backend/_test_right_panel_toggle.js` 50/50 通过（该测试钉住
  "面板关了还能再开"的整组行为）。
- 未跑浏览器实测；根因是基于布局规则（`body.chat-open .chat-panel` fixed 浮层 + 截图
  浮层气泡位置）的推断，旗标/类名失同步的具体触发路径未逐一复现（候选：全屏中刷新、
  enterProject 与 _restoreChatWorkspace 的先后）。
- 若用户复现的其实是另一种症状（比如整页无响应），此修不覆盖——需再要一张带控制台报错的截图。
