## 一、三层状态总览栏（`788f820`）

工单抽屉顶部三行进度条，一眼看清当前在哪层哪步。

**`_buildThreeLayerBar(hasSP, hasOS, ticketData)`**：

```
📐 规范  Propose ✓ ── Apply ○ ── Verify ○ ── Archive ○   [紫色]
⚡ 纪律  TDD · 调试规范 · 验证铁律                        [橙色，dev 阶段激活后变亮]
🔧 编排  需求 ✓ → 架构 ✓ → 开发 ● → 测试 ○ → 审查 ○     [蓝色，当前阶段加粗高亮]
```

- 规范层：`openspec_stage` 驱动进度（proposed/applied/verified/archived）
- 纪律层：ticket 进入 dev 阶段后激活变亮
- 编排层：`ticket.status` 映射到对应节点
- 无 Superpowers 且无 OpenSpec 时隐藏，不占空间

**CSS**：`.three-layer-bar` / `.tlb-row` / `.tlb-node.tlb-done/pending/active` 三色样式

## 四、Specs 版本历史 UI（`174606b`）

### 后端：`GET /openspec/ticket/{id}/spec-versions`

读取 `ticket_spec_versions` 表 + 文件系统 `specs.v*.md`，返回版本列表（version / change_summary / created_at / content）。

### 前端：`_loadSpecVersionHistory()`

版本数 > 1 时在 OpenSpec 面板追加 `📜 历史(N)` Tab：
- 列出每个版本：v1 / v2 / v3 ...
- 每版本显示：变更摘要 + 时间 + specs 预览（折叠，max-height 120px）

## 五、项目三层仪表盘（`174606b`）

### 后端：`GET /openspec/project-stats`

一次查询返回：
- `openspec.coverage_pct`：有 openspec_stage 的工单比例
- `openspec.verified / archived`：各阶段计数
- `superpowers.activated`：触发过 superpowers_skill 的工单数
- `harness.done_pct`：已完成工单比例
- `harness.changed`：发生过变更的工单数

### 前端：`loadOpenSpecDashboard()`

OpenSpec Tab 自动加载，三列覆盖率卡片：

```
┌──────────────┬──────────────┬──────────────┐
│ 📐 规范层     │ ⚡ 纪律层     │ 🔧 编排层     │
│ ████░░ 67%   │ ██░░░░ 40%  │ ████░░ 60%   │
│ 验证 2·归档 1 │ 激活 4/10    │ 完成 6/10     │
└──────────────┴──────────────┴──────────────┘
```
