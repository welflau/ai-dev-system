# Agent 级 LLM 配置（per-agent 覆盖 + 头像弹配置）

2026-10-11

## 需求

每个 Agent（Role Agent + AI 助手）可独立指定模型 API（base_url/key/format）与 CLI
（cli_type/cli_cmd/cli_model）；点击 AI 助手头像弹出配置界面。

## 实现

### 后端

1. **新表 `agent_llm_config`**（database.py）：`agent_type UNIQUE` + 全套 LLM 字段。走
   `CREATE TABLE IF NOT EXISTS`，重启自动建表。
2. **路由机制（方案 A：ContextVar + 上下文感知）**（llm_client.py）：
   - `LLMClient.__init__(config=None)`：config 非空时按字段覆盖 settings，空则全局默认。
   - `get_agent_llm_config(agent_type)`：查表返回完整配置（空字段回填全局 settings）。
   - `get_effective_llm_client()`：读 `_llm_ctx.agent_type`（**已存在**，chat.py /
     orchestrator.py 的 `set_llm_context(agent_type=...)` 早就在设）→ 有覆盖返回缓存好的
     per-agent 客户端，无则返回全局单例。
   - **4 个公开入口全部改成 facade**：`chat` / `chat_json` / `chat_with_tools` /
     `chat_with_tools_stream` → 解析生效客户端后委托给 `_chat` / `_chat_json` /
     `_chat_with_tools` / `_chat_with_tools_stream`。内部 `self.chat()` 调用点改 `self._chat()`
     避免双重 facade。
   - 关键点：**不做 `self.*` 字段临时交换**（两个 Agent 并发调 LLM 会互相覆盖），而是
     per-agent 独立 `LLMClient` 实例缓存 + facade 委托，天然并发安全。
   - `_invalidate_agent_client(agent)`：配置写入后失效缓存。
3. **API**（main.py）：
   - `GET /api/llm/agents` — 枚举 `agent_registry`（13 个）+ 各自生效配置 + 全局 + cli 模型选项；
     api_key 不外泄（只给 `has_api_key`）。
   - `POST /api/llm/agents/{agent_type}/config` — upsert 覆盖。
   - `DELETE /api/llm/agents/{agent_type}/config` — 删覆盖 = 恢复继承。
4. **meta 快照上下文化**（chat.py）：`_snapshot_llm_meta` 改 async，用 `get_effective_llm_client()`
   解析，头像/消息记录反映该 Agent 实际用的模型。

### 前端

- `showAgentLlmConfigModal(agentType)`：头像/列表入口，动态弹窗；「继承全局」勾选=删除覆盖；
  保存走 POST/DELETE。
- `openAgentLlmPicker()`：全局 LLM 配置弹窗里「各 Agent 独立模型配置 →」按钮 → 列出所有
  Agent 选一个配置。
- 头像入口：`#chatPanelIcon`（💬）加 onclick（stopPropagation 避免触发 title 区项目切换）。

## 与方案文档的偏差

docs/20261011_01 里写的是「整包覆盖 + 显式继承开关」。实现改成 **字段级 overlay**：
覆盖行里空字段回填全局（更宽容，也覆盖「只改 model 其余继承」的直觉用法）；「恢复继承」
= 删行。

## 验证

- `py_compile` / `node --check` 全过。
- curl 实测：GET 枚举 13 Agent；POST ChatAssistant 覆盖 → GET 显示 effective 变掉 →
  DELETE → 恢复继承。
- 独立脚本实测路由：无上下文 → 全局；设 `agent_type='DevAgent'` → 命中覆盖（cli_type/cli_model 变）。

## 追加：用户实际期望的入口（2026-10-11 下午）

用户截图反馈：第一版入口（标题栏 💬 + 全局 AI 配置按钮）不是他们找的位置。实际期望：

1. **消息旁的 AI 头像**（每条 assistant 消息左侧图标+模型短名）点击 → 弹配置：
   - `_buildAssistantAvatar`（全局 AI 助手消息）→ ChatAssistant
   - `_buildTicketAssistantAvatar(model, agentType)`（工单评论消息）→ 对应 agentType
   - 加 `cursor:pointer` + title + `event.stopPropagation()`
2. **Agent 详情弹窗**（设置 → Agents → 点 Agent）新增「🧠 模型配置」区块：
   - 生效配置摘要（继承/已自定义 · api_format · model）异步填 `#agentDetailLlmBadge`
   - 「⚙️ 配置模型」按钮 → `showAgentLlmConfigModal(agent.name)`
   - 注意：badge 填充前检查 `el.isConnected`（弹窗切 agent 后旧响应不覆盖）

教训：**"点击头像"指消息流里的头像，不是面板标题栏图标**——入口要贴着用户视线。

## 追加 2：弹窗不出现（2026-10-11 傍晚）

「配置模型」按钮点了没反应。根因：本系统 `.modal-overlay` **默认隐藏**
（`opacity:0; pointer-events:none`，靠 `.active` 类点亮，openModal/closeModal 走的就是它），
我动态建的弹窗只设了 `display:flex` 没加 `active` → DOM 里有但透明且不可点。
修复：`className = 'modal-overlay active'`（两个动态弹窗都改）。

教训：**这个项目的动态 modal 必须带 `.active` 类**，光 display:flex 没用。

## 边界

- `api_key` 更新时 POST 留空 = 沿用已有 key（不覆盖）；新增时留空 = 继承全局。
- 并发安全靠 per-agent 客户端实例缓存，无 `self.*` 交换竞态。
- settings-agents 页的「Agent 列表」是 skills/pack 那套注册表，与后端 role Agent 不是
  一回事，故次级入口放在「全局 AI 配置 → 各 Agent 独立模型」而非该页。
