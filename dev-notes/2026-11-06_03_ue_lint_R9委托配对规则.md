# DevLog：ue_lint R9 委托配对规则

> 日期：2026-11-06
> 关联：`docs/20261105_07_QA日志闭环设计方案.md` 4.3.1（Phase 3b 替代路线）
> 位置：`plugins/ue5/actions/ue_lint/rules.py`

## 目标

Phase 3b 评估结论指出：交互静态检查更务实的落地是**扩展 ue_lint 规则集（R9+ 确定性规则）**，而非独立 LLM 检查流程。本 DevLog 落地第一条：R9 委托配对。

## 现状

ue_lint 已有 R1-R8（8 条规则），全为**编译正确性/工程结构**检查（GENERATED_BODY / OnRep / include / Build.cs / uproject / include 顺序 / 类型头文件 / 文件类型），**零交互检查**。规则框架成熟：确定性正则、blocking/warning 分级、`@ue-lint-skip Rx` 逃生注释、`run_all_rules` 统一入口。

## 设计

R9 检查 `AddDynamic` 是否有配对 `RemoveDynamic`（委托泄漏/悬挂指针）。

**关键决策**：
1. **warning 级别（非 blocking）**：跨文件解绑合法，绑定到永久对象（UI 按钮、单例）无需解绑——"无 RemoveDynamic" 不一定是 bug，不能阻塞。
2. **按「委托对象 + 回调函数」粒度**：提取 `(delegate, callback)` 对，精确匹配 Add/Remove，避免"同委托不同回调"误判为已配对。
3. **文件内检查**：只在本文件内找配对，跨文件解绑视为合法（保守）。

## 实现

- `_RE_ADD_DYNAMIC` / `_RE_REMOVE_DYNAMIC`：正则提取 `(委托名, 回调名)`，兼容 `&UClass::Func` 与 `Func` 两种写法。
- `rule_R9_delegate_pairing`：Add 对 - Remove 对 = 未配对的绑定 → warning。
- 注册进 `_RULE_FUNCS` 列表。

## 关键修正（测试抓出）

初版用 `_is_skipped_by_escape(line, "R9")` 检查**当前行**，但逃生注释 `// @ue-lint-skip R9` 在 AddDynamic 的**上一行**，导致逃生注释失效（测试场景 3 失败）。

修正为对齐 R2 的做法：用 `content[max(0, m.start() - 120):m.end() + 20]` 取匹配点前 120 字符的 snippet 检查，捕获上一行的逃生注释。

## 验证（6 场景全过）

| 场景 | 结果 |
|---|---|
| Add+Remove 配对 | ✅ 不报 |
| Add 无 Remove | ✅ 报 1 条 warning，含委托+回调名 |
| 逃生注释（上一行） | ✅ 不报 |
| 非 C++ 文件 | ✅ 跳过 |
| 多 Add 部分 Remove | ✅ 只报未配对的 |
| 回调名提取 | ✅ OnClicked/OnButtonClicked 正确 |

## 后续

- R9 是 warning 级别，不影响 self_test 的 blocking 判断，可安全上线。
- 可继续加 R10（交互回调无 IsValid 检查）、R11（交互回调递归）——同框架，确定性正则。
