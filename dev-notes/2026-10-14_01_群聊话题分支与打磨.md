## 一、话题分支（核心，两轮迭代）

### v1：黑板数据模型改成「当前话题 + 归档分支」

- `_empty_board` 拆掉 `topics[]`/`goals[]` 扁平列表，改为 `topic_nodes[]` 归档分支；
  当前话题分区（proposals/decisions/…）保持扁平。
- `_archive_current_topic(board)`：换话题时把当前话题快照（title+goal+全分区+summary）归档进
  `topic_nodes`（上限 8 个），再清空分区、goal 置空。**加了「空内容不归档」保护**，避免产生空分支。
- 前端 `_renderBoardSummary`：侧栏渲染成**话题树**——顶部「🎯 当前话题」（目标+验收点完成度），
  下面「话题分支（N）」每项折叠成一行（标题 + 完成度 x/y），点开看该话题的目标/验收/共识。

### v2：话题归属从「文本差异」改成「LLM 路由」

文本差异把「上面提到 X」「甩个链接」都误判成新话题。改成：

- `_pm_route_topic`：**一次 LLM 调用同时做话题路由 + 目标提炼**，输出
  `{topic_relation: continue|resume|new, topic_title, goal, acceptance_criteria, participants}`。
- 路由语义：
  - `continue` = 当前话题追问 → 目标/分区不动（零 churn）；
  - `resume` = 追问更早分支 → `_find_archived_topic`（2-gram Jaccard ≥0.5 标题匹配）+ `_restore_topic_node` 恢复；
  - `new` = 新话题 → 归档当前 + 新目标。
- 降级：路由 JSON 解析失败 → continue（不乱建分支）；首条消息强制 new。

## 二、验收点完成度标记（启发式）

- `_bigrams`（中英混合 2-gram）+ `_criterionCovered`（≥40% 命中判覆盖）。
- 侧栏每条验收点实时状态：`✅` 已达成（decisions 覆盖）/ `🔶` 讨论中（proposals/facts 覆盖）/ `⬜` 未开始。
- 归档分支的完成度 = 该节点 decisions 对自身验收点的覆盖。

## 三、交互打磨

1. **「＋」按钮共用**：`onNewChatClick()` 按 Tab 分发——群聊 → `startNewGroupChat()`（新 session+新黑板），
   其余 → `newChatSession()`。撤掉独立的「👥＋」按钮。
2. **Markdown 排版**：`_pm_agent_prompt` / `_pm_decision_prompt` 明确要求 Markdown
   （代码用 ```语言 代码块、路径/标识符反引号、要点列表）。渲染管线本就与 AI助手 共用
   `formatChatContent`，改的是「让 Agent 输出 markdown」。
3. **🆕 新话题开关**：群聊输入框左侧（仅群聊显示），点亮后下一条消息带 `force_new_topic=true`
   强制开新话题（跳过路由判断），用完自动复位——解决「甩链接被判成延续」的意图歧义。
4. **路由结果透明化**：新增 `topic_route` SSE 事件，流里显示「📌 话题：延续「X」/
   🆕 新话题：X / 📌 回到话题：X」，并**附带完整 board** 让侧栏立即同步（不等第一轮 board_update）。

## 四、关键实现细节 / 教训

- `_pm_route_topic` 是模块级函数，`set_llm_context` 需在函数内 import（此前踩过 NameError）。
- 话题路由与目标提炼合并成一次调用，**没增加 LLM 调用次数**（原来就有一轮 goal 提炼）。
- 归档分支上限 8 个，防止话题树无限膨胀。
- 完成度是启发式（关键词覆盖），精确版（PM 显式输出每条验收点状态）留待后续。
