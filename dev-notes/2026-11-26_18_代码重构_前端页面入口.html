2026-11-26 · 上期：系统路径打开 · 项目重构方案

浏览器直接打开一个多级 /app/… 地址时，服务需要返回首页，由前端接管后续导航。迁移前这条主线已经正常。测试发现两个偏差：OpenAPI 把首页标成 JSON；部署目录中如果有一个叫 index.html 的目录，旧服务会尝试把它作为文件发送，最终返回 500。

本期把 /app、/app/{path:path} 和 /favicon.ico 集中到页面路由。缺少可用首页时统一返回原有中文 JSON 404；正常部署时不改变页面字节、缓存头或文件响应能力。基线 497e03f，代码提交 de10788。

从地址到响应

两个页面 GET 仍共用一个处理函数。即便子路径与前端目录中的其他文件同名，也只读取配置目录下的 index.html。成功时继续用 FileResponse，所以字节范围请求仍能拿到 206 部分响应；首页缺失或同名目录都返回 {"message":"前端文件未找到，请确保 frontend/ 目录存在"}。图标独立返回 SVG，沿用原来的图案，不进入 OpenAPI。

main.py 保留 serve_frontend 和 favicon 两个 Python 名称。三个 GET 各注册一次，静态目录的挂载和中间件均没有移动。页面路由与 /static 使用同一个启动目录。OpenAPI 的两个 GET 现在声明成功类型为 text/html，并补充了 404 的 application/json；操作标识、参数和其余响应保持原样。

用什么证据验证

  1. 先在旧版跑 10 项测试。 在临时目录放入内容不同的首页和子页面，分别请求 /app、/app/ 和指向真实子页面名字的深链接，再检查字节范围请求、缺失文件、同名目录、图标和 OpenAPI。结果 7 通过、3 失败（1.18 秒）：同名目录得到了 500，两个页面入口都误报 JSON。普通首页缺失本来就返回 404。
  2. 迁移后重跑。 同一组业务断言在真实应用的 ASGI 入口运行，不启动生命周期、不修改项目首页。最终采用 HTTPX 连接测试应用：最低版本临时环境里的 Starlette 没有提供 starlette.testclient 模块，最初的测试适配器无法导入；改为 HTTPX 后，两个环境都可执行这组测试。
  3. 浏览器直达与刷新。 截图脚本将仓库里的真实首页和 CSS 复制到临时目录，在随机本机端口挂载页面路由。Edge 先打开首页，再直达多级深链接并刷新，核对三次 HTML 的每一个字节、缓存头、文档标题和样式表。最后以同名目录替换临时首页，验证 404，同时确认图标仍可解析为 SVG。

截图中的顶栏来自刷新后的真实页面；表格取自浏览器收到的响应，摘要仅展示前 12 位。测试没有加载业务 JS、远程脚本或用户数据，验证范围是后端交付页面，不覆盖前端恢复某个项目或标签页的状态。
