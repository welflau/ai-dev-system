## 一、Superpowers 铁律真正生效（Step 4）

**问题**：`_inject_superpowers()` 把 SKILL.md 存入 `context['superpowers_context']`，但 WriteCode/PlanCodeChange 等 Action 从未读取它，铁律实际上没有影响 LLM。

**修复（`agents/base.py`）**：

`_resolve_skills_prompt()` 末尾追加 `superpowers_context`：

```python
sp_ctx = context.get("superpowers_context", "") if context else ""
if sp_ctx:
    parts.append(sp_ctx)
```

**完整链路**：
```
_inject_superpowers → context['superpowers_context'] = SKILL.md 内容
  → _resolve_skills_prompt → parts.append(superpowers_context)
  → _current_skills ContextVar
  → ActionNode._compile() → ## 专业技能 (Skills) 段 prepend
  → LLM 看到 TDD/调试/验证铁律
```

所有 Action（WriteCode / PlanCodeChange / SelfTest 等）**自动**获得铁律，无需逐个修改。

## 三、变更分析中间件 + Tweak Flow（Step 6-8）

### `change_impact.py`（新文件）

**ChangeImpactAnalyzer**：
- 轻量 LLM 调用（非 ReAct，直接 chat，~1-2s）
- 只在 `ACTIVE_PHASES` 工单触发
- 评论 ≤ 10 字直接返回 none
- 有 OpenSpec `specs.md` 时辅助分析
- 输出：`none / tweak / partial / breaking`

**ChangeImpact 数据类**：
```python
type: str              # none/tweak/partial/breaking
reason: str            # 变更原因说明
affected_specs: list   # partial 时受影响的场景
```

### `orchestrator.py` 变更

**`reply_to_comment()` 接入中间件**：
```
用户评论
  → _handle_change_impact()
    ├── none     → 正常 LLM 回复路径（原有逻辑）
    ├── tweak    → _tweak_flow()
    ├── partial  → 暂降级走 tweak（P2 再补 SpecVersionManager）
    └── breaking → 通知人工介入（P3 再补衍生工单）
```

**`_tweak_flow()`**：
1. `change_count + 1`
2. `reset_phases(from_phase="development")`（触发阶段重置）
3. 回复确认评论：「已收到调整，已重置开发阶段」

**`_handle_change_impact()`**：
- 读取 OpenSpec specs 辅助分析
- 记录 `ticket_logs` layer=harness action=change_detected
- 路由到对应 Flow
