## 背景

用户给出截图：现有「AI 配置」弹窗只有 LLM / 图片生成 / 资产搜索三个 Tab，
要求「公共配置 Key 的地方，需要添加生视频的项目配置」。

三个拍板（AskUserQuestion）：
1. 范围 = **三项全放**（MiniMax H3 全字段 + 排队参数 + VideoClaw sidecar + LightAI 提示）
2. 保存 = **新建独立 router**（不复用 `POST /api/llm/config`）
3. 测试连接 = **两个都要**（status 用不联网 probe，测试按钮用联网 ping）

## 调研结论

- 「图片生成」不是独立组件，是 `llmConfigModal` 的一个 Tab；三个 Tab 共用一个
  `POST /api/llm/config`（`app.js:2676-2727` / `main.py:606-751`）。
- `cloud_video/` 之前**没有任何 HTTP 配置端点**。
- `.env` 回写两套：`main.py:648-690` dict 重建（丢注释/空行）、`main.py:989-1003`
  逐行替换（保真）。现有三处回写**互相无锁**，并发会丢更新。
- GET 只回传 `configured` 布尔不回传 key（`image_gen.py:70-80`）；截图里的 `sk-...`
  是 `placeholder`，不是掩码值 —— 现有 UI 分不清「已配置/未配置」。
- 字段已在 `config.py` / `.env.example` 齐全，`cloud_video.PROVIDERS` 是单一真源。

## 三端点契约

- **GET /config/status**：`configured` + `minimax_h3`（`card_key_configured` 只布尔）+
  `queue`（含 `stats{active,waiting,limit,unlimited,idle_window,tz}`）+ `videoclaw` +
  `lightai{configured,hint}` + `providers` + `warning`。**密钥绝不回传**。
- **POST /config**：17 个可选字段。逐字段 `if in raw` 才更新 `settings.*`；
  密钥空串跳过；bool 显式 `.checked` 回写 `"true"/"false"`；`.env` **逐行替换保真**
  （保留注释/空行/其它节）+ `asyncio.Lock`；排队字段变更后重建全局队列。
- **POST /config/test**：`probe_provider`（不联网）→ 通过则 `ping()`（联网验卡 12s）；
  支持**未保存表单 key** 临时注入 settings 并 try/finally 还原；测试时强制 `ENABLED=true`。

## 四个实现坑（都已修，均有测试覆盖）

1. **包级 re-export 静态绑定**：初版 router `from cloud_video import ping` 让测试 patch
   `cloud_video.client.ping` 失效（与 §15.5 同坑）。改 `from cloud_video import client
   as cloud_client` + `cloud_client.ping()`。
2. **`build_queue_from_settings` 读 `os.getenv`**：面板热更新改的是 `settings.*`，
   重建队列拿不到新值（测试期望 idle_limit=3 实得 5）。改读 settings，清理 os import。
3. **测试连接被表单 `enabled=false` 挡住** → `not_configured`。改为测试时无条件强制
   启用、finally 还原。
4. **CSS 笔误** `var(--text-muted;` 缺右括号。

## 严格遵守的边界

- `.env` 绝不整文件覆盖（会清空 LLM/LIGHTAI/PEXELS 等其它节）—— 这是调研里最大的风险点。
- 密钥空输入 = 不覆盖旧值；bool `false` 不能被 `||` 兜底吃掉。
- GET 不回传密钥；UI 明确「第三方鼠鼠卡密中转，非 MiniMax 官方 API，官方 key 不能填这里」。
- LightAI Key 只在「图片生成」Tab 配，新 Tab 只显示是否已配置，避免两处重复输入覆盖。
- VideoClaw sidecar 自身无密钥（dashscope/ark 在 VC 仓库 config.yaml）。
