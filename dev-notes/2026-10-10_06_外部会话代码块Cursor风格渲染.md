# 外部会话代码块按 Cursor 风格渲染（语言徽标 + 路径 + 行号范围 + 高亮）

2026-10-10

## 起因

Cursor 会话消息里的代码块 fence 是文件引用格式：```` ```792:848|相对路径 ````（起止行|路径）。
`formatChatContent` 的 fence 正则只认 `[\w]*` 语言标签，`:|/.` 都不在内 → 整块没被识别成
代码块，原始反引号 + 路径 + 代码当纯文本铺出来（用户截图对比 Cursor 原生效果：语言徽标 +
文件名 + Ln 范围头部 + 语法高亮）。

## 实现

`frontend/app.js`：

1. **三处 fence 正则放宽** `[\w]*` → `[^\n]*`（占位保护、split、per-part match 三处要一致）：
   - ```` ```[^\n]*\n ```` 要求 info 后有换行，行内 ```` `x` ````/```x``` 不受影响。
2. **info 解析分支**：`/^(\d+):(\d+)\|(.+)$/` 命中 → `buildCodeRefCard(start, end, path, code)`；
   否则走原逻辑（`lang = info` → 图片行检测 / buildCodeFileCard / markdown 渲染）。
3. **`buildCodeRefCard`**（新增，紧挨 buildCodeFileCard）：
   - 头部：语言徽标（扩展名映射 `_REF_EXT_LANG`，如 .cpp/.h/.hpp → C++）+ 文件名（basename，
     title 悬浮全路径）+ `Ln 792-848`（起止相同只显示一个）。
   - 正文：`hljs.highlight(code, {language})` 高亮，无 hljs/未知语言回退 highlightAuto /
     escapeHtml。不折叠（参考 Cursor 原生行为）。
4. **`styles.css`** 新增 `.chat-code-ref` 系列：圆角边框卡、头部语言徽标（primary 色淡底）、
   文件名 ellipsis、Ln 右对齐灰字、pre 高度上限 480px 可滚、注释斜体（对齐参考图）。

## 关键弯路

- 把 `lang = info` 逻辑包进 else 时漏了一层闭合括号，`node --check` 抓到后补上——**改嵌套
  结构后必须立刻跑语法检查**，别攒到最后。
- 缩放角标那次学到的教训复用：卡内伪元素/子元素如果参与 flex 布局会把头部挤偏，这里头部
  本身就是 flex，`Ln` 靠 `margin-left:auto` 右对齐，徽标 `flex-shrink:0`。

## 波及面（有意为之）

`formatChatContent` 是主聊天 + 外部会话气泡共用的，所以主聊天里如果出现 ```起:止|路径
fence 也会同样渲染成卡。普通 ```lang fence 行为不变（回归测试过 split 分支：py 块、行内
三反引号、前后文本段均正常）。

## 追加：卡片上下大片空白（2026-10-10 下午用户反馈）

截图里卡片头部上方/下方、代码下方各有一大段空白。根因：`.chat-msg-bubble` 是
`white-space: pre-wrap`（styles.css 7633），而 `buildCodeRefCard` 模板字符串里的换行+缩进
被气泡原样渲染成空白行。修复：

1. `buildCodeRefCard` 模板压成单行（模板里不许有标签间换行）。
2. 防御补一刀：`.chat-msg-bubble .chat-code-ref { white-space: normal; }`，pre 自己的
   UA 默认 `white-space: pre` 不受影响。

**教训：往聊天气泡里塞任何 HTML 模板，模板源码必须是单行**——formatChatContent 里旧的
图片卡片模板（22370 附近）也有同样问题但没暴露，先不动。
