# 外部会话面板切 Tab 不再自动刷新：DOM 搬家缓存，刷新交给 ↻ 按钮

2026-10-10

## 起因

用户反馈：每次从别的 Tab 切回「外部会话 · Cursor」Tab，面板都自动重新拉列表 + 详情，
要等一会儿才出内容。期望：切 Tab 不重读，只在点 ↻ 刷新按钮时才重读。

根因：`_loadMainTabContent` 对 `external-sessions` 每次都走 `_mountExternalSessionsPane`
重建 DOM + `_esRefresh()` 拉列表；再加上前一轮"恢复上次选中会话"的逻辑，还会再拉一次
详情。tasks 面板早就是"搬家"策略，es 面板注释却写"每次重建不复用"。

## 实现（改成和 tasks 一样的"搬 DOM"策略）

`frontend/app.js`：

1. 新增缓存变量 `_esPaneEl` / `_esPaneProject`（面板根节点 + 所属 projectId）。
2. 新增 `_esEvictPane()`：把 `.external-sessions-pane` 从 host 摘下来存进 `_esPaneEl`，
   记下 `_esState.projectId`。
3. `_loadMainTabContent`：
   - 顶部加 `if (tab.type !== 'external-sessions') _esEvictPane();`（和 tasks 那行并列）。
   - es 分支三档：
     - 面板还在台上（重复激活同一 Tab）→ 直接 return，不动；
     - 有缓存且 `_esPaneProject === pid` → `host.innerHTML=''` + `appendChild(_esPaneEl)`，
       不重读；
     - 否则 `_mountExternalSessionsPane`（首次打开 / 切项目 / 关掉重开）。
   - 切项目残留保护：`_esState.projectId` 与当前 pid 不一致时先丢旧 DOM/缓存再重挂。
4. `closeMainTab` / `closeAllMainTabs`：关掉 es Tab 时把面板 DOM 和缓存一起清掉，重开走
   全新挂载（重新拉数据，符合"关掉重开=新数据"直觉）。

## 追加：切回后滚动位置丢失（2026-10-10 下午）

搬 DOM 后刷新问题解决了，但用户反馈切回不回到原来位置。原因：原来"每次重建"模型里，
`_esRenderSessionDetail` 会用 localStorage 的 `esScrollPos:<sid>` 恢复右栏滚动；改成搬 DOM
后跳过渲染，右栏滚动只能靠浏览器保留 DOM 的 scrollTop——但浏览器在 detach/reattach 时会
把 scrollTop 归零（至少这个壳层里如此）。

修复：`_esEvictPane` 搬走时把左右两栏滚动位置记进 `_esListScrollTop` / `_esOutputScrollTop`
（内存变量，取的是当前 DOM 最准确的 scrollTop，不是可能差几帧的 localStorage），切回
appendChild 后 `requestAnimationFrame` 里显式设回。左侧列表滚动之前就没落盘，这次一并记。

**教训：搬 DOM 不能假设 scrollTop 会跟着节点一起保留，滚动位置要自己搬家。**

## 验证边界

- `node --check` 过，未跑浏览器实测。
- 事件绑定靠 inline onclick/oninput/onscroll 属性，节点搬走再放回事件不丢；`_esState`
  模块变量和 DOM 状态一致，列表/搜索/选中/滚动位置原样保留。
- `_esState.projectId` 项目残留检查依赖"切项目时旧面板还在台上"这一场景；若切项目本身会
  重置整个 shell（mainTabs 被清/ host 被清），该分支是冗余保险，不影响正常路径。
- 切项目后旧 tab.projectId 可能残留旧项目，但 openMain 每次都会刷新
  `existing.projectId = tab.projectId || currentProjectId`，配合缓存项目比对能兜住。
