# 验收 CLI モード base64 卡死 + JSON 二次提取切碎对象 + PlanCodeChange 磁盘兜底

2026-10-23

前作：`dev-notes/2026-10-23_08_无围栏回复散文净化与SelfTest拦截.md`

## 起因

`TK-20261023-982770` 在通过 `h5_typecheck`、`h5_playtest`、`code_review` 后，进入 `ProductAgent.acceptance_review`，随后连续被打回直到第 5 次 `blocked`：

1. **18:28–18:38 `ProductAgent.acceptance_review` 超时 602s**：
   - `acceptance_review` 把截图编成数十 KB 的 base64 塞进 `images=[screenshot_data_url]`；
   - `llm_client._messages_to_stdin` 在 CLI 模式下检测到 `image` block，直接把含 base64 的 JSON dict 作为纯文本塞进 `codebuddy` 的 stdin（且丢掉了 `system_text`）；
   - `codebuddy`（`deepseek-v4-pro-ioa`）对着数万字符的 base64 文本空转了 104,000 行 stdout，满 600s 超时降级判 `acceptance_rejected`。
   - 同时 `_run_and_screenshot` 对 Vite 项目直接用 `python -m http.server` 服务仓库根目录（而非 `dist/`），根 `index.html` 的 `<script type="module" src="/src/main.ts">` 根本无法在静态服下执行。
2. **18:40–18:52 两轮 `DevAgent.fix_issues` 均报 `LLM 输出无效 (type=NoneType)`**：
   - 第一步 `PlanCodeChangeAction`：模型要改 `scripts/verify-files.mjs`，但 `orchestrator._collect_existing_code` 只把 `src/*` 和 4 个入口文件放进 `existing_code` 字典，没读 `scripts/*`；`PlanCodeChangeAction` 只查内存字典不查磁盘，直接当“找不到文件”跳过并回退 `WriteCodeAction`；第二轮模型判断现有全部文件已合规（`files_unchanged` 16 个，create/modify 为空），也被当成“规划失败”回退 `WriteCodeAction`。
   - 第二步 `WriteCodeAction`：模型实际上返回了完整合法的 JSON，只是前面带了一句英文确认 `All acceptance checks pass...{ "files": { ... }, "key_implementations": [...] }`。
   - 然而 `llm_client._chat_json` 的二次提取写成了：
     ```python
     start = cleaned.find("[") if "[" in cleaned else cleaned.find("{")
     end = cleaned.rfind("]") + 1 if "]" in cleaned else cleaned.rfind("}") + 1
     ```
     只要 JSON 对象 `{...}` 内部带有数组 `[...]`（比如 `key_implementations` 或 `tsconfig.json` 的 `include`），`"[" in cleaned` 就是 `True`，于是它从对象**内部的 `[` 截到 `]`**，把外层 `{ "files": ... }` 切碎，导致 `json.loads` 必败、返回 `None`。

## 实现

1. **`llm_client._extract_json_value`**（`backend/llm_client.py`）：
   - 用 `json.JSONDecoder().raw_decode` 扫描所有 `{` 与 `[` 起点，优先提取跨度最大的合法 `dict`，彻底修掉「JSON 对象内含数组时被 `find("[")` 切碎」以及「前置散文里含 `'{` 字符干扰 `find("{")`」的问题。
   - `_messages_to_stdin` 统一走 `_messages_to_prompt` 纯文本（含 `<ads_context>`），不再把 base64 图片 JSON 塞进纯文本 CLI stdin。
2. **`AcceptanceReviewAction`**（`backend/actions/acceptance_review.py`）：
   - `_run_and_screenshot` 若检测到 `dist/index.html`，优先静态服务 `dist/` 编译产物；
   - CLI 模式下不传 base64 vision blocks，改为在 prompt 中告知仓库内截图相对路径。
3. **`PlanCodeChangeAction` + `_collect_existing_code`**（`backend/actions/plan_code_change.py`、`backend/orchestrator.py`）：
   - `_collect_existing_code` 纳入 `tsconfig.json`、`vite.config.ts` 及 `scripts/*.mjs`；
   - `files_to_modify` 若不在 `existing_code` 字典中，自动回退读取 `repo_path` 磁盘文件；磁盘也不存在时按新建生成；
   - 若模型明确规划 `files_unchanged` 非空且无需新增/修改，直接沿用现有干净文件返回成功。

相关测试：`tests/plugins/test_h5_plugin.py`（23 项通过）。
