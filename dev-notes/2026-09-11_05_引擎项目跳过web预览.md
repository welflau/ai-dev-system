## 一、问题

真实工单实测时 DeployAgent 给 UE 项目起了 HTTP 预览：

```
10:14:37 deploy_agent: 🌐 [dev] 开发环境 已部署: http://localhost:9096
```

`deploy_env` 起的是 `python -m http.server`，只对能用浏览器打开的静态站点有意义。
UE 项目根目录连 `index.html` 都没有，访问只会看到一个目录列表 —— 白占一个端口。

库里已经有 3 条这样的僵尸记录：

```
TestTPS          prod  9219  running
FPS Shooter Demo prod  9247  running
TestFPS          dev   9096  running
```

**顺带发现的第二个问题**：`_generate_deploy_files` 无条件产出
`build/Dockerfile`（`FROM python:3.10-slim` + `uvicorn`）和 `docker-compose.yml`。
TestFPS 和 TestGame 两个 UE 仓库里都已经被提交了这套 Python 部署模板 —— 
UE 项目既不用 Docker 也不跑 uvicorn，纯垃圾文件。

---

## 二、原有逻辑的缺口

`deploy_env` 里本来就有一段引擎项目保护，但**只管 test/prod**：

```python
if env_type != "dev":      # ← dev 完全没拦
    if any(t.startswith("engine:ue") or t.startswith("engine:unity") for t in traits):
        return None
```

理由写的是"隔离 clone 会产生数 GB 损坏副本"—— 只考虑了体积，没考虑
"HTTP 预览对引擎项目本身就没意义"。dev 环境不 clone（直接用仓库目录），
所以逃过了这个判断。

---

## 三、修复

抽出 `DeployAgent._skip_preview_reason(project_id, env_type, repo_path)`，
统一三个环境的判定，并给出人类可读的原因：

| 场景 | 行为 |
|---|---|
| 引擎项目（ue/unity/godot）+ dev | 跳过 —— 无静态站点入口 |
| 引擎项目 + test/prod | 跳过 —— 仓库体积过大 |
| 引擎项目但根目录**有 index.html** | **照常部署**（引擎项目也可能带 web 前端）|
| 普通 web 项目 | 照常部署 |

三处接入：

1. `deploy_env()` —— 起服务前判定，替换原来只管 test/prod 的逻辑
2. `deploy()` —— 判定结果传给 `_generate_deploy_files(engine_project=...)`，
   并把原因放进 `deploy_result.preview_skipped` 供前端显示
3. `api/projects.py` 手动部署端点 —— 跳过时返回 `{"status": "skipped", "reason": ...}`，
   而不是 `HTTPException(500, "部署失败")`。这不是失败，是不适用

`_generate_deploy_files` 增加 `engine_project` 参数（默认 False，向后兼容）：
引擎项目不产 Dockerfile/compose，`deploy.md` 改写成 UBT + RunUAT 打包说明。
