## 二、聊天刷新后三类数据丢失（`e9095b4`）

### Bug 1：卡片状态不持久（pending / executed 刷新丢失）
**根因**：`message_done` SSE 事件未携带 `msg_id`，`patchActionState` 找不到 `messageId`  
**修复**：`_save_chat_message` 返回 `msg_id`，两个 stream generator 在 `message_done` 里携带；前端 `_sendChatStreaming` 存入 `_savedMsgId`，卡片创建后写 `data-message-id`

### Bug 2：消息顺序乱（同秒多条消息）
**根因**：`ORDER BY created_at ASC` 无 tiebreaker，SQLite 同秒顺序不确定  
**修复**：三处查询加 `id ASC/DESC` tiebreaker

### Bug 3：Git Commit 失败等错误卡刷新消失
**根因**：`chat_alert_hook` 只推 SSE（ephemeral），不写 DB  
**修复**：`chat_alert_hook` 额外写 `chat_messages`（`action_type=error_alert`）；`_buildAnyActionCardHtml` 加 `error_alert` 渲染

## 四、卡片状态根本修复（`4f88da4` + `74cabd0`）

### 时序 Bug（`4f88da4`）
`message_done` 时卡片还未 DOM 存在，直接查不到。改为：`message_done` 时存 `_savedMsgId`，卡片 `insertBefore` 后再写 `data-message-id`。

### MCP callback 路径（`74cabd0`，根本原因）
`confirm_direct_ticket` 完全不走流式！走的是 `mcp_action_callback` HTTP 端点 → `chat_mcp_action` SSE。此路径 `msg_id` 从未传给前端，前三次修法都是在流式路径改，完全无效。

**修复**：
- `mcp_action_callback` 保存 DB 后，补推 `chat_mcp_action_id` SSE 事件携带 `msg_id`
- 前端监听 `chat_mcp_action_id`，写入最新 action 卡片的 `data-message-id`

### 空气泡（`74cabd0` + `22b533a`）
- `error_alert` 存 `content=""` + `action_data`；`appendChatBubble` 渲染空 div → 加 `(content || actionHtml) ?` 判断
- `appendChatBubble` if-else 链无 `error_alert` 分支 → 末尾加 fallback 调 `_buildAnyActionCardHtml`
