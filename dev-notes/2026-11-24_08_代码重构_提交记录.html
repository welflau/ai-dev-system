依据是各篇笔记的「改动清单」。大部分文件只属于一批，直接按路径 git add。有交叠的是下面几个：

文件 交叠情况 处理

按 hunk 拆用的是补丁方式，因为这个环境用不了交互式的 git add -p：

# 1. 取整份补丁
git diff HEAD -- backend/main.py > full.patch
# 2. 用脚本按 "@@ " 行切开，保留文件头和选中的 hunk，写成 partial.patch
# 3. 只应用到暂存区，工作区文件不动
git apply --cached --recount partial.patch
# 4. 核对：暂存区和工作区各剩哪些 hunk
git diff --cached -- backend/main.py
git diff -- backend/main.py

.gitattributes 把 *.py 设成了 eol=lf，git diff 输出的补丁已经是 LF，可以直接套到暂存区。 补丁文件要按字节读写，经过 PowerShell 的 > 重定向会被转成 UTF-16，上面第 1 步实际是用 Python 的 subprocess 取的。

client.py 第 3 个 hunk 里带着一行 import cloud_video.lightai as lightai，它是体检修复里拆环的一部分。 这一行和 record_task 的改动在同一个 hunk 里拆不开，就跟着提交 2 走了。

踩过的坑

  • pytest.ini 里已有 -q，命令行再加一个就不打印汇总行。 这次 worktree 里多加了 -q，输出里没有「N passed」， 通过数是数进度行里的 . 和 F 得到的。07 的复核命令里已经写了这一条，这次还是踩了。
  • 提交信息文件不能带 BOM。 PowerShell 5.1 的 Set-Content -Encoding utf8 会写 BOM，BOM 会进到提交标题里。 这次用 Python 写文件再 git commit -F。
  • 中文路径。 git status 默认把非 ASCII 路径显示成八进制转义，加 -c core.quotepath=false 才能看到原文件名。 git add 时把路径作为参数列表传给 subprocess，没有经过 shell 拼接。

没有验证的部分

  • 没有推送，CI 没有跑。 ci.yml 里的 pytest 步骤在提交 3 里，要推送后才会第一次执行。Ubuntu 加 Python 3.12 下的结果还没有见过。
  • 提交时没有触发任何检查。 本机没有装提交钩子，上面的验证都是手工跑的。
  • a099133 和 d1f478a 只跑了 pytest。 分层守卫和 flake8 没有在这两个中间提交上单独跑。 按那 2 条失败的测试推断，a099133 上分层守卫会报 cloud_video 那个环，没有实际跑过确认。
  • a099133 上的前端没有在浏览器里看过。 前端三个文件整份进了这个提交，内容和最终提交一样。
