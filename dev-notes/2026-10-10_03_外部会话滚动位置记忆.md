# 外部会话右栏滚动位置记忆：首次到底、再进回历史位置

2026-10-10

## 起因

外部会话浏览器切会话时，右栏滚动位置每次重置。用户要求：**首次打开某个会话 → 停到最新
位置（底部）；打开过 → 恢复到上次浏览到的位置**。

## 实现

滚动容器是右栏 `#esPanelOutput`（`overflow:auto`）。方案：按 sessionId 把 scrollTop 存
localStorage（面板关掉再开也保留），用「有无记录」区分首次/再次。

`frontend/app.js` 改动：

1. **持久化 + 节流**（模块级）：
   - `_esSaveScrollPos` / `_esGetScrollPos`：`localStorage['esScrollPos:' + sessionId]`。
   - `_esOnScroll`：挂在 `#esPanelOutput` 的 `onscroll` 上，**rAF 节流**——滚动事件每帧只写
     一次 localStorage（`_esScrollSaveQueued` + `_esScrollPending` 存最后一帧位置），否则滚动
     时高频同步写 localStorage 会卡。
2. **`_esSelectSession`**：开头置 `_esSuppressScroll = true`，失败分支也要恢复 `false`。
3. **`_esRenderSessionDetail`**：渲染后 `requestAnimationFrame` 里恢复滚动——
   - 有记录 → `scrollTop = savedPos`
   - 无记录 → `scrollTop = scrollHeight`（底部），并 `setTimeout 150ms` 再校正一次
4. **`_esRenderImages`**：去掉缩略图 `loading="lazy"`（本地 API 现查现读很快，图片数量少），
   否则懒加载图片在滚动容器里首帧不撑高，scrollHeight 偏小导致「滚到底」不准。

## 关键弯路：渲染会污染「历史位置」

`outEl.innerHTML = ...` 会把 scrollTop 归零并触发 scroll 事件，如果这时按当前
`activeSessionId` 落盘，会**把上一个会话的位置错记到新会话头上**（甚至记成 0）。

所以 `_esSelectSession` 在写「加载气泡…」之前就必须 `_esSuppressScroll = true`，
一直压到 `_esRenderSessionDetail` 的 rAF 恢复滚动之后才放开；API 失败的 catch 分支也要
放开，否则之后用户滚动再也不记录。

## 验证边界

- `node --check` 语法过，未跑浏览器实测。
- **快速连点两个会话**：两个 `_esSelectSession` 并发，各自 rAF 可能乱序执行、互相覆盖
  scrollTop（先点的 rAF 晚执行会把位置设成错的）。极端操作，当前未做渲染 token 防抖。
- **「显示思考」开关**：切换会改变消息内容高度，历史 scrollTop（绝对像素）会漂移，浏览器
  会自动 clamp 到新 scrollHeight 内，但位置对不上原内容。可接受。
- **内容变短**：历史 scrollTop 超过新 scrollHeight 时被 clamp 到底部附近。
- **localStorage 累积**：每个看过的 sessionId 留一条几字节记录，不清理（可接受）。
