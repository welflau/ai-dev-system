背景

2026-11-23 的体检文档列了 14 条问题并给了处理顺序。本轮按顺序做前 5 步里改动量小、 能用测试锁住的部分：修掉两个会让功能 / 门禁直接失败的问题（第 1、2 条），把测试接进 CI（第 3 条）， 收紧默认暴露面（第 4、5、6 条），统一版本号、配置模板和文档口径（第 7、8 条的一部分）。

开发过程中又查出体检文档没有覆盖到的三个问题，一并修了，见「调研结论」第 3、4、5 点。

调研结论

  1. POST /api/projects 挂在辅助函数上（体检第 1 条）。@router.post("") 下面紧跟的是 _auto_init_ads_dir，create_project 没有注册成路由，请求体被当成辅助函数的参数解析，返回 422。 对整个应用枚举路由后确认：以下划线开头的 endpoint 只有这一处，也没有重复的 method + path。

  2. cloud_video 包内成环（体检第 2 条）。环是 cloud_video ⇄ client ⇄ queue： client 顶层导入 queue，queue 排队超时要抛 client 里定义的 CloudVideoUnavailable， lightai 要抛 client 里的 CloudVideoError，client 又通过 from cloud_video import lightai 依赖包本身。根因是两个异常类放在了依赖最多的模块里。

  3. shell 黑名单比体检文档描述的更糟（新发现）。体检文档只说「覆盖不到 PowerShell 写法」， 实测旧正则连最典型的 bash / cmd 写法都拦不住：

    命令 旧正则 新正则
    rm -r dir 拦 拦
    rm -rf / 放行 拦
    rm -fr x 放行 拦
    format c:、format c: /q 放行 拦
    Remove-Item -Recurse -Force . 放行 拦
    del /f a.txt、rd /s /q build、shutdown /s 拦 拦

    原因：旧正则把所有分支包在 \b( ... )\b 里，结尾的 \b 要求匹配末尾落在单词边界上。 rm -rf 在 -r 处匹配结束，后面紧跟 f，不是边界；format c: 在冒号处结束， 后面是空格或行尾，两侧都不是单词字符，也不是边界。 这个正则同时被 actions/generic_cli.py 复用，两处一起受影响。

  4. Python 3.14 以下后端起不来（新发现）。backend/api/tickets.py 第 1455 行的函数注解用了 List， 文件里却没有 from typing import List。3.14 的注解是延迟求值的（PEP 649），所以本机一直正常； 在 3.12 上 import main 直接 NameError: name 'List' is not defined。 CI 用的正是 3.12，但 backend-test 只 import 了 models，碰不到这个文件。 按 CI 的 flake8 命令在本地复现，报 4 条 F821 undefined name 'List'（第 1455、1466、1474、1578 行）， 引入提交是 a40cba43（2026-11-12）。GitHub 上 lint job 的实际运行记录没有查看。

  5. chat_assistant.py 还有一处非法转义（新发现）。体检文档只记了 api/chat.py 的 \A， 新加的编译检查测试又抓到 agents/chat_assistant.py 提示词里的 \` 和 F:\A_Works\BigShot。

  6. 监听地址的实际生效值。从脚本入口启动（python main.py、start-backend.bat 都是）时， python-dotenv 从 config.py 所在目录向上找 .env，先命中 backend/.env，根目录 .env 不会被加载。 本机 backend/.env 没有 HOST，所以实际生效的是代码缺省值，改之前就是 0.0.0.0。 桌面版 desktop.py 自己绑定 127.0.0.1:18000，不受影响（体检文档里这句「未核实」已更新）。

关键设计

  • 异常类下沉到叶子模块，旧路径保持可用。from cloud_video import CloudVideoError 和 from cloud_video.client import CloudVideoUnavailable 仍然成立，而且拿到的是同一个类对象， except 不会漏接从另一条路径抛出来的异常。测试里同时断言了 errors.py 只 import __future__， 以及 queue / lightai 不再 import client，防止环被接回去。 没有用更新 layers_baseline.json 的办法消违规，基线文件未动。

  • 黑名单定位是兜底，不是安全边界。命令串可以用变量拼接、.NET API、脚本文件绕过， 主要防线仍是 Tier 1 的用户确认和权限审批，这一点写进了代码注释。规则的写法：

    • 开头统一用 (?<![\w-])，所以 --rm、graceful-shutdown 这类不会被当成命令词；
    • 每条规则自带收尾断言 (?![\w-])，不再依赖外层的 \b；
    • 删除类规则在「同一条命令内」（不跨 | ; &）找递归 / 强制开关，开关可以出现在路径后面；
    • PowerShell 的参数缩写（-r、-rec、-fo、-for）单独列出，bash 的短选项簇限定在 rfdiv 这几个字母， 避免 -LiteralPath 这类正常参数因为含字母 r 被误判；
    • powershell -enc / -EncodedCommand 直接拦：Base64 之后的内容对确认界面和黑名单都不可见。
    • _DANGEROUS_PATTERNS 的名字和 .search() 用法不变，generic_cli.py 不用改。

  • 监听地址和 CORS 是「缩小暴露面」，不是鉴权。

    • HOST 缺省 127.0.0.1：局域网内其他机器连不上了，需要对外时在 backend/.env 显式写 HOST=0.0.0.0。
    • CORS 用 allow_origin_regex 放行 localhost / 127.0.0.1 / [::1] 的任意端口， 另加 CORS_ALLOW_ORIGINS 逗号分隔的显式白名单。前端由后端同源托管（const API = '/api'）， 同源请求不走 CORS，所以页面功能不受影响；用局域网 IP 打开页面时同样是同源。
    • CORS 只阻止浏览器里的跨域读取。恶意网页仍然可以向本机发出不需要预检的请求， 非浏览器客户端也完全不受限制。真正的鉴权（本地 token）本轮没有做，见「遗留」。

  • 兜底 500 按来源区分。本机调用方照旧拿到 str(exc)，界面上能直接看到原因，日常使用体验不变； 非回环来源只拿到通用提示和 12 位 error_id，详情凭 error_id 在 server.log 里查。 响应体新增了 error_id 字段，detail 字段保留。前面如果挂了同机反向代理，所有请求都会被当成本机。

  • 版本号单一来源。config.APP_VERSION = "0.22.0"，启动日志、FastAPI 文档、/api/health 都读它。 取值依据是 README 徽章和版本历史表里最新的 v0.22（此前代码里是 0.10.0 和 0.13.0 两个过期值）。 测试把 README 徽章和这个常量绑在了一起，以后只改一边会红。

  • 事件循环策略保留行为，只消警告。没有直接删掉 set_event_loop_policy：旧版 uvicorn 在 --reload / 多 worker 模式下会先设置 Selector 策略，这行代码的作用是把它盖回 Proactor， 删掉可能让那种启动方式下的子进程调用失败。现在的写法是放进 catch_warnings， 并用 getattr 兜住 3.16 移除该类之后的 AttributeError。

  • 提示词里的路径改成运行时推导。generated-images 与 main.py 挂载静态目录用的是同一个 BASE_DIR， 打包版会自动指向 runtime/ 下；deploy_ucp.py 按 chat_assistant.py 自身位置推导， 和 pack_installer._PACKS_DIR 是同一个目录，没有为此新增跨层 import。命令里顺手给脚本路径加了引号。

  • _utc_now_z() 保持字符串格式。datetime.now(timezone.utc).replace(tzinfo=None).isoformat() + "Z"， 输出和原来逐字符同形，不会多出 +00:00。

实现坑

  1. 行尾混用。仓库里 main.py、config.py、api/*.py、ci.yml、根目录 .env.example 是 CRLF， cloud_video/*、actions/*、docs/、dev-notes/ 是 LF。全程用「精确匹配 + 保持原行尾」的小脚本改文件， 每次替换都校验命中次数，避免整文件被改写成另一种行尾、diff 里全是噪音。

  2. 提示词改动要证明没改内容。chat_assistant.py 的 \` 改成 \\` 之后， 用 AST 把改动前后（git show HEAD: 对比工作区）所有字符串常量取出来比对： 除了 deploy_ucp 那几行，其余常量完全一致，说明运行时的提示词文本没有变化。

  3. 测试文件自己也会触发 SyntaxWarning。回归测试的 docstring 里一开始直接写了 F:\A_Works\...， 等于把要消灭的问题又写了一遍，改成文字描述。

  4. utcnow 的回归断言不能用字符串搜索。新 helper 的 docstring 里就有 utcnow() 字样， 改用 AST 查 Attribute(attr="utcnow")。

  5. 3.12 下 pytest 的报错会被掩盖。import main 失败时，pytest 最后抛的是 ValueError: I/O operation on closed file，真正的 NameError 要单独 python -c "import main" 才看得到。 推测与 main.py 开头把 sys.stdout.buffer 包成新的 TextIOWrapper 有关（模块导入失败后包装对象被回收， 连带关掉了 pytest 的捕获文件），没有进一步验证，也没有改，记在「遗留」里。

  6. python -c 和脚本入口加载的 .env 不一样。python -c "from config import settings" 在仓库根目录执行时 加载的是根目录 .env（得到 HOST=0.0.0.0），而脚本入口加载的是 backend/.env。 验证监听地址时必须用脚本入口，否则会得出相反的结论。

  7. 运行期间审批服务出过一次故障。有一轮只读命令被自动审批复核拦下，原因是复核服务自身报错 （不是命令被判为不安全）。原样重试一次仍失败后停下等待，审批配置恢复后继续，没有换别的方式绕过。

行为变化（升级后需要知道）

  1. 服务默认只监听 127.0.0.1。本机此前实际监听的是 0.0.0.0:8001。如果有从其他机器、手机或虚拟机 访问这个后端的用法，需要在 backend/.env 里加 HOST=0.0.0.0。
  2. 跨域调用只放行本机来源。如果有别的站点（非本机来源）的网页在调这个后端， 需要把它的来源写进 CORS_ALLOW_ORIGINS。
  3. /api/health 的 version 从 0.13.0 变成 0.22.0，FastAPI 文档页的版本同步变化。
  4. shell 工具会拒绝更多命令，包括此前能通过的 rm -rf、format c: 和各种 PowerShell 递归 / 强制删除。 openspec 这类 skill 的 --description / --goal 自由文本也会过同一个黑名单， 文本里出现 format c:、rm -rf 这类字样会被拒绝（旧规则对 shutdown、reboot 等词已有同样的行为）。
  5. 非本机来源的 500 响应不再带异常文本，多了 error_id 字段。

遗留与后续

本轮刻意没做：

项 原因
本地 token 鉴权（体检第 4 条第 3 步） 要同时改 SSE（EventSource 不能带请求头）、<img> 直链、/generated-images 等静态挂载和 3.5 万行的 app.js，没有浏览器端到端验证手段，改坏的概率高。建议单独立项，先定 token 的传递方式（Cookie / 查询参数 / 请求头）。

大文件拆分、宽泛 except、分层治理（第 10–12 条） 长期项，不在本批范围。
