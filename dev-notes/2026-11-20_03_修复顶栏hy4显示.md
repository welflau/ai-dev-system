# 修复顶栏 LLM 模型显示（hy4 幽灵）（2026-11-20）

> 关联方案：`docs/20261119_01_plugin-import外部仓库接入插件方案.md` §18

> 提交基线：`ef48ba4`（生视频配置 Tab）；本篇改动**尚未提交**。

## 背景

用户两张截图：配置的是 CLI 模式 CodeBuddy + `deepseek-v4-pro-ioa`（红箭头指向模型下拉），
但顶栏徽标「有时显示 hy4 / 有时显示可用」，问「是缓存了？」。

诊断结论：**不是缓存**，三个原因叠加。用户拍板「按这 4 项全修」。

## 根因（逐条实证）

1. **两套 JS 抢同一个 `#llmStatus` DOM**
   - `checkLLMStatus()` `app.js:2427`（DOMContentLoaded、保存配置、切模型时）写 `LLM: ${data.model}`；
   - `checkServerHealth()` `app.js:19449` → `updateLLMStatusIndicator('available')` `app.js:19590`
     （`initLogPanel` 启动 + `setInterval` 每 30s）写「可用」。
   - 谁后写谁显示 → 时而 `LLM: hy4`、时而「可用」，看起来像缓存。
   - 前端**无任何 localStorage/sessionStorage 缓存** LLM 状态，`window._llmConfig` 只是每次实时
     `GET /api/llm/status` 的内存变量，刷新页面就没了。
2. **`/api/llm/status` 的 `model` 字段错配**：`main.py:574` 无条件返回 `llm_client.model`。
   CLI 模式下 `model` 是 API 模式遗留主模型名（`.env:4` `LLM_MODEL=hy4`），**不参与实际调用**。
   后端其它地方（`llm_client.py:2328`/`:2371`、`api/chat.py:_snapshot_llm_meta`）都做了
   `is_cli ? cli_model : model` 区分，唯独 status 端点没做。
3. **保存链路把 hy4 一遍遍固化**：`saveLLMConfig()` `app.js:2807` 无条件把隐藏的 `llmModel`
   输入框（回填自 `data.model` = hy4）作为 `payload.model` 发回 → `main.py:631` 写回
   `llm_client.model` → `main.py:675` 再写回 `.env` 的 `LLM_MODEL=hy4`。
   这是最像「缓存」的一环，其实是配置回写循环。

实证（改前）：
```
api_format : cli
model      : hy4                    <- /api/llm/status 的 model
cli_model  : deepseek-v4-pro-ioa     <- CLI 实际调用用的
=> 顶栏 checkLLMStatus 用 data.model => LLM: hy4
=> 聊天头像/日志用 cli_model      => deepseek
```

## 四项修复

| # | 改动 | 文件 |
|---|---|---|
| 1 | `/api/llm/status` 新增 `display_model`（CLI 取 `cli_model or model`，API 取 `model`）；`model` 保留原语义供 API 输入框回填；`_public_llm_fields()`（`/api/llm/agents`）同步加 | `backend/main.py` |
| 2 | 顶栏**单一数据源**：`checkLLMStatus()` 用 `display_model` 写文字与 class；`updateLLMStatusIndicator()` 降级为**只改点色**、绝不碰 `.text`；`checkLLMStatus` 包装器日志判断从「读 DOM 文字」改为「读 `window._llmConfig.configured`」 | `frontend/app.js` |
| 3 | 保存链路：前端 CLI 模式**不发 `model`**；后端 CLI 模式**忽略 body.model**、**不写 `LLM_MODEL` 到 .env**；`.env` 残留 `LLM_MODEL=hy4` → `deepseek-v4-pro-ioa`（字节级最小替换，其余 44 行原样保留） | `frontend/app.js` / `backend/main.py` / `backend/.env` |
| 4 | 历史聊天消息 `llm_model` 快照**保持不动**：记录的是当时真实用的模型，老消息里的 hy4 是历史事实 | 不改代码，仅测试确认 |

## 边界

- `model` 字段**不改名、不改语义**（API 模式弹窗回填依赖它），`display_model` 是纯增量。
- `.env` 被 `.gitignore:39` 忽略，**不会进提交**；本地清理只对当前机器有效，
  代码层修复（不写回 + display_model）才是跨机器生效的部分。
- API 模式保存行为完全不变（测试覆盖）。
- 顶栏点色（健康检查 = 后端可达性）与文字（checkLLMStatus = LLM 配置）语义分离，不再互相覆盖。
