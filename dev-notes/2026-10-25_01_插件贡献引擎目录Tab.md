# 仓库页的引擎目录 Tab 由插件声明

2026-10-25

## 起因

UE、Unity 项目除了仓库本身，还要能看到引擎装在哪。这个目录不在 git 里，也不该写进宿主的 Git / P4 逻辑。两边的安装位置和版本号规则都不一样，要不要出现、叫什么、指向哪个文件夹，由各自的插件决定。

## 实现

插件在 `workspace.py` 里提供 `workspace_roots(project)`。宿主 `collect_workspace_roots` 只按 `plugin.json` 的 `required_traits` 收集，不认识 Epic 或 Unity Hub 的路径。

- UE 插件（`engine:ue5` / `engine:ue4`）：优先用项目上保存的 `ue_engine_path`，没有再按 `.uproject` 的 EngineAssociation 解析。Tab 文案取主次版本，例如「UE 引擎 5.7」。
- Unity 插件（`engine:unity`）：读 `ProjectSettings/ProjectVersion.txt` 的 `m_EditorVersion`，再对 Hub 的 editors 清单和常见的 `Editor/<版本>` 目录。

解析不到时插件仍返回一条记录，Tab 出现并说明原因。没有 `workspace.py` 的插件不出现。

浏览接口是 `GET /api/projects/{id}/workspace-roots`，以及该根下的 `tree` / `search` / `file` / `file-raw`。相对路径用和仓库文件一样的越界检查，客户端不能拿绝对路径往外读。树一次只列一层。搜索按广度优先，扫到预算就停。

仓库页在 Git / P4 后面追加这些 Tab。引擎 Tab 下收起分支和提交记录，选择器显示引擎根路径。双击文件仍在右侧预览，不按项目仓库的相对路径去开标签。

## 效果

TestFPS（`engine:ue5`，没有手填引擎路径）出现「UE 引擎 5.7」，指向 `G:\EpicGames\UE_5.7`。根目录是 Engine、FeaturePacks、Templates。H5 项目的这个接口返回空列表，不出现 Tab。`../` 越界返回 400。
