# 聊天超链接可点击 + 网页 Tab 内嵌显示

2026-10-10

## 起因

外部会话气泡里的 MR 创建链接等裸 URL 是纯文本，不可点。需求：URL 可点击，点击开一个
主舞台 Tab 内嵌显示网页。

## 实现

**URL 链接化** `frontend/app.js`：

- `_linkifyUrls(text)`：裸 URL → `<a class="chat-url-link">`，在 `_inlineFormat` 的标签占位
  保护区内调用（已有 `_linkifyBareFilePaths` 同款机制），只碰纯文本，不会碰已生成的锚点。
  `_inlineFormat` 是主聊天 + 外部会话气泡共用的，两处同时生效。
- 输入文本是 HTML 转义过的，URL 里 `&` 是 `&amp;` 形态——href/onclick 属性会被 HTML 解码回
  `&`，正好；label 不重复转义。
- 边界处理（node 单测过）：
  - 尾部实体（`&gt;`）和 ASCII 标点剥离；
  - **括号配平**：URL 内合法含 `()`，只把"超配平"的尾部 `)` 还给正文（markdown `[x](url)` 收尾）；
  - **CJK 不进 URL**：中文句子和 URL 之间常无空格，正则排除 `\u4e00-\u9fff`/全角标点区，
    否则 `https://x/path。多个` 会把后文吞进链接。

**网页 Tab**：

- `adsShell.openMain({type:'web', url, title})` 新分支：同 URL 复用同一 Tab（id=`web:<url>`），
  标题 `_webTabTitle`（主机名 + 路径尾段）。
- `_loadMainTabContent` web 分支：头部 = 标题 + ↻ 重新加载（`adsShell.reloadWebTab`）+
  ↗ 系统浏览器打开（`window.open` 兜底），主体 = `<iframe>`（referrerpolicy=no-referrer，
  不加 sandbox 以免目标站登录态/存储被破坏）。
- Tab 图标 🌐；`openWebTabFromChat(url)` 全局入口：项目壳层开 Tab，否则退回系统浏览器；
  聊天全屏时先 `_exitChatFullscreenSoft()`。

## 追加：工蜂拒绝内嵌实锤 → 系统浏览器兜底（2026-10-10 下午）

用户截图证实：git.tencent.com 在 iframe 里显示"拒绝了我们的连接请求"（X-Frame-Options），
和预判一致。浏览器安全机制，应用侧无法绕过（除非后端反代，但登录态/SSRF 问题一大堆，不做）。

兜底落地：

1. **后端** `main.py` 新增 `GET /api/open-in-browser?url=`：`webbrowser.open(url)` 调系统
   默认浏览器，仅放行 http/https。比 `window.open` 可靠（应用壳里 window.open 行为不可控）。
2. **前端**：网页 Tab 头部 ↗ 改走该端点（失败退回 window.open）；iframe 上方常驻一条
   `.main-ws-web-hint` 黄色提示条："部分站点禁止内嵌，白屏请点 ↗"。
3. 链接点击仍先开 Tab（保留"应用内打开"的路径，未来换壳或站点放行时自动可用）。

## 关键限制（如实告知用户）

iframe 内嵌第三方站点受 **X-Frame-Options / CSP frame-ancestors** 约束——git.tencent.com
这类站点大概率拒绝被内嵌，iframe 会白屏。头部 ↗ 按钮是兜底。应用若是 Electron 壳且关了
webSecurity 则能嵌；纯浏览器环境基本只能靠 ↗。

## 验证边界

- `node --check` 过；`_linkifyUrls` 用 5 组用例单测（主用例 &amp;、尾部实体、markdown 括号、
  多 URL 无空格中文、纯文本）。
- 未跑浏览器实测：iframe 白屏行为、onclick 属性里 `&amp;` 的解码链路均按规范推断。
- URL 正则不匹配 `\n`，跨行折行的 URL（截图里那种长 URL 换行显示）源文本若真有换行符
  会只链到行尾——实测 Cursor 消息里 URL 是完整一行，未处理折行拼接。
