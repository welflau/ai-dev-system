# 项目本地 MCP Server 运行时端口协议自动嗅探

2026-10-23

## 起因

像 `Kinema`（`F:\A_Works\Kinema`）这样的项目自带了内嵌在开发服务器中的 Streamable HTTP MCP Server（`http://127.0.0.1:5173/mcp`，Server 名为 `bagins`，暴露 23 个关卡编辑与导航工具），但仓库内没有显式编写 `.ads/mcp_servers.json` 或 `.cursor/mcp.json`。

原先 ADS 的项目级 MCP 发现（`backend/mcp_client.py` 的 `_load_project_mcp_config`）仅靠读取静态 JSON 配置文件，存在三个问题：

1. **无法发现项目自建的运行中 HTTP MCP**：没有对项目开发端口（如 Vite `5173`）挂载的 `/mcp` 端点做协议探测。
2. **CLI 模式未注入 HTTP MCP 与多路项目配置**：`backend/llm_client.py` 在组装 `--settings` / `--mcp-config` 时只读了 `.ads/mcp_servers.json` 的 `command/args/env`，既漏掉了 `url`（HTTP/SSE 类型），也未合并自动嗅探或 `.mcp.json` / `.cursor/mcp.json` 的项目级配置。
3. **本机 HTTP MCP 被慢速 stdio 子进程阻塞**：Windows 下首次预热若同时派生十余个用户级 stdio MCP 子进程，事件循环会被子进程启动占满，导致本机毫秒级即可就绪的 HTTP MCP 未能在首轮对话前完成 `list_tools`。

## 实现

**候选端口提取与轻量协议握手探测（`backend/mcp_client.py`）**

- `_collect_candidate_mcp_ports(repo_path)`：复用 `propose_project_icebreak._detect_launch_entries` 提取项目的前后端开发端口（如 Vite `5173`），并补充扫描 `vite.config.*`、`scripts/*mcp*`、`.env`、`README.md` 中的本机端口。
- `probe_http_mcp_endpoint(url, timeout=0.6)`：向 `http://127.0.0.1:{port}/mcp` 发送 JSON-RPC `initialize` 探测（同时兼容 `application/json` 与 `text/event-stream` SSE 响应格式），解析 `result.serverInfo.name` 与 `version`；探测拿到 `mcp-session-id` 后立即发送 `DELETE` 释放临时探测会话，避免在目标开发服务器（如 Kinema 的「连接过的 Agent」面板）留下僵尸连接记录。
- `sniff_project_http_mcp_servers(repo_path)`：并发探测候选端口，将发现的 MCP Server 写入 `_SNIFFED_MCP_CACHE` 并合入 `_load_project_mcp_config`（优先级高于用户级全局配置，低于项目内 `.ads/mcp_servers.json` 等显式配置，允许用户显式覆盖或禁用）。
- **启动优先级排优**：在 `warmup_project_servers` 与 `list_tool_schemas_for_project` 中优先启动 `_sniffed` 本机 HTTP MCP 并等待其握手完成，再后台派生耗时的 stdio 进程；当用户在破冰卡点击「一键启动」拉起项目开发服务（`POST /api/chat/env-services/start`）端口就绪后，自动触发 `warmup_project_servers` 完成嗅探与连接。
- 顺带补齐 `{repo}/.mcp.json`、`{repo}/.claude/.mcp.json`、`{repo}/.codebuddy/.mcp.json` 静态配置读取。

**CLI 模式与前端 MCP 面板同步（`backend/llm_client.py`、`backend/api/projects.py`、`frontend/app.js`）**

- `backend/llm_client.py`：复用 `_load_project_mcp_config(cwd, include_user=False)`，同时支持注入 `stdio`（`command/args/env`）与 `http`/`sse`（`type/url/headers`）类型的项目 MCP。
- `backend/api/projects.py` & `frontend/app.js`：`GET /api/projects/{id}/mcp/all` 触发端口嗅探并在尚未建连时顺手拉取 `tools` 列表，将项目级与嗅探到的 MCP 归入 `project`（📁 项目 MCP）分组，携带实时运行状态、已加载的 `tools` 列表及 `🛰️ 自动嗅探` 徽标。
- `frontend/app.js` & `frontend/styles.css`：修复 `_renderMcpView` 中工具标签未套 `.mcp-tools`（`flex-wrap: wrap; gap: 6px;`）且用 `join('')` 拼接导致 23 个工具名当成单个长单词横向撑破卡片的问题；修正 `.mcp-server-header` 左右徽标分组对齐。
- `backend/api/commands.py`：`/mcp-config list` 同步执行嗅探并展示 `🛰️自动嗅探` 来源标识。

## 验证

1. **单元测试**：`backend/_test_mcp_client.py` 新增 `test_http_mcp_port_sniffer`（模拟 Streamable HTTP SSE 握手、`DELETE` 会话清理与 `.ads/mcp_servers.json` 覆盖禁用），6/6 全部通过。
2. **Kinema 实测**：在 `F:\A_Works\Kinema`（`127.0.0.1:5173` 运行中、无任何静态 MCP 配置文件）上调用 `mcp_client.list_tool_schemas_for_project(r"F:\A_Works\Kinema")`，自动嗅探出 `bagins (http://127.0.0.1:5173/mcp v0.1.0)` 并成功连接拉取全部 23 个工具（`mcp__bagins__navigate_to_menu`、`mcp__bagins__open_editor`、`mcp__bagins__add_object` 等）。
