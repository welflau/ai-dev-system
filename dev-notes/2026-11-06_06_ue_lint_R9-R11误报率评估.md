# DevLog：ue_lint R9-R11 误报率评估

> 日期：2026-11-06
> 关联：R9/R10/R11 交互检查规则（044aab8 / c4cebe9 / 9993d91）

## 评估方法

用典型 UE 代码模式实测三条规则的误报（正确代码被误报为 warning）。

## 实测结果

| 场景 | 代码 | R9 | R10 | R11 |
|---|---|---|---|---|
| UI 按钮绑定（正确） | `Button->OnClicked.AddDynamic(this, ...)` | ❌ 误报 | ❌ 误报 | — |
| 回调只访问 this（正确） | `void F() { ClickCount++; }` | — | ❌ 误报 | — |
| 函数重载（正确） | `void F() { F(1); }` | — | — | ❌ 误报 |
| 真递归（bug） | `void F() { F(); }` | — | — | ✅ 真阳性 |

## 误报率评估

| 规则 | 误报率 | 主要误报场景 | 真阳性价值 |
|---|---|---|---|
| R9 委托配对 | **高（~50-70%）** | UI 组件委托（OnClicked/OnCheckStateChanged），UE UMG 最常见模式，几乎全无需 Remove | 中（跨生命周期委托泄漏） |
| R10 空引用 | **中（~30-40%）** | 回调只访问 this 成员（无空引用风险） | 中（空引用崩溃） |
| R11 递归 | **低（<10%）** | 函数重载（同名不同参数） | 高（递归是明确 bug） |

## 根因分析

1. **R9 误报根因**：UE 委托分两类——「跨对象生命周期」（OnDestroyed/OnActorBeginOverlap，需 Remove）和「UI 组件」（OnClicked/OnCheckStateChanged，随 owning widget 销毁，无需 Remove）。R9 不区分，一刀切报。
2. **R10 误报根因**：只检查"有无 IsValid"，不分析"访问了哪个对象"。回调只访问 this 成员时无空引用风险，但被误报。
3. **R11 误报根因**：正则 `\bFunc\s*\(` 匹配了带参数的调用（重载），实际递归是「无参调用自身」。

## 改进方向（按优先级）

### 1. R9 加委托类型白名单（高优先级）

只检查跨对象生命周期的委托，跳过 UI 组件委托：

```python
# 跨对象生命周期委托（需要 RemoveDynamic）
_LIFECYCLE_DELEGATES = {"OnDestroyed", "OnActorBeginOverlap", "OnActorEndOverlap", "OnEndPlay", "OnDeath"}
# UI 组件委托（随 owning widget 销毁，无需 Remove，跳过）
# OnClicked / OnCheckStateChanged / OnValueChanged / OnHovered / OnPressed ...
```

### 2. R11 正则精确化（中优先级）

只匹配无参调用（递归是"调用自身"），排除带参数的调用（重载）：

```python
# 递归：无参调用自身
re.search(r"\b" + re.escape(cb) + r"\s*\(\s*\)", body)
```

### 3. R10 接受当前误报（低优先级）

"回调只访问 this"的改进需分析对象访问，成本高收益低。warning 级别可接受，靠逃生注释消化。

## 建议

- R9 误报率高，**建议立即加委托类型白名单**（改动小，收益大）。
- R11 误报率低但改进极简（正则加 `\s*\)`），**顺手做**。
- R10 误报率中等但改进成本高，**接受现状**。
- 三条均为 warning 级别，误报不阻塞流程（self_test 只看 blocking），短期无副作用。

## 修复实施（已落地）

1. **R9 白名单**：加 `_LIFECYCLE_DELEGATES`（OnDestroyed/OnActorBeginOverlap/OnEndPlay/OnDeath/OnTakeAnyDamage/OnComponentHit 等 12 个跨生命周期委托），R9 只检查白名单内的委托，跳过 UI 组件委托（OnClicked 等）。
2. **R11 正则精确化**：`\bFunc\s*\(` → `\bFunc\s*\(\s*\)`，只匹配无参调用，排除函数重载。

### 修复后验证

| 场景 | 修复前 | 修复后 |
|---|---|---|
| R9 UI 按钮绑定（OnClicked） | ❌ 误报 | ✅ 不报 |
| R9 OnDestroyed 无 Remove | ✅ 报 | ✅ 仍报 |
| R9 OnDestroyed 有 Remove | ✅ 不报 | ✅ 不报 |
| R11 函数重载 | ❌ 误报 | ✅ 不报 |
| R11 无参递归 | ✅ 报 | ✅ 仍报 |

误报率改善：R9 从 ~50-70% 降到 <10%（仅剩跨文件解绑误报），R11 从 ~10% 降到 ~0%。

## R10 误报改进（补充落地）

R10 原逻辑「回调体内有无 IsValid」误报率高（~30-40%），根因是"回调只访问 this 成员"被误报。

**改进**：只关心「非 this 的对象指针访问」——回调体内提取所有 `X->` 访问，排除 `this->`，无非 this 指针访问则跳过（无空引用风险）。

### R10 修复后验证

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 只访问 this 成员（无 `->`） | ❌ 误报 | ✅ 不报 |
| `this->` 成员访问 | ❌ 误报 | ✅ 不报 |
| 访问其他对象无 IsValid | ✅ 报 | ✅ 仍报（真阳性） |
| 访问其他对象 + IsValid | ✅ 不报 | ✅ 不报 |
| 回调参数指针访问无守卫 | ✅ 报 | ✅ 仍报（保守） |

**误报率改善**：R10 从 ~30-40% 降到 ~10-15%（剩余误报：回调参数指针访问，参数可能为空需保守保留）。
