# 无围栏回复散文净化 + SelfTest 语法污染拦截 + 后台任务 cmd 数组容错

2026-10-23

前作：`dev-notes/2026-10-23_07_时间轴进行中步骤动效与后台任务按钮.md`

## 起因

两个现场问题：

1. 点时间轴上的 **📟 后台任务** 打开面板时报 `加载失败: TypeError: str.replace is not a function`。
   - 根因：`h5_typecheck` / `h5_playtest` 把 `command` 存成了 argv 数组（`List[str]`），`_buildTicketTasksFromLogs` 原样赋给 `t.cmd`；数组的 `.length <= 50` 跳过了截断，传进 `escapeHtml(cmd)` 时调 `str.replace` 直接抛错。
2. `src/scenes/GameScene.ts`、`package.json`、`scripts/verify-files.mjs` 文件开头被写进了 LLM 的对话回复（如 `Typecheck passes. 已按要求修改 src/scenes/GameScene.ts… 修改后的完整文件内容：`），但 `[2/2] 自测验证` 却显示 `自测 7/7 通过 ✅`，直到下一阶段 `h5_typecheck` 跑 `tsc --noEmit` 才报 38 个语法错误。
   - 根因 A（为什么生成脏了）：`PlanCodeChangeAction._generate_file / _modify_file` 的 prompt 写的是「不要 markdown 代码块包裹」，LLM 照做不打 ```` ``` ```` 围栏，但前面照样带了一段中文解释；而 `strip_code_fences` 只在 `len(spans) == 1`（有围栏）时才剥散文，0 围栏时原样放行。
   - 根因 B（为什么自测没拦住）：`SelfTestAction` 的「语法检查」只测 `.py`（`compile`）和 `.html`（`<html`），既不测 `.json` 也不调 `find_content_defects`；更致命的是非 UE 项目就算语法检查不通过，`DevAgent._do_develop` 也无条件打勾 `phase="done"` 并流向 `development_done` 提交入库。

## 实现

1. **后台任务面板容错**（`frontend/app.js` + `h5_typecheck.py` / `h5_playtest.py`）：
   - `escapeHtml`、`_buildTicketTasksFromLogs`、`_refreshTasksPanelInner` 对 `Array` 自动 `.join(' ')` 转字符串。
   - `h5_typecheck` 与 `h5_playtest` 落 `data["command"]` 时统一存命令行字符串。
2. **无围栏散文剥离与提示词修正**（`backend/content_sanitizer.py` + `backend/actions/plan_code_change.py`）：
   - `strip_code_fences` 在 `len(spans) == 0` 时走 `_strip_unfenced_prose`：
     - `.json` 整体解析失败时，剥掉外围散文提取可 `json.loads` 的 `{...}` / `[...]`。
     - 源码文件首行是散文时，向后定位第一行真实源码/注释/shebang（`#!`、`import`、`export`、`//`、`/*` 等），并剥除尾部「说明：…」散文段落。
   - `find_content_defects` 新增 `.json` 的 `json.loads` 校验。
   - `PlanCodeChangeAction` 改为要求单个 ```` ``` ```` 代码块包裹，净化后若仍有 `find_content_defects` 缺陷则拒绝覆盖文件。
3. **SelfTest 真拦截**（`backend/actions/self_test.py` + `backend/agents/dev.py`）：
   - `SelfTestAction` 落盘前先跑 `sanitize_delivery_files`；「语法检查」对所有文件跑 `find_content_defects`。
   - `DevAgent._do_develop` 在自测出现语法/非空/落盘失败时，标记 `自测验证` 为 `phase="error"` 并返回 `status="development_failed"`，不再假装 7/7 通过。

相关测试：`backend/_test_content_sanitizer.py`（63 项全绿）、`backend/_test_command_log_ui.js`（30 项全绿）。
