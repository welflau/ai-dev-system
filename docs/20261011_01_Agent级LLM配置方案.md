# Agent 级 LLM 配置方案

> 日期：2026-10-11  
> 状态：✅ 已实现并验证（后端 + 前端入口全部落地）

## 背景

当前系统只有一个**全局** LLM 配置（`.env` 的 `LLM_*` / `LLM_CLI_*`），所有 Agent（orchestrator 调度的 Role Agent + AI 助手 + 其他）共用同一个 `llm_client` 单例。需求：

1. 每个 Agent 可以指定自己的模型 API（base_url / api_key / api_format）
2. 每个 Agent 可以指定用哪个 CLI、哪个模型（cli_type / cli_cmd / cli_model）
3. AI 助手（ChatAssistant）这类 Agent 也能配自己的一套
4. 点击 AI 助手头像弹出配置界面

## 现状盘点（事实落地）

- **全局单例**：`llm_client = LLMClient()`（backend/llm_client.py:2762），配置来自 `config.py` 的 `LLM_*`/`LLM_CLI_*`（env 驱动）。
- **运行时改配**：`POST /api/llm/config`（backend/main.py:584）改单例字段 → 同步 `settings` → 写回 `.env`。没有 per-agent 维度。
- **所有调用点共享**：Role Agent（`llm_client.chat()`）、AI 助手（backend/api/chat.py:290/371/483 等）、REACT 模式（base.py:509/575）都直接 `from llm_client import llm_client`。
- **Agent 枚举入口**：`agent_registry._REGISTRY`（backend/agent_registry.py）自动发现所有 `BaseAgent` 子类，天然是配置维度来源。
- **头像 meta**：`_snapshot_llm_meta()`（backend/api/chat.py:2731）读单例字段，前端头像据此显示 model/cli 图标。
- **已有协程上下文**：`_llm_ctx`（llm_client.py 内的 `contextvars`）已用于 ticket/agent/action 追踪，协程安全。

## 核心决策

### ① 配置层级：全局继承 + 每 Agent 覆盖

每个 Agent 的生效配置 = 有覆盖则用覆盖，无则用全局。字段与全局完全同构：

```
api_format  (anthropic / openai / cli)
base_url, api_key, model        # API 模式
cli_type, cli_cmd, cli_model    # CLI 模式
cli_timeout
```

未配置的 Agent 零迁移成本（继承全局）。覆盖采用**整包覆盖 + 显式继承开关**语义：要么整套用自己的，要么整套继承全局，避免「只改 model 忘了改 key」的半套状态。

### ② 路由方式（关键选型）：ContextVar + 上下文感知代理

**方案 A（推荐）**：复用 `_llm_ctx` 的 contextvars 模式。在 Agent 边界设 `agent_type`，`llm_client.chat()/stream()` 入口按当前 agent_type 解析出对应配置，走既有的 `_call_api` / `_call_cli`。

- `llm_client` 保持单例，零侵入：所有 `llm_client.chat(...)` 调用点不改。
- 实现要点：`chat()/stream()` 开头 `cfg = _resolve_config_for_context(agent_type)`；`_call_cli` 用的 `self.cli_cmd/cli_model/cli_type` 和 API 模式的 `self.model/base_url/api_key` 从解析出的 cfg 取值（可用局部变量传递，不改核心逻辑）。
- 配置按 agent_type 内存缓存，配置写入时失效。
- **连带修正**：`_snapshot_llm_meta` / `/api/llm/status` 目前读裸字段，需改为读「当前上下文解析后的配置」，头像和状态面板才能正确反映每个 Agent 实际用的模型。

**方案 B（不推荐）**：per-agent 独立 `LLMClient` 实例 + 显式传参 `get_llm(agent_type).chat()`。改动面大、易漏调用点。

选定 **方案 A**。

### ③ 存储：新表 `agent_llm_config`

```
agent_llm_config(
  id,
  agent_type TEXT UNIQUE,          # 具体 agent 名；无 '__default__'（未配置即继承全局）
  api_format TEXT, base_url TEXT, api_key TEXT,
  model TEXT, cli_type TEXT, cli_cmd TEXT, cli_model TEXT, cli_timeout INTEGER,
  updated_at TEXT
)
```

- 不放 `.env`（.env 只存全局默认），不塞 `system_settings` 大 JSON；独立表查询清晰。
- 「恢复继承」= 删一行（DELETE），语义干净。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/llm/agents` | 枚举 `agent_registry` + 每 Agent 生效配置（覆盖 or 全局标注） |
| POST | `/api/llm/agents/{agent_type}/config` | 写覆盖（幂等 upsert） |
| DELETE | `/api/llm/agents/{agent_type}/config` | 删覆盖 = 恢复继承全局 |
| GET | `/api/llm/cli-models/refresh` | 复用现有：实时查 CLI 模型列表填下拉 |

## 前端（实际落地入口）

1. **消息旁 AI 头像点击弹配置**（主入口，贴用户视线）：
   - 全局 AI 助手消息的头像 → `showAgentLlmConfigModal('ChatAssistant')`
   - 工单评论消息的头像 → 对应 `agent_type`
2. **Agent 详情弹窗**（设置 → Agents → 点 Agent）：新增「🧠 模型配置」区块，显示生效配置摘要 + 「⚙️ 配置模型」按钮。
3. **聊天面板标题栏 💬 图标** → `ChatAssistant` 配置。
4. **全局 AI 配置弹窗**（⚙️ → LLM Tab）：「🤖 各 Agent 独立模型配置 →」列出 13 个 Agent 选择。
   - 配置弹窗含「继承全局」开关（勾选=删覆盖）+ API/CLI 字段。

## 建议 MVP 范围

1. 后端：建表迁移 → `get_effective_llm_client()` → 三个 API。✅
2. 前端：头像 click → modal（AI 助手 + Role Agents）。✅
3. 验证通过后推广到 Role Agents（registry 枚举自动，工作量小）。✅

## 待拍板 / 风险

1. **CLI 与 API 按 Agent 混用**：方案 A 天然支持（AI 助手用 claude CLI、DevAgent 用 Anthropic API 可并存），但并发下多 CLI 子进程 + 多 API key 同时存活需确认可接受。
2. **API key 存储**：建议先明文进 SQLite（与现状 `.env` 明文对齐），安全加固（系统凭据）另开。
3. **`llm_status` / `_snapshot_llm_meta` 的上下文化**：改造点虽小，但涉及头像/状态面板展示，需回归验证。

## 实现总结（2026-10-11 已实现并验证）

### 后端

- 新表 `agent_llm_config`（`agent_type UNIQUE` + 全套 LLM 字段），`CREATE TABLE IF NOT EXISTS` 重启自动建表。
- **路由（方案 A 落地）**：复用已有 `_llm_ctx.agent_type` ContextVar（chat.py / orchestrator.py 的 `set_llm_context(agent_type=...)` 早已就位）。
  - `LLMClient.__init__(config=None)`：config 非空按字段覆盖 settings。
  - `get_agent_llm_config(agent_type)` 查表回填全局；`get_effective_llm_client()` 按上下文返回 per-agent 客户端或全局单例。
  - 4 个公开入口（`chat`/`chat_json`/`chat_with_tools`/`chat_with_tools_stream`）改成 facade 委托；**per-agent 独立客户端实例缓存**（非 `self.*` 临时交换），并发安全。
  - `_invalidate_agent_client()` 配置写入时失效缓存。
- API：`GET /api/llm/agents`、`POST /api/llm/agents/{agent_type}/config`、`DELETE /api/llm/agents/{agent_type}/config`（api_key 不外泄，仅 `has_api_key` 标记）。
- `_snapshot_llm_meta` 改 async + `get_effective_llm_client()`，消息头像/记录反映各 Agent 实际模型。

### 实现偏差

- 覆盖语义：方案写「整包覆盖 + 显式继承开关」→ 实现为**字段级 overlay**（空字段回填全局，更宽容）。
- 路由：方案写「ContextVar + `self.*` 临时取值」→ 实现为 **per-agent 独立客户端实例缓存**，避免并发下两个 Agent 互相覆盖字段。
- 前端入口：方案写「settings-agents 列表」→ 实际落在**消息旁头像**（用户视线所在）+ Agent 详情弹窗（settings-agents 的 Agent 列表是 skills/pack 那套注册表，与后端 role Agent 不是一回事）。
