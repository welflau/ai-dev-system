# 全局页面左侧导航与全局作用域方案

日期：2026-10-29
状态：方案待评审 → 第一期实施

## 1. 背景与目标

当前前端有两级页面，但只有项目页有侧边栏：

- **全局页** `#projectListPage`（“我的项目”）：无侧边栏，只有顶栏 4 个按钮
  （系统设置 / 全局对话追踪 / 导入现有工程 / 新建项目）+ 项目卡片网格 + 全局日志面板。
- **项目页** `#projectPage`：有 `projectSidebar`，含需求 / 工单 / 流程 / 文件 /
  外部会话 / Agent / 知识（知识库+资产库）/ 自动化 / 设置。

问题：**知识库和资产库本来就存在全局形态**，却被“藏”在两处——项目侧边栏的子项、
以及设置页的 Tab（`settings-knowledge` / `settings-assets`）。用户在全局页（未进任何项目）
想浏览全局知识库、全局资产库时没有入口，必须先进一个项目、再点设置。

目标：在**全局页也加入左侧导航条**，挑出“全局可用的条目”，其数据作用域为全局。
典型例子：

- 知识库 → **全局知识库**（G_Knowledge）
- 资产库 → **全局资产库**（G_ArtRes）

## 2. 现状梳理

### 2.1 页面与壳层

- 页面切换走 `showPage(pageId)`（`frontend/app.js:3110`）。
- `showProjectList()`（`app.js:3116`）→ `adsShell.leaveProject()` + `showPage('projectListPage')`。
- `showProjectDetail(projectId)`（`app.js:3132`）→ `adsShell.enterProject()` + `showPage('projectPage')`。
- 壳层抽象 `adsShell`（`app.js:279`），`enterProject()` 给 body 加 `shell-project`；
  `isProjectShell()`（`app.js:838`）判断当前是否项目壳。
- 项目侧边栏 DOM：`index.html:203` `<aside class="sidebar" id="projectSidebar">`，
  其导航结构 `index.html:215` 起（`sidebar-nav` / `sidebar-nav-group` / `nav-item`）。

### 2.2 现有“全局形态”的数据来源（关键结论：数据都已就绪，缺的是入口）

| 条目 | 全局数据源 | 现有 API | 备注 |
|---|---|---|---|
| 全局知识库 | G_Knowledge | `GET /knowledge/global`（`app.js:29879`）、`GET /knowledge/system`（`app.js:29850`） | 设置页已有“🌐 全局知识库”卡片（`index.html:1698`） |
| 全局资产库 | G_ArtRes | `GET /api/art-assets`、`/art-assets/stats` | `art_assets` 表天然全局，`project_scope='global'` |
| 全局 Agent | 内置 + 用户 Agent 注册表 | `GET /agents`（`app.js:15464`）、`GET /llm/agents`（`app.js:2684`）、`GET /agents/status` | 全局注册表，不依赖项目 |
| 外部会话（跨项目） | external_sessions | 全局对话追踪（`showGlobalChatTraceModal`） | 第二期候选 |

## 3. 设计原则（条目挑选标准）

一个条目能否上全局侧边栏，唯一判据：**它的数据是否本来就存在“全局作用域”形态**。
不把项目侧边栏整体照搬。

| 条目 | 全局形态 | 结论 |
|---|---|---|
| 知识库 | ✅ G_Knowledge | **上** |
| 资产库 | ✅ G_ArtRes | **上** |
| Agent | ✅ 全局注册表 | **上** |
| 外部会话 | ✅ 跨项目追踪 | 第二期可选 |
| 需求 / 工单 / 流程 / 文件 / 自动化 | ❌ 全部绑 project_id | 不上 |

## 4. 方案设计

### 4.1 UI 布局

1. 在 `#projectListPage` 内新增 `<aside class="sidebar" id="globalSidebar">`，
   **复用现有 sidebar 整套样式类**（`sidebar` / `sidebar-header` / `sidebar-nav` /
   `sidebar-nav-group` / `nav-item` / `nav-sub-item`），不新造 CSS 体系。
2. 全局页布局从“通栏”改为“侧边栏 + 内容”两列。用与项目页相同的 `project-layout`
   布局语义（或新增一个轻量 `.global-layout`），保证收起/展开行为一致。
3. 收起/展开复用 `toggleProjectSidebar()` 的模式；偏好键新增独立的
   `ads.shell.globalSidebarCollapsed`，与项目侧边栏互不干扰。

侧边栏结构（第一期）：

```
🌐 全局
├─ 📚 知识库      → 全局知识库（G_Knowledge）
├─ 🖼️ 资产库      → 全局资产库（G_ArtRes）
└─ 🤖 Agent      → 全局 Agent 注册表
```

### 4.2 数据作用域：不加新后端表，组件按 scope 参数化

后端 API 全部现成，核心是前端把“全局视图”与“项目视图”用 **scope 参数**区分：

- 全局页资产库 = `scope: global`（`project_scope='global'` 的资产，现状即此）。
- 项目页资产库 = `scope: project`（该项目资产）。

知识库同理：全局页 → `/knowledge/global`，项目页 → `/knowledge/projects/{id}/...`。

这正好衔接资产四维作用域模型（global / project / ticket / session）：全局侧边栏的
资产库就是 `scope:global` 视图；工单/会话资产被“提升”（promote）到全局后，
自然出现在这里。会话层的登记、TTL 与提升见
[`docs/20261101_01_会话临时素材管理方案.md`](./20261101_01_会话临时素材管理方案.md)。

### 4.3 点击路由（已确认结论）

**关键事实（已确认）**：所有 `.tab-content` 都挂在 `#projectPage` 内
（`index.html:408` 起），全局页 `#projectListPage` 无任何 tab-content。
因此 `switchTab`（`app.js:3372`）只作用于项目页，**全局页无法复用**。

结论：全局侧边栏条目点击后，在全局页内容区**内嵌独立视图**，不走 `switchTab`。
为规避 DOM id 冲突（设置页已有 `assetListGrid` / `assetSearchQ` 等），全局视图使用
**全新 DOM id**，并新增独立的渲染函数，不复用设置页现有函数（除非抽成带容器参数的公共函数）。

- **第一期（纯前端，内嵌简化视图）**：
  - 全局页 `#projectListPage` 包进两列布局（侧边栏 + 内容区）。
  - 侧边栏 3 个条目（知识库 / 资产库 / Agent）+ 1 个“项目”（回到默认项目卡片视图）。
  - 点击条目 → 内容区切换显示对应全局面板（新 id，独立渲染函数，只取全局作用域数据）。
- **第二期**：面板升级为大视图（缩略图墙、文档列表），组件按 scope 参数化；
  顺手补缩略图短板（当前资产墙只对 svg 渲染真图，png/jpg 显示 emoji，`app.js:3470`）。

## 5. 实施步骤

### 第一期（1 次前端改动，无后端）

1. `index.html`：`#projectListPage` 包进 `.global-layout`（flex 两列：侧边栏 + 内容区）；
   新增 `globalSidebar`（复用 `.sidebar` 样式类）+ 3 个全局面板 DOM（新 id）。
2. `app.js`：
   - 新增全局侧边栏条目点击路由 + 收起逻辑（参照 `toggleProjectSidebar`，偏好键独立）。
   - 新增 3 个独立渲染函数（全局知识库 / 全局资产库 / 全局 Agent），
     分别调用 `/knowledge/global`、`/api/art-assets`、`/agents` + `/llm/agents`。
3. `styles.css`：新增 `.global-layout` 两列布局 + 收起规则
   （`.global-layout.sidebar-collapsed .sidebar { display:none }`），其余复用现有 sidebar 样式。
4. 验证：全局页侧边栏可收起/展开；3 个条目点击能到达对应全局视图；进入/退出项目
   时全局侧边栏状态不串；现有项目页、设置页回归无破坏。

### 第二期

1. 资产库/知识库从设置页 Tab 提升为全局页内独立视图。
2. 组件 scope 参数化（global / project 两态）。
3. 资产墙补 png/jpg 真缩略图渲染。

## 6. 与既有方案衔接

- **壳层方案**（`docs/20260806_01_ADS界面壳层与面板统一方案.md`）：本方案在
  `adsShell` 框架内新增“全局壳侧边栏”，与项目壳侧边栏并列，不破坏 `isProjectShell()`
  的判定逻辑。
- **资产四维作用域**（本轮讨论）：全局侧边栏的资产库即 `scope:global` 视图，
  是后续资产统一管理入口的 UI 落点之一。session / ticket 层已拆到独立方案
  [`20261101_01_会话临时素材管理方案.md`](./20261101_01_会话临时素材管理方案.md)，
  不把 `ticket` / `session` 塞进 `art_assets.project_scope`。

## 7. 决策点与风险

- **决策点 1（已定案）**：第一期直接做**全局页内嵌简化视图**，不跳转设置页 Tab。
  理由：所有 tab-content 挂在 `#projectPage`，全局页无法复用 `switchTab`；
  且设置页未来要降级为“配置入口”，资产/知识的浏览主战场应在全局页。
- **决策点 2（已确认）**：`.tab-content` 全部在 `#projectPage` 内，全局侧边栏必须走
  内嵌视图 + 全新 DOM id，不能复用设置页的 `assetListGrid` / `assetSearchQ` 等 id。
- **风险**：两列布局改动可能影响 `#projectListPage` 现有卡片网格与全局日志面板的
  响应式样式，改动后需回归全局页布局；`body.chat-open #projectListPage`（styles.css:613）
  的聊天面板腾位逻辑需一并兼容。
