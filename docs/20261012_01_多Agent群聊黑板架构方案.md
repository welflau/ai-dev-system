# 多 Agent 群聊黑板架构方案

> 日期：2026-10-12
> 状态：✅ Phase 1 已实现（回合制辩论 + 黑板读写 + 前端开关），Phase 2/3 待做

## 背景

当前「群聊」只有两版实现，本质是「多个 Agent 人格各自回答同一个问题」，**没有真正的协作**：

1. `/group`（`backend/api/chat.py:247`）——关键词/`@` 路由到**单个** Agent 人格回复，只是 persona 套壳。
2. `/group/all`（`backend/api/chat.py:329`）——3 个 Agent 用 `asyncio.gather` **并发盲答**，各自独立调 LLM，**互不可见**，也没有任何共享状态。

目标升级为「围着同一块黑板开会的团队」，满足三个需求：

| 需求 | 黑板模型的映射 |
|------|--------------|
| 多 Agent 群聊 | 多个 Knowledge Source（各 Agent 是不同专业视角）|
| 共享黑板上下文 | 结构化 Blackboard（分区状态对象，非消息流）|
| Agent 针对对话思考 | 每 Agent 每轮输出三态：**发言 / 私有思考 / 写黑板** |

## 现状盘点（事实落地）

- **群聊端点**：`/group`（`chat.py:247`）、`/group/all`（`chat.py:329`），persona 配置 `_AGENT_CONFIG`（`chat.py:198`）、关键词路由 `_KEYWORD_ROUTES`（`chat.py:234`）。
- **并发盲答**：`group/all` 里 `_call_agent` 只拼 `system_prompt + history + user`，Agent 之间无任何数据通道（`chat.py:357`）。
- **消息表**：`chat_messages` 已有 `session_id / turn_id / thinking_json / action_type / action_data / images_json / llm_model` 等列（`database.py:71/111/113/162` + `_save_chat_message` `chat.py:2813`）。**缺 `speaker`（发言人）和 `kind`（消息类型）两列**——当前 Agent 名字被塞进 `action_data={"type":"group_agent_reply","agent":...}`（`chat.py:314`）。
- **会话表**：`chat_sessions` 已有（`database.py:494`），支持多会话、标题、message_count。
- **迁移框架**：`database.py:71` 起有 `(table, column, type)` 的 ALTER TABLE 迁移列表，加列零成本。
- **思考基础设施**：`thinking_json` 存思考步骤、`/thinking-stream` SSE 频道（`chat.py:22/125`）、`BaseAgent` REACT 路径的 `thinking_steps` 事件（`base.py:350`）、`QueryEngine + Budget`（`base.py:282/295/300`）、`compact_history`（`base.py:546`）。

## 核心决策

### ① 黑板 = 结构化分区对象，独立建表

黑板是 `session_id` 维度的共享状态，用命名分区，**不是消息流**：

```jsonc
{
  "session_id": "S_xxx",
  "project_id": "P_xxx",
  "version": 3,
  "topic": "本次讨论的问题定义",
  "facts":     [{ "agent": "DevAgent", "content": "UE5.3 已确认", "ts": "..." }],
  "proposals": [{ "agent": "DevAgent", "content": "方案 B", "ts": "..." }],
  "open_questions": [{ "agent": "TestAgent", "content": "并发安全未验证", "ts": "..." }],
  "decisions": [{ "agent": "OrchestratorAgent", "content": "采用方案 B", "ts": "..." }],
  "artifacts": [{ "type": "ticket", "id": "T_xxx", "label": "实现工单" }]
}
```

存储：新表 `chat_blackboards`（`session_id UNIQUE` + `state_json` + `version` + `updated_at`）。理由：

- 黑板是**可累积、可回滚、可回溯**的独立实体，跟「每轮消息」生命周期不同（消息是流，黑板是快照）。
- 复用现有 ALTER/建表框架，刷新后能还原，符合系统「刷新还原气泡」的既有持久化习惯。

> 取舍：先不塞进 `chat_sessions` 大 JSON，独立表查询清晰、可版本化。

### ② 参与模型：并行盲答 → 回合制（轮内并行、轮间串行）

「Agent 能针对对话思考」的前提是**互见**。当前 `group/all` 并行盲答做不到。改成三阶段：

```
Round 1 发散：各 Agent 读「黑板 + 用户问题」，各自提提案（并行，写入 proposals）
Round 2 交锋：各 Agent 看到 Round 1 所有人的提案，批判/补充/修正（并行，写 open_questions）
Round 3 收敛：收敛器读整块黑板，压缩出最终结论（单 Agent，写 decisions）
```

- **轮内并行、轮间串行**：同一轮各 Agent 互不依赖可并行（快），轮与轮之间串行（保证能「看到上一轮」）。
- 收敛条件（三选一即停）：`decisions` 达成共识 / 无新增 `proposals` / 预算（轮数或 token）耗尽。
- 收敛器默认用 `OrchestratorAgent`（已有 persona，`chat.py:215`），可配置为 `ChatAssistant`。

> 这是 Multi-Agent Debate（MAD）范式的最小实现，比当前「三盲答」多出「交锋」和「收敛」两个真实协作环节。

### ③ 每 Agent 每轮三态输出

输入 = **对话转录 + 黑板快照 + persona**，输出拆成三层：

```jsonc
{
  "public_message":   "我认为应该用方案 B，因为...",       // 进群聊时间线
  "thought":          "TestAgent 担心并发，但本轮已确认预算...", // 进思考面板（复用 thinking_json）
  "blackboard_writes": [
    { "section": "proposals", "op": "add", "content": "方案 B" },
    { "section": "open_questions", "op": "add", "content": "..." }
  ]
}
```

- `public_message` → 落 `chat_messages`（role=assistant + speaker=agent_name + kind=utterance）。
- `thought` → 复用 `thinking_json` 列 + 现有思考面板/`/thinking-stream`，**无需新建 UI**。
- `blackboard_writes` → 更新 `chat_blackboards`，作为黑板事件（Phase 3 可 SSE 推前端）。

实现上用 LLM 的 structured output（`chat_json`）让 Agent 一次返回三态，避免多轮调用。

### ④ 存储增量：两列 + 一张表

`chat_messages` 加两列（走 `database.py` 迁移列表）：

- `speaker TEXT`——发言人（`DevAgent`/`user`/`OrchestratorAgent`/`converger` 等），替代现在塞 `action_data` 的做法。
- `kind TEXT DEFAULT 'message'`——消息类型：`utterance`（发言）/ `thought`（思考）/ `board_op`（黑板操作）/ `system`（收敛器小结）。

新表 `chat_blackboards` 如上。旧 `group/all` 的 `action_data={"type":"group_agent_reply"}` 逻辑保留兼容，新路径改用 `speaker` 列渲染 Agent 气泡。

### ⑤ 复用现有 Agent 基建，不自造轮子

| 能力 | 复用点 | 位置 |
|------|--------|------|
| 每轮上下文压缩 | `compact_history` | `base.py:546` |
| 思考预算控制 | `QueryEngine + Budget` | `base.py:282/295` |
| 流式思考推送 | `/thinking-stream` + `_THINKING_QUEUES` | `chat.py:22/125` |
| Agent persona | `_AGENT_CONFIG` | `chat.py:198` |
| 单轮 trace 关联 | `turn_id` 机制 | `database.py:149` |
| 消息持久化 | `_save_chat_message` | `chat.py:2813` |

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/projects/{pid}/chat/group/board` | 新黑板群聊入口：入参 message + session_id + rounds（默认 2）+ participating agents；流式返回各 Agent 发言/思考/黑板事件 |
| GET | `/api/projects/{pid}/chat/group/board/{session_id}` | 取黑板当前快照（分区 JSON + version） |
| GET | `/api/projects/{pid}/chat/group/board/{session_id}/events` | 黑板操作事件流（Phase 3，SSE） |

- 旧 `/group`、`/group/all` 保留，新端点独立，避免破坏现有群聊 UI。
- 响应沿用 SSE 事件协议（`turn_begin` / `agent_info` / 思考事件 / 消息事件），前端零协议改造成本。

## 前端

1. **群聊面板**：复用现有 Agent 气泡渲染（emoji + color），气泡来源从 `action_data.agent` 改为 `speaker` 列。
2. **黑板侧栏**（Phase 2）：聊天面板右侧浮层，分区展示 `proposals / open_questions / decisions / artifacts`，随黑板事件实时更新。
3. **思考面板**：复用现有思考面板，展示每 Agent 每轮 `thought`（已有分组展示能力）。
4. **收敛小结卡片**：收敛器产出（`kind=system`）渲染为置顶小结气泡。

## 建议 MVP 范围

1. **后端**：加 `speaker`/`kind` 两列 → 建 `chat_blackboards` 表 → 黑板分组对象 + 读写函数 → 回合制编排器（Round 1/2 + 收敛器）→ `/group/board` 流式端点。
2. **前端**：黑板群聊入口 + Agent 气泡按 `speaker` 渲染 + 思考面板展示每轮 thought。
3. **验证**：同一需求跑「旧 `/group/all` 并行盲答」vs「新 `/group/board` 回合制」对比，确认「互见 + 黑板」是否带来真实质量提升（这是本方案唯一需要证明的假设）。

## 待拍板 / 风险

1. **回合制延迟**：串行回合数 × 单 Agent 时延。默认 2 轮（发散 + 交锋）+ 收敛器，约 3 次串行 LLM 调用。若体验太慢，可退化为「1 轮发散 + 收敛器」。
2. **黑板写冲突**：轮内并行时多 Agent 同时写黑板。Phase 1 用「轮内只读上一轮快照、轮末合并写」避免锁；不做实时并发写。
3. **收敛器可靠性**：收敛器可能把 `proposals` 压坏（丢关键分歧）。需在 prompt 里强制「保留分歧、标注未决项」，并把 `open_questions` 原样带出。
4. **是否需要私有思考**：`thought` 若对用户可见，Agent 可能「表演式思考」；若不可见则失去可观测性。建议**对用户可见但折叠**，与现有思考面板定位一致（可观测优先）。
5. **结构化输出可靠性**：三态输出依赖 `chat_json` 稳定返回。需加降级：解析失败时把整段输出当 `public_message`，黑板写为空。

## 实现总结（2026-10-12 Phase 1 已实现）

### 后端

- `chat_messages` 加 `speaker` / `kind` 两列（`database.py` 迁移列表），建 `chat_blackboards` 表（session_id 主键 + state_json + version）。
- 黑板纯函数：`_empty_board` / `_load_blackboard` / `_save_blackboard`（upsert，version 自增）/ `_apply_board_writes`（去重 + 非法分区忽略）/ `_board_snapshot_text` / `_board_agent_prompt` / `_board_converger_prompt`（`api/chat.py`）。
- 新端点 `POST /group/board` + `_group_board_generator`：轮内并行、轮间串行（默认 2 轮 + 收敛器），`chat_json` 三态输出；JSON 解析失败时整段当公开发言降级。
- SSE 事件：`turn_begin / board_init / agent_thought / agent_message / board_update / converge / message_done / error`。
- 发言以 `action={"type":"group_agent_reply", ..., "thought":...}` 落库（刷新可走既有气泡还原路径），收敛小结以 `kind="system"` 落库。

### 前端

- 群聊 Tab 新增「🧠 黑板群聊（回合制辩论）」开关（`_groupBoardMode` + `toggleGroupBoardMode`）。
- 无 @mention 时若开关打开，走 `/group/board` 流式，否则保持原 `/group/all`。
- `_sendGroupBoardStreaming` 消费 SSE：黑板卡片 live 更新（`_renderBoardSummary`）、每 Agent 思考条目、发言气泡、收敛结论卡片。
- 新增 CSS：`.group-board-card / .group-board-thought / .group-board-converge / .board-sec / .board-item`。

### 实现偏差

- 方案写「前端气泡来源从 action_data.agent 改为 speaker 列」→ 已补：历史渲染路径同时支持 `group_agent_reply` action 和 `speaker` 列（`_AGENT_MENTIONS` 提供 emoji/color），speaker 无 action 也能还原气泡。
- 方案写「思考复用 thinking_json」→ 已补：`thought` 同时写 `action_data.thought`（直播）和 `thinking_json`（分组格式 `{round, reasoning, steps, events}`，刷新后走思考面板渲染）。
- 方案 API 表里的 GET 快照 / events 端点未做（Phase 3）。

- 独立脚本验证：迁移建列建表、黑板纯函数（去重/非法分区忽略/快照）、upsert SQL（version 自增 + 覆盖）。
- **端到端已跑通**（`backend/_e2e_group_board.py` 直接驱动 `_group_board_generator`，真实 DB + 真实 LLM CLI）：
  - 回合制「互见」生效：Round 2 各 Agent 明确引用/反驳他人提案（"采纳 TestAgent…""反对 DevAgent…"）。
  - 三态输出 + 黑板（v1 proposals/open_questions → v2 decisions/open_questions）+ 收敛器「共识/分歧/下一步」全链路正常。
  - 落库正确：`chat_messages` 8 条（user + 6 utterance + 1 system），speaker/kind/thinking_json 均正确；`chat_blackboards` version=2。
  - 期间修复 f-string 未转义 bug（`_board_agent_prompt` 里 `{facts,...}` → `{{facts,...}}`）。
