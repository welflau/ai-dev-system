# 会话-工单双向链接与背景追溯方案

**创建日期**: 2026-07-14  
**状态**: 待实现  
**背景**: 需求/工单由 AI 会话创建后，当前系统没有保存"来自哪条消息/哪个会话"的信息，也无法从工单界面导航回到创建时的对话位置，导致难以复原需求背景和决策上下文。

---

## 一、现状差距

| 数据点 | 现状 | 缺口 |
|---|---|---|
| `chat_messages.id` / `session_id` | ✅ 已存在 | — |
| 卡片 DOM 上的 `data-message-id` | ✅ 前端已有 | 没传给后端 |
| `requirements.source_message_id` | ❌ 无此字段 | 需 DB migration |
| `tickets.source_message_id` | ❌ 无此字段 | 需 DB migration |
| 工单 → 会话导航入口 | ❌ 不存在 | 需新增 |
| `chat_messages.action_result` 存 req/ticket id | ❌ 未存 | 需补充 |

### 已有基础

- `chat_messages` 表已有 `id`、`session_id`、`action_type`、`action_data`、`action_state`、`action_result` 字段
- 前端 DOM 卡片上已有 `data-message-id`，`doConfirmRequirement` 已调 `patchActionState(msgId, 'executed', {...})` 但没传 result 中的 `requirement_id`
- `locateInTicketFeed` 函数已实现"工单时间轴 → AI 对话"定位，可参考复用

## 二、双向绑定数据模型

```
chat_messages
  ├── id = "MSG-xxxx"
  ├── session_id = "SES-xxxx"
  ├── action_type = "confirm_requirement"
  ├── action_state = "executed"
  └── action_result = {"requirement_id": "REQ-xxxx", "title": "...", "at": "..."}  ← 补充

requirements
  ├── id = "REQ-xxxx"
  ├── source_message_id = "MSG-xxxx"   ← 新增
  └── source_session_id = "SES-xxxx"  ← 新增

tickets (直接工单)
  ├── id = "TK-xxxx"
  ├── source_message_id = "MSG-xxxx"  ← 新增
  └── source_session_id = "SES-xxxx"  ← 新增
```

### 3.2 后端：创建接口接收 source 字段

**`api/chat.py` — `confirm-create-requirement` 端点**

```python
class ConfirmRequirementRequest(BaseModel):
    title: str
    description: str = ""
    priority: str = "medium"
    images: list = []
    paused: bool = False
    source_message_id: Optional[str] = None   # ← 新增
    source_session_id: Optional[str] = None   # ← 新增
```

创建需求时将这两个字段写入 `requirements` 表，并在 `action_result` 里补充 `requirement_id`：

```python
# patchActionState 补充 requirement_id
await db.update("chat_messages",
    {"action_result": json.dumps({"requirement_id": req_id, "title": title, "at": now_iso()})},
    "id = ?", (source_message_id,))
```

**`api/tickets.py` — `create-direct` 端点**（`DirectTicketCreate` 模型）

```python
class DirectTicketCreate(BaseModel):
```

### 3.3 前端：传 source 字段

`doConfirmRequirement` 和 `doConfirmDirectTicket` 均已有 `card.dataset.messageId`，补充传参：

```javascript
// doConfirmRequirement
const msgId = card.dataset.messageId || '';
const sessionId = _currentChatSessionId || '';
const result = await api(`/projects/${currentProjectId}/chat/confirm-create-requirement`, {
    method: 'POST',
    body: { title, description, priority, images,
            source_message_id: msgId, source_session_id: sessionId },  // ← 新增
});

// patchActionState 补充 requirement_id（已调，补充字段）
if (msgId) patchActionState(msgId, 'executed', {
    title,
    requirement_id: result.requirement_id,   // ← 新增
    at: new Date().toISOString()
});
```

### 3.4 工单抽屉显示来源区块

在 `openTicketDrawer` 渲染的基础信息区下方，若 `ticket.source_message_id` 存在则显示：

```html
<div class="drawer-section source-section">
  <h4>🗨 创建来源</h4>
  <div class="source-message-preview">
    <span class="source-time">来自会话「2026-07-13 20:15」</span>
    <span class="source-snippet">「创建一个空地图，默认的地图…」</span>
```

需要后端接口 `GET /projects/{pid}/chat/message/{message_id}` 返回消息摘要（或直接从 ticket 详情 API 里 JOIN 带出来）。

### 3.5 导航函数

```javascript
async function locateSourceMessage(sessionId, messageId) {
    // 1. 确保聊天面板已打开
    if (!chatPanelOpen) toggleChatPanel();
    // 2. 切换到对应 session
    if (sessionId && sessionId !== _currentChatSessionId) {
        await switchChatSession(sessionId);
    }
    // 3. 等待渲染后滚动到目标消息并高亮
    setTimeout(() => {
        const el = document.getElementById(`msg-${messageId}`)
                || document.querySelector(`[data-msg-id="${messageId}"]`);
        if (!el) return;
        el.scrollIntoView({ behavior: 'smooth', block: 'center' });
        el.classList.add('source-msg-highlight');
        setTimeout(() => el.classList.remove('source-msg-highlight'), 2000);
    }, 400);
}
```

CSS 高亮动画：
```css
.source-msg-highlight {
    animation: source-pulse 0.5s ease 3;
    border-radius: 8px;
}
@keyframes source-pulse {
    0%,100% { box-shadow: 0 0 0 0 rgba(99,102,241,0.4); }
    50%      { box-shadow: 0 0 0 8px rgba(99,102,241,0.4); }
}
```

## 四、可选：内容整合（上下文摘要写入工单描述）

在确认创建时，自动提取当前会话最近 N 条消息摘要，追加到工单/需求描述末尾：

```
[用户自定义描述]

── 创建背景（来自会话摘要，2026-07-13 20:15）──
用户：「创建默认地图，包含基础光照和玩家出生点…」
AI 分析：需要在 UE 项目中创建一个空关卡作为默认起始地图，
         包含方向光、天空球、PlayerStart Actor。
```

**实现方式**：前端在 `doConfirmRequirement` 时读取 `chatHistory`（已有全局变量），取最近 3-5 条，拼成 context_summary 字符串传给后端，后端 append 到 description。

**注意**：这个特性可能引入冗余信息，建议作为 opt-in（默认关闭，可在设置里开启）。
