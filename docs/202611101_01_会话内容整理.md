### 核心主题：将沟通内容（含AI对话）工单化的可行性分析

#### 一、通用会话工单化（人类对话）

- **核心理念**：把聊天记录中的关键信息（任务、决策、问题）自动或半自动转化为可追踪的工单，解决信息散落、难以执行的问题。
- **优点**：减少手动录入，提升协作效率，尤其适用于客服、项目管理。
- **挑战**：需智能过滤非任务性闲聊；过度自动化会导致工单泛滥，建议采用“自动建议+人工确认”模式。

#### 二、PRD讨论工单化

- **适用场景**：产品需求文档评审过程中的每条修改意见、需求变更均视为工单。
- **优势**：每个改动有明确负责人、状态和时间戳，避免遗忘，利于版本管理和审批。
- **注意点**：PRD讨论发散性强，不宜逐句拆解，建议按议题或段落聚合，保持讨论流畅性。

#### 三、时间回放轴

- **功能描述**：工单的所有状态变更、评论、附件更新按时间顺序排列，支持拖动回看任意时刻快照。
- **价值**：便于项目复盘、新人学习、审计溯源。
- **实现要点**：需记录每次变更的差异（diff），并处理并发冲突标记。

#### 四、AI会话工单化的特殊考量

- **适合的原因**：
  - AI对话目标明确、信息密度高，可复用为知识库条目。
  - 成功案例（如生成的代码、分析报告）可沉淀为“最佳实践”。
  - 满足合规场景的审计与溯源需求。
- **不适合的原因**：
  - 大量试错性、发散性内容会造成工单噪音，需用户手动筛选。
  - 涉及隐私和权限风险，需精细控制可见范围。
  - AI无法承担任务责任人角色，此类工单更适合作为“知识型工单”（只记录不流转）。
- **建议方案**：为用户提供“星标”或“导出为工单”按钮，由用户自主决定哪些AI对话内容值得沉淀。

#### 五、整体结论

- 这套设计构成了一个闭环：**会话→工单→时间轴演变→复盘→优化下次会话**。
- 关键在于平衡“结构化”与“灵活性”：过度工单化可能抑制创造力，应允许用户自定义哪些对话需要进入工单体系。
- 对于AI对话，**适合但需克制**，优先将明确产出型对话工单化，探索性对话保持原样。

基于之前的讨论，我为你设计了一套**面向企业与AI协作场景的工单化系统**的详细方案。该方案将人类会话、PRD讨论、AI对话统一纳入工单体系，并配备时间回放轴，兼顾灵活性与结构化。

## 二、工单模型设计

### 2.1 基础字段（所有工单通用）

| 字段                        | 说明                                                         |
| --------------------------- | ------------------------------------------------------------ |
| `id`                        | 唯一标识                                                     |
| `title`                     | 标题（自动生成或用户填写）                                   |
| `type`                      | 枚举值：`task` / `bug` / `requirement` / `knowledge` / `decision` / `prd_change` |
| `source`                    | 来源：`chat` / `prd_doc` / `ai_session` / `manual`           |
| `creator`                   | 创建者（人或AI标识）                                         |
| `assignee`                  | 负责人（可为空，知识型工单无）                               |
| `status`                    | 状态机（见下文）                                             |
| `priority`                  | P0~P3                                                        |
| `tags`                      | 自定义标签                                                   |
| `related_objects`           | 关联对象列表（如关联的会话ID、文档ID、AI对话ID）             |
| `created_at` / `updated_at` | 时间戳                                                       |
| `snapshot`                  | 当前快照（JSON，包含完整内容）                               |

### 2.2 状态机（按类型定制）

**任务型工单**：`待认领 → 进行中 → 待验收 → 已完成 → 关闭`

**Bug型工单**：`待确认 → 已复现 → 修复中 → 待验证 → 已验证 → 关闭`

**需求变更型**：`提议 → 评审中 → 已批准/已拒绝 → 实施中 → 已上线`

**知识型工单**：`草稿 → 已发布 → 过期` （无需流转，创建即终态）

**决策型工单**：`待讨论 → 已决议 → 归档`

### 2.3 特殊字段：Diff记录

每个工单维护一个事件列表 `events[]`，每个事件包含：

```json
{
  "timestamp": "2026-11-01T10:00:00Z",
  "actor": "user_123",
  "action": "update_field", // create / update_field / add_comment / change_status / attach_file
  "field": "description",
  "old_value": "...",
  "new_value": "...",
  "context": "来自AI对话#456的建议"
}
```

## 三、会话转工单流程

### 3.1 触发方式

- **自动建议**：系统实时扫描群聊/私聊消息，当检测到以下模式时弹出“建议创建工单”按钮：
  - 包含“请跟进”、“待处理”、“谁负责”等关键词
  - 出现明确的待办事项（如“下周前完成XX”）
  - 多人@某人并要求行动
- **手动创建**：用户在任何消息上右键/长按，选择“创建工单”
- **批量创建**：在群聊历史记录中框选多条消息，一键生成多个关联工单

### 3.2 智能提取策略

利用NLP模型从选中文本中提取：

- **标题**：取首句或最高TF-IDF句子
- **描述**：保留原文，并自动添加“源消息链接”
- **负责人**：通过实体识别提取人名或角色（如“@张三”）
- **截止时间**：识别日期短语（“明天下午3点前”）
- **优先级**：根据语气词（“紧急”、“尽快”）自动判断

### 3.3 人工确认环节

- 系统弹出预览卡片，用户可编辑字段后再提交
- 提供“忽略此建议”选项，并可设置“不再为此类消息建议”

## 四、PRD讨论工单化

### 4.1 与文档编辑器深度集成

在PRD文档（如飞书文档、语雀）右侧嵌入讨论面板，每条评论均可“转工单”：

- **按段落/章节聚合**：用户选中一段文字，点击“就此发起需求变更工单”
- **自动关联版本**：工单创建时记录当前文档版本号（或git commit hash）
- **状态联动**：当工单状态变为“已批准”时，自动在文档对应位置打上“已确认”标记

### 4.2 典型场景示例

```
文档段落：“登录模块需支持人脸识别”
评论A：“建议改用微信原生刷脸SDK” → 创建工单【需求变更】替换人脸识别SDK
评论B：“这个改动影响Android端吗？” → 创建子工单【调研】评估Android兼容性
```

### 4.3 审批流配置

- 每个PRD工单可绑定审批人（产品负责人、技术负责人）
- 状态流转自动通知相关方
- 审批通过后，工单内容自动更新到PRD文档（需用户确认）

## 五、AI会话工单化

### 5.1 用户打标机制

在AI对话界面增加“⭐收藏并生成工单”按钮，点击后弹出表单：

- 自动填充：对话摘要（由AI生成）、关键结论、引用代码/图表
- 用户补充：工单标题、类型（知识/决策/任务）、可见范围
- 支持选择“仅自己可见”或“分享至团队空间”

### 5.2 知识型工单的特殊处理

- **无负责人**：状态只有“草稿”和“已发布”，无需流转
- **可嵌套**：一个AI工单可引用另一个AI工单（如“基于工单#123的方案优化”）
- **搜索权重高**：在团队知识库中优先显示，支持全文检索
- **版本更新**：如果用户再次向AI提出类似问题并获得改进答案，可更新原工单内容（保留历史版本）

### 5.3 隐私保护

- 默认AI会话工单仅创建者可见
- 发布到团队时，系统自动脱敏（如隐藏邮箱、手机号、API Key）
- 提供“导出为匿名版”选项

## 六、时间回放轴

### 6.1 事件记录

每个工单的所有变更都作为独立事件存储，包括：

- 创建、字段修改、状态变更、评论、附件上传、关联变更
- 来源标记（如“来自AI建议”、“来自PRD评论”）

### 6.2 可视化组件

在工单详情页顶部提供“回放”按钮，点击后进入全屏时间轴视图：

- **滑块控制**：拖动时间滑块，工单内容实时回滚到对应时刻
- **差异高亮**：新增内容绿色背景，删除内容红色删除线
- **事件标记**：时间轴上用不同颜色圆点表示不同类型事件（蓝色=状态变更，黄色=评论，紫色=AI介入）
- **速度控制**：支持1x/2x/4x倍速自动播放

### 6.3 高级功能

- **分支回放**：如果工单曾经被分叉（如同时有两个备选方案），时间轴可展示分支合并过程
- **多工单联合回放**：选择一组关联工单，查看它们之间的交互时间线（如需求变更导致Bug工单创建）
- **导出回放视频**：生成MP4文件用于复盘汇报

## 七、权限与隐私控制

| 角色         | 权限                                                        |
| ------------ | ----------------------------------------------------------- |
| 普通成员     | 创建自己的工单，查看公开工单，对自己创建的工单进行编辑/删除 |
| 团队管理员   | 管理所有工单，调整权限，设置审批流模板                      |
| 系统管理员   | 全局配置，审计日志查看，数据导出                            |
| AI会话创建者 | 决定是否将AI对话转为工单，以及可见范围                      |

**数据隔离**：跨团队的工单不可互相访问，除非显式共享。
