# 会话临时素材管理方案

日期：2026-11-01  
状态：第一期落地  
关联：`docs/20261029_01_全局页面左侧导航与全局作用域方案.md`（四维作用域）  
对照：`docs/20261015_01` ArtifactStore、`docs/20260430_01` 美术资产库

---

## 1. 问题

会话会留下图、文档、CLI 写出的文件，但它们只挂在气泡或磁盘目录上：没有登记、没有过期、没有提升。删除会话只删 DB 行，文件永驻。

现有正式出口是四条互不相通的管道：

| 出口 | 落点 | 绑定 |
|---|---|---|
| 工单产物 | `ArtifactStore` → `<repo>/artifacts/{req}/{ticket}/{kind}/` | 必须登记 `kinds.yaml` |
| 美术库 | `art_assets` + `G_ArtRes` | 写入一律 `project_scope='global'` |
| 知识 | `/save-to-knowledge` → `.ads/wiki/`，与 `knowledge_index` 仍是两套 | 项目/全局 |
| 仓库文件 | `save-to-repo` / `generate_document` → `docs/*.md` | git |

会话草稿散落在 `chat_images/{project_id}/`、`generated-images/`、`chat_images/ue_screenshots/`。10-29 提过「global / project / ticket / session 四维 + promote」，没有模型也没有代码。

## 2. 核心判断

**会话素材是第五层，不是第五种工单，也不是第四种 kind。**

| 层 | 职责 | 生命周期 |
|---|---|---|
| 会话素材 | 探索期中间文件，跟会话走 | TTL / 用户钉住 / 提升后脱离 TTL |
| 工单产物 | SOP 链可消费的正式产出 | 跟工单，不走会话 GC |
| 项目/全局资产 | 可复用美术 | 进 `G_ArtRes` 才算 |
| 知识 | 可复用文字经验 | wiki / index |
| 仓库文件 | 进 git 的文档/代码 | 版本由 git 管 |

不把会话文件塞进 ArtifactStore：`put()` 强制 kind、路径绑 ticket、会污染 skill 拓扑。不把会话图直接写入 `art_assets`（`confirm-generate-image` 过去就是这样漏进全局墙）。提升时再写入对应终态。

「素材」：**会话过程中产生或附上的、尚未进入终态出口的文件。**

## 3. 数据模型

表 `session_materials`：

- `id` `SM-…`
- `session_id` → `chat_sessions.id`（必填）
- `project_id` 可空（全局会话为 NULL）
- `message_id` 可空
- `name` / `mime` / `size_bytes` / `rel_path`（相对 `BASE_DIR`）
- `public_url` 可空（已有静态挂载时沿用）
- `origin`：`upload` | `import` | `generated` | `export` | `tool`
- `status`：`scratch` | `pinned` | `promoted` | `deleted`
- `expires_at`（scratch 才有，辅助；GC 以会话 `last_active_at` 为准）
- `promoted_sink` / `promoted_id`
- `metadata` JSON
- `created_at` / `updated_at`

磁盘：

- 新写入：`{DATA_DIR}/session_materials/{session_id}/{sm_id}_{safe_name}`
- 旧文件：`chat_images/`、`generated-images/` **迁入登记、不改物理路径**
- 均不进项目 git

四维作用域是视图，不是 `art_assets.project_scope` 上的四值枚举。session 用本表；ticket 提升后走 artifacts / 工单描述；project / global 提升进 `art_assets` 时写上真实 `project_scope`。

## 4. 捕获与提升

统一 `MaterialRegistry.attach(...)`，在现有落盘点挂钩。捕获可以自动；进正式库必须用户点或建单时勾选。

| 来源 | 挂钩 | 第一期 |
|---|---|---|
| `_save_images` | 消息落库后按 URL 登记 | `origin=upload` |
| 外部会话导入 | 导入循环里按 URL 登记 | `origin=import` |
| `confirm-generate-image` | 完成后登记，**禁止直接入全局 art_assets** | `origin=generated` |
| `generate_document` / `save-to-repo` | 已是 repo 终态 | 登记为 `promoted` + sink=repo |
| MCP/CLI `Write` | `_session_file_changes` | 第二期 |

提升出口：挂到工单（描述 Markdown + 可选 ArtifactStore）/ 美术库 / 知识 / 仓库 docs / 钉住。提升默认复制不移动。

建单卡「附带本会话素材」：默认勾选 `origin=upload` 与 `status=pinned`，不默认勾选全部生成图。

## 5. 生命周期

对齐 Checkpoint 的 TTL + keep-N，另开服务：

- scratch：会话 `last_active_at` 起 14 天；每会话最多 50 条 scratch，超出删最旧
- pinned：不限期，不占 scratch 额度
- promoted：文件可留副本
- 删会话：删该会话 scratch / pinned 文件与行；promoted 只删行
- 孤儿扫描与 `/api/local-file` 收口：第二 / 三期

## 6. 明确不做

- 不扩展 `kinds.yaml` 表达会话草稿
- 不把 `art_assets.project_scope` 扩成四值枚举
- 不做 NLP 自动判断「这张图有价值」
- 第一期不做跨会话素材搜索
- 不把黑板 `artifacts[]`、Memory、Checkpoint 并进这张表

## 7. 落地顺序

1. 本方案 + 表 + `MaterialRegistry`
2. 挂钩现有落盘点
3. 列表 / preview / pin / promote API + TTL GC
4. 会话侧栏 + 气泡入口 + 建单卡勾选

第二期：skill/CLI 输出目录切到 session 目录；`Write` 可选登记；`art_assets` 按 scope 过滤；`/api/local-file` 收口。  
第三期：删项目级联、孤儿 quarantine、项目级未提升草稿浏览。
