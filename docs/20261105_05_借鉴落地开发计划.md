## 二、第 1 项：路径纠偏（最简）

### 2.1 目标

堵住 `_ue_import_asset_impl` 的本地文件路径越权/注入口，对标 MagicAI 的 `fix_output_path()` + `ensure_within_project_dir()`（file_tools.py:628-679）。

### 2.2 现状（`ue_mcp_server.py::_ue_import_asset_impl`，266-362 行）

| 校验 | 状态 | 位置 |
|---|---|---|
| UE 内路径白名单（`/Game/` 前缀） | ✅ 已有 | :308 |
| 本地文件存在校验（`.exists()`） | ✅ 已有 | :299 |
| **本地路径归一化（`resolve()`）** | ❌ 缺 | — |
| **本地路径越权拦截（白名单根目录）** | ❌ 缺 | — |
| **路径转义（防注入 UE Python 代码）** | ⚠️ 半缺 | :318 f-string 拼接 |

**风险点**：当 `ART_ASSETS_LOCAL_PATH` 未配置时，`file_path` 直接当绝对路径用（:287 `elif rel_path: abs_path = rel_path`），无目录约束；`abs_path` 又直接 f-string 拼进 UE Python 代码（:318）。

### 2.3 改动方案

在第 2 步（确定资产名）后、第 3 步（验证 UE 路径）前插入：

```python
from pathlib import Path as _P
from config import DATA_DIR

_p = _P(abs_path).resolve()                      # 归一化
_allowed = []
if settings.ART_ASSETS_LOCAL_PATH:
    _allowed.append(_P(settings.ART_ASSETS_LOCAL_PATH).resolve())
_allowed.append((_P(DATA_DIR) / "session_materials").resolve())

if not any(str(_p).startswith(str(r)) for r in _allowed):
    return {"success": False, "message": "文件路径越出资产库/会话素材范围，拒绝导入"}
abs_path = str(_p)
```

### 2.4 风险

低。纯防御性，不动现有正常路径。

## 三、第 2 项：AIGC 接入 ArtistAgent（方案 C）

### 3.1 目标

补全美术 fallback 链：`搜库 → AIGC → 占位图 → 人工`，对标 MagicAI 的四级优先级（但用代码强制而非 prompt 约定）。

### 3.2 现状（`generate_assets.py`）

现有 fallback 链（`_resolve_one`，206 行）：

```
1. _search_library() → sourced        ✅ 已有（代码强制优先级）
2. [缺失] AIGC 生图 → generated       ❌ 待接入
3. _make_placeholder() → placeholder  ✅ 已有
4. manual_required / not_found        ✅ 已有
```

**关键矛盾**：`generate_assets.py:9-11` 注释写"系统当前没有接入图像模型"，但 `image_processor.py` 早已接入 LightAI（`request_image` 默认 `requester="ArtAgent"`）。

### 3.3 改动方案

1. **`_resolve_one` 签名**加 `project_id` / `ticket_id` / `allow_aigc` 参数。
2. **`run()`** 里读 `sop_cfg.get("use_aigc", False)`，从 context 取 project_id/ticket_id。
3. **未命中本地库后插入 AIGC 分支**（约 :222 之后）——**异步投递**：

```python
if allow_aigc and not needs_frames:
    from image_processor import request_image
    tag = await request_image(
        prompt=f"{aid} {desc}",
        project_id=project_id, ticket_id=ticket_id,
        requester="ArtAgent",
    )
    # 占位图照出，记录 aigc_tag；生图完成后由
    # image_processor 的 callback_doc/callback_tag + _replace_placeholder 回填
```

4. **`asset_gen.yaml`** 加 `use_aigc: false`（默认关，生图有成本）。

### 3.4 关键决策

- **异步投递而非同步等待**：生图几十秒/张，同步会拖垮工单流水线。
- **占位图与 AIGC 并存**：投递 AIGC 后仍生成占位图作为即刻可用 fallback，生图完成后回填。

### 3.5 风险（唯一不确定点）

`_replace_placeholder` 回填机制是否适配 asset_manifest.yaml 场景——**实施前需先读 image_processor.py 的 `_replace_placeholder`（约 399 行调用处）确认**。

## 四、第 3 项：请求分类前置层（第二批，需设计）

### 4.1 现状

ADS 已有雏形：`confirm_direct_ticket` 的 `start_from` 参数（`pending` / `architecture_done` / `development_in_progress`）能"跳过前置阶段"，但**人工指定，非自动分类**。

### 4.2 方向

在 `compose_sop` 前加自动分类（大改/小改/问答）：
- **大改** → 完整 SOP（现状）
- **小改**（1-2 模块）→ `start_from=development_in_progress`，只派 DevAgent + TestAgent
- **问答** → 不走工单流水线

映射 MagicAI 的"MODIFY 模式关键词评分只注册必要 Agent"（agent_session.py:203-231）。

### 4.3 风险

中高。涉及编排核心，分类规则误判会跳过必要阶段，需保守设计（**判不准就走完整流程**，宁可多跑不欠做）。
