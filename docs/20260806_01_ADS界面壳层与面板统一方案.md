# ADS 界面壳层与面板统一方案

日期：2026-08-06  
状态：阶段 1–3 已落地（壳层 Grid + 右栏合并 + 一键分屏 + C 工作区 md/diff Tab）；阶段 4（视觉令牌化）可渐进  
关联讨论：侧栏收起、工单关闭留白、对标 Cursor 面板纪律（非抄编辑器）  
关联现状代码：`frontend/index.html` / `frontend/styles.css` / `frontend/app.js`  
  （`project-layout`、`sidebar`、`content-dock-wrapper`、`chat-panel`、`ticketDrawer`、`log-panel`）

---

## 一、背景与结论

### 1.1 现状问题

ADS 项目页当前是多套独立面板拼装，缺少统一壳层（Shell）：

| 面板 | 现状实现 | 典型问题 |
|---|---|---|
| 左侧导航 | `.sidebar` 菜单树 | 可收起能力刚补；与内容区无统一 API |
| 主内容 | `.content-area` + 多 Tab 页 | 看板等未作为「工作区文档 Tab」管理 |
| 工单详情 | `#ticketDrawer` fixed + Dock `padding-right` | 关闭后内联 padding 残留 → **主区留白** |
| AI 对话 | `#chatPanel` fixed + `body.chat-open` `margin-right` | 与 Drawer 双预留，易叠出空白带 |
| 实时日志 | `#logPanel` 底栏常驻 | 空看板时仍占一半高度，观感割裂 |

根因不是「缺一个按钮」，而是：

1. **没有单一布局公式**（多套 `margin` / `padding` / 内联 style 各自腾位）
2. **工单详情与 AI 对话是两套右栏**，同时打开即「双右栏挤兑」
3. **关闭面板 ≠ 主区回弹**（占位状态与可见性不同步）
4. **md / diff 无统一落点**，后续若再开模态/第四列会重复上述问题

### 1.2 结论（产品决策）

1. ADS 是**编排台 / 指挥台**，不是 IDE；学 Cursor 的是**面板纪律**，不是 Activity Bar + 编辑器全家桶。
2. **左侧不拆成 Activity Bar（A）+ Sidebar（B）**：继续**单侧栏**，与现网一致，避免多点一次。
3. 统一壳层为四区：`侧栏 | 主舞台 C | 右侧工作台 D | 底栏 E`。
4. **工单详情与 AI 对话合并到右侧 D**（Tab + 一键分屏），禁止再并行 Dock 独立 Drawer + 独立 Chat 双占位。
5. **md / diff 只落在主舞台 C**（工作区 Tab / C 内分屏）。
6. **任意面板显隐只改 CSS Grid（或等价 flex）行列**；主舞台 `1fr` 永远吃剩余空间。  
   **禁止**再用 `margin-right` / `padding-right` 给 `position: fixed` 浮层腾位作为主路径。

## 二、目标与非目标

### 2.1 目标

1. 关闭任一右/底面板后，主舞台**立即**铺满剩余空间，无空白带。
2. 工单操作与 AI 对话可在右侧 **一键分屏**并排，也可 Tab 切换。
3. 打开 md、diff 时有唯一、可预期的落点（主舞台 C）。
4. 所有业务面板标题栏视觉与控件一致，形成统一「窗口」语言。
5. 前端以 `shell.*`（或同等）单一 API 管理面板状态，可持久化、可测试。

### 2.2 非目标

- 不实现完整 IDE（多编辑器组、全局拖出 OS 级浮动窗、调试器协议等）。
- 不强制左侧拆 Activity Bar。
- 不在本方案重做看板信息架构或 SOP 编排逻辑。
- 不要求像素级复刻 Cursor 皮肤（图标可渐进从 emoji 迁到线性图标）。

## 三、壳层总览

### 3.1 区域定义

```
┌──────────────┬────────────────────────────┬──────────────────┐
│ S 侧栏       │ C 主舞台（唯一弹性主区）     │ D 右侧工作台     │
│ 导航 / 项目  │ 看板·列表·图·仓库·md·diff   │ 工单 / AI 对话   │
│ （可整收）   │ 工作区 Tabs + 可选内分屏     │ Tab 或一键分屏   │
│              ├────────────────────────────┤                  │
│              │ E 底栏 Panel（日志等，可收） │                  │
└──────────────┴────────────────────────────┴──────────────────┘
```

| 代号 | 名称 | 职责 | 关闭后行为 |
|---|---|---|---|
| **S** | 侧栏 | 一级+二级导航（现有菜单合成一区） | 收起为窄轨或 0 宽，C+D 变宽 |
| **C** | 主舞台 | 唯一主内容与文档/diff 阅读区 | 不可「关掉主舞台」；可关内部 Tab |
| **D** | 右侧工作台 | 工单详情 + AI 对话 | 整栏关闭 → C（与 E）吃满右侧 |
| **E** | 底栏 | 实时日志等过程输出 | 收起到标题条高度或完全隐藏 |

### 3.2 硬性布局规则（开发约束）

**R1. 单一布局宿主**  
项目页根布局必须是一层 Grid（推荐）或等价结构，例如：

```text
grid-template-columns: [sidebar] var(--sidebar-w) [main] 1fr [right] var(--right-w, 0px);
grid-template-rows:    [center] 1fr [bottom] var(--bottom-h, auto);
```

- `var(--right-w)` 在 D 关闭时为 `0`（或列直接移除）。
- `var(--bottom-h)` 在 E 收起时为标题条高度（如 28–36px）或 `0`。

**R2. 禁止双预留**  
废弃作为主路径的：

- `body.chat-open .project-layout { margin-right: … }`
- `body.has-docked-drawer .main-container { padding-right: … }`
- 拖拽时写入 `.main-container` 的**内联** `paddingRight`（若过渡期保留，关闭时必须清除）

**R3. 面板可见性 = 占位**  
`display` / 列宽 / 行高与「是否占布局空间」必须同步。不允许「面板已不可见但仍占 500px」。

**R4. C 永远是 `1fr`**  
任何打开 D/E/分屏，只压缩 C 的可用宽高，不得在 C 旁再留无名空白列。

**R5. 浮层仅用于模态**  
确认框、新建项目、系统设置等可用 overlay。  
**工单详情、AI 对话、日志、md、diff 不得作为与主布局脱节的第三套 Dock 浮层长期方案。**

## 四、各区详细规格

### 4.1 S — 侧栏（保持单区）

**决策**：不拆 Activity Bar + Sidebar。理由：ADS 侧栏模式单一（点菜单 → 换主区），拆两层增加一次点击，无收益。

**行为**：

- 顶部：项目名 + **收起/展开**按钮（Cursor 风格侧栏图标，已部分落地）。
- 收起：窄轨（约 44px）仅保留展开按钮；或宽度 0 + 主区边缘露出展开钮（二选一，实施时定一种并写死）。
- 展开：现有导航树（工单子菜单、设置子菜单、底部提交需求等）保持信息架构，除非另开导航改版任务。
- 状态：`localStorage` 键建议 `ads.shell.sidebarCollapsed`。

**约束**：

- 侧栏只负责导航，**不承载**长文 md、diff、完整 AI 会话、完整工单详情。

### 4.2 C — 主舞台（工作区）

**定位**：看板 / 列表 / 关系图 / 仓库 / 统计等「页面」与 **md / 代码 / diff** 同级，均为工作区 Tab。

**Tab 模型（逻辑）**：

| Tab 类型 | 示例标题 | 内容 |
|---|---|---|
| `page` | 看板、Roadmap、BUG… | 现有 `tab-content` |
| `file` | `README.md`、`Foo.cpp` | 预览 / 源码 |
| `diff` | `变更 · TK-xxx` 或 `a.cpp ↔ b.cpp` | Diff Viewer |
| `split` | （可选）C 内左右/上下分屏容器 | 同时看 md+diff |

**打开规则**：

| 入口 | 行为 |
|---|---|
| 侧栏点「看板」等 | 激活或打开对应 `page` Tab |
| 仓库树点 `.md` / 源码 | C 打开 `file` Tab（md 默认预览） |
| 工单「产出文件」/ OpenSpec 文档 | C 打开 `file`；若有变更可同时开 `diff` 或 C 内分屏 |
| AI「N files changed」点文件 | C 打开对应 `diff` 或 `file` |
| 看板点卡片 | **不**用详情替换整个 C；C 保持看板，**打开 D** |

**C 内分屏（文档场景）**：

- 用于 md ∥ diff 对照，**不是**工单∥AI（工单∥AI 在 D 内分屏）。
- 默认实现可后置；但 API 预留 `shell.openInMain({ type, id, split?: 'beside' })`。

**约束**：

- 禁止用全屏模态作为 md/diff 的主阅读路径。
- 禁止把长 diff 塞进 D 工单栏当主视图（D 可放文件列表，点击仍在 C 打开）。

### 4.3 D — 右侧工作台（工单 + AI）

#### 4.3.1 信息架构

D 是**唯一右侧业务栏**，内含：

1. **工单**面板：现 `#ticketDrawer` 的详情、三层状态、时间轴、评论、操作、产出入口等。
2. **对话**面板：现 `#chatPanel` 的全局/工单/群组等模式（工单上下文时默认绑定当前工单）。

#### 4.3.2 两种布局模式

| 模式 | 形态 | 何时用 |
|---|---|---|
| **Tab（默认）** | 同一时间只显示工单或对话 | 省宽度；日常查看 |
| **一键分屏** | `工单 \| 对话` 左右并排，中间拖条 | 边看工单边问 AI |

**一键分屏（已定交互）**：

- D 标题栏（或 Tab 栏）提供按钮 **「⊞ 分屏」**。
- 点击后：D 内部分为左右两半，各有自己的标题栏；中间 `col-resize` 分隔条。
- 再点「合并」或等效操作：回到 Tab 模式，记住上次激活的 Tab。
- **不**要求用户拖出两个 OS/浏览器级窗口。
- **不**用「页面级再 Dock 一个 Chat」实现并排。

分屏比例：默认 50/50；可拖；建议 `localStorage`：`ads.shell.rightSplitRatio`。

#### 4.3.3 打开 / 关闭语义

| 用户动作 | 系统行为 |
|---|---|
| 点击看板/列表工单卡 | `shell.openRight({ tab: 'ticket', ticketId })`；若 D 已关闭则打开 |
| 需要 AI | 切到对话 Tab，或点「分屏」 | 
| 关闭 D（工作台 ×） | 整栏关闭，列宽归 0，C 回弹 |
| 分屏时关「对话」半边 | 退出分屏，保留工单半边（或回到 Tab-工单） |
| 分屏时关「工单」半边 | 退出分屏，保留对话（或回到 Tab-对话） |

#### 4.3.4 迁移约束（对现有代码）

实施完成后：

- `#ticketDrawer` 的 Dock / `has-docked-drawer` / overlay 主路径废弃（或仅作过渡期兼容开关，默认关）。
- `#chatPanel` 不再 `position: fixed; right: 0` 独立占 `margin-right`；改为 Grid 第 3 列（或 D 容器内的子视图）。
- 允许短期「视觉搬家、API 未齐」的过渡，但**不得**长期保留双占位。

### 4.4 E — 底栏（日志）

- 默认：**收起**为单行标题条（约 28–36px），显示「实时日志」+ 未读/error 角标。
- 展开：可拖高度；上限不超过主区一定比例（建议 ≤ 45vh）。
- 有新 error/warn 时可角标闪烁，**不强制**自动撑满半屏。
- 状态：`ads.shell.bottomCollapsed`、`ads.shell.bottomHeight`。

**约束**：E 从属于 C 列下方（或跨越 C+D 的底行——实施二选一，推荐**仅在 C 列下方**，避免分屏时日志压住 D 操作区）。若跨越 C+D，须在验收中确认 D 输入框不被遮挡。

## 五、标题栏规范（每个面板一条）

### 5.1 原则

- **C / D（含分屏每一半）/ E** 必须有统一高度的标题栏（建议 36–40px）。
- S 可简化（项目名 + 收起），不强制与 D 完全同一套按钮，但间距/字号应对齐设计令牌。
- 分屏后：**每一半各自一条标题栏**（工单一条、对话一条）。

### 5.2 标题栏内容槽位（从左到右）

1. **标题**（文本，ellipsis）
2. **可选 Tab 或工具组**
3. **右侧动作**：按需显示  
   - 分屏 ⊞ / 合并  
   - 最大化（可选，后置）  
   - 收起（E）  
   - 关闭 ×  

### 5.3 各面板默认动作

| 面板 | 标题示例 | 必备动作 |
|---|---|---|
| C | 当前 Tab 名 | Tab 条；关闭文件类 Tab |
| D 整体（Tab 模式） | 当前 Tab：工单标题或「对话」 | ⊞ 分屏、× 关闭工作台 |
| D 工单半边 | 工单短标题 / ID | × 关闭该半边 |
| D 对话半边 | 「对话」或会话名 | × 关闭该半边 |
| E | 实时日志 | 收起/展开、清空（可选） |

### 5.4 视觉约束

- 同一套：背景、底边框、按钮尺寸（建议 28×28 点击热区）、hover。
- 主导航逐步减少「靠 emoji 区分模块」的依赖；emoji 可用于状态角标。本条可渐进，不阻塞壳层改造。

## 六、关键用户场景排版（验收用例）

### 6.1 只看看板

`S | C(看板) | （D 关）`  
E 默认收起。

### 6.2 打开工单（最常见）

`S | C(看板) | D(工单 Tab)`  

- C **保持**看板，不整页被详情替换。  
- 关闭 D → 回到 6.1，C 立刻变宽。

### 6.3 工单 + AI 并排

`S | C(看板) | D(工单 | 对话)`（一键分屏）  

- 仅 D 内部分栏；禁止再出现第三列 fixed Chat。

### 6.4 工单内打开 md / diff

`S | C(file 或 diff Tab) | D(仍挂该工单)`  

- 可选：C 内再分屏 md∥diff。  
- 文件列表可留在 D 工单区，点击只切换 C。

### 6.5 专注对话（可选）

允许 D 最大化或仅 C+D 对话（后置）；**不得**破坏 R1–R4。

## 七、Shell API 契约（约束实现）

实施时应提供单一入口（名称可调整，语义必须具备），例如挂在 `window.adsShell` 或模块 `shell.js`：

```ts
// 伪代码 — 约束语义，非最终签名
type RightTab = 'ticket' | 'chat';
type MainTab =
  | { type: 'page'; pageId: string }
  | { type: 'file'; path: string; preview?: boolean }
  | { type: 'diff'; ticketId?: string; path?: string; base?: string; head?: string };

interface ShellState {
  sidebarCollapsed: boolean;
  rightOpen: boolean;
  rightMode: 'tab' | 'split';
  rightTab: RightTab;          // tab 模式当前页
  rightSplitRatio: number;     // 0~1，split 时左侧（工单）占比
  bottomCollapsed: boolean;
  bottomHeight: number;
  activeTicketId: string | null;
  mainTabs: MainTab[];
  mainActiveIndex: number;
}

shell.getState(): ShellState;
shell.setSidebarCollapsed(v: boolean): void;
shell.openRight(opts: { tab?: RightTab; ticketId?: string; split?: boolean }): void;
shell.closeRight(): void;
shell.setRightMode(mode: 'tab' | 'split'): void;
shell.toggleRightSplit(): void;   // 一键分屏 / 合并
shell.openMain(tab: MainTab, opts?: { activate?: boolean; splitBeside?: boolean }): void;
shell.closeMainTab(index: number): void;
shell.setBottomCollapsed(v: boolean): void;
```

**约束**：

- 业务代码（看板点击、AI 文件链接、仓库打开文件）**只调 shell API**，不得直接改 `body.classList` 多套占位 class 作为长期方案。
- 状态变更必须驱动**一处**布局渲染函数（如 `renderShellLayout(state)`）。
- 关键状态写入 `localStorage`（键名统一 `ads.shell.*` 前缀）。

## 八、状态持久化

| 键 | 含义 | 默认 |
|---|---|---|
| `ads.shell.sidebarCollapsed` | 侧栏收起 | `0` |
| `ads.shell.rightOpen` | 右栏是否打开 | `0` 或按产品：进入项目默认开对话可另议 |
| `ads.shell.rightMode` | `tab` / `split` | `tab` |
| `ads.shell.rightTab` | `ticket` / `chat` | `chat` 或上次 |
| `ads.shell.rightWidth` | D 宽度 px | 如 `480` |
| `ads.shell.rightSplitRatio` | 分屏左占比 | `0.5` |
| `ads.shell.bottomCollapsed` | 底栏收起 | `1`（建议默认收起） |
| `ads.shell.bottomHeight` | 展开高度 | 如 `200` |

不要求持久化所有 mainTabs（可会话级）；`activeTicketId` 可与现有 `chatCurrentTicketId` 合并。

## 九、分阶段实施与验收

### 阶段 1 — 止血与壳层骨架（优先）

**做**：

1. 项目页改为 Grid 三列（S / C / D）+ C 下 E（或底行策略按 4.4）。
2. Chat 迁入 D 列容器；去掉 `margin-right` 主路径。
3. 工单详情迁入 D（先 Tab，可暂不一分屏）。
4. 关闭 D 必清所有占位；回归「关工单无留白」。
5. 抽出 `shell` 状态与 `openRight` / `closeRight`。

**验收**：

- [ ] 打开工单再关闭，主舞台宽度恢复，无中间空白带。
- [ ] 仅开 AI、仅开工单、两者 Tab 切换，均无双 `padding+margin` 叠加留白。
- [ ] 刷新后侧栏收起、底栏收起、右栏宽度偏好恢复。

### 阶段 2 — 一键分屏

**做**：

1. D 标题栏「⊞ 分屏」/「合并」。
2. 分屏拖条 + `rightSplitRatio` 持久化。
3. 半边关闭语义按 4.3.3。

**验收**：

- [ ] 一键进入 `工单 | 对话`，无需手动拖浏览器窗口。
- [ ] 拖分隔条流畅；关闭 D 整栏后 C 回弹。
- [ ] Tab ↔ 分屏切换不丢失当前 `ticketId` 与对话滚动位置（尽力而为，至少不丢 ticketId）。

### 阶段 3 — 主舞台工作区 Tab（md / diff）

**做**：

1. C 支持 `page` + `file` + `diff` Tab。
2. 仓库 / 工单产出 / AI 文件链接接入 `shell.openMain`。
3. （可选）C 内 md∥diff 分屏。

**验收**：

- [ ] 从工单点 md，C 打开预览，D 仍显示该工单。
- [ ] 从 AI 变更列表点文件，C 打开 diff。
- [ ] 关闭文件 Tab 不影响 D。

### 阶段 4 — 视觉统一与导航微调

- 标题栏令牌化；底栏默认收起；emoji→图标渐进。

## 十、明确禁止清单（Code Review 用）

1. ❌ 新增 `body.xxx-open { margin-right / padding-right }` 给业务面板腾位。  
2. ❌ 工单详情与 AI 再做成两个互相独立的 fixed 右栏长期并存。  
3. ❌ 用「关面板但不关占位 class」的临时修复当成终态。  
4. ❌ md/diff 主路径做成第四列或居中大模态（临时预览除外）。  
5. ❌ 为并排工单与 AI 要求用户拖拽操作系统窗口。  
6. ❌ 左侧强行拆 Activity Bar，除非未来侧栏模式 ≥3 套且有明确切换成本论证。  
7. ❌ 业务点击处理器里散落直接操作多个 DOM 占位，绕过 shell API。
