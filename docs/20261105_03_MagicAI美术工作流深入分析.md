## 一、种类：1 个 artist Agent + 3 类生成来源

MagicAI 的美术工作流是**单 Agent（artist）**承担，但内部按资产来源分 3 类，统一暴露为 7 个 MCP 工具：

| 来源 | MCP 工具 | 实现 | 用途 |
|---|---|---|---|
| AIGC 高质量生成 | `generate_asset` | `aigc_service.py`（混元3D / Suno / SD / Replicate） | 精灵/3D模型/音乐等主资产 |
| 本地快速占位符 | `generate_sprite` / `generate_tileset` / `generate_ui_element` | 纯 PIL 绘制，无网络 | 快速打通流程的占位图 |
| 复用已有/社区资产 | `search_assets` | 查 PG + 自动下载 | 优先复用，省生成成本 |

artist 的职责边界（`20261103_08`）：**只做资产获取，不写游戏逻辑**——这是"单一职责分层"的一部分（Lead 不碰文件、designer 不碰源码、artist 不写逻辑）。

## 二、详细配置

### 2.1 工具白名单（`agent_session_config.py:169-175`）

artist 按最小权限只拿到「文件读写 + 资产库 MCP + execute」，**不拿 check/run**（那是 developer/qa 的）。这是唯一一个被禁止跑引擎检查的生成型 Agent。

### 2.2 技能注入

`pixel-art`（像素美术创作指南）应注入 artist，但 **Web 主力路径未接线**（`load_agent_prompt_with_skills()` 只定义未调用），详见对标文档第五节。

### 2.3 资产类型枚举

```
type: 3d-model / sprite / texture / music / sfx / animation / vfx / tileset / ui
source: ai-generated / uploaded / marketplace
category: art / ai
```

### 2.4 目录自动归类（`_determine_asset_subdir`）

```
sprite→sprites/     texture→textures/    3d-model→models/
music→sounds/music/ sfx→sounds/sfx/      animation→animations/
vfx→effects/        其他→generated/
```

### 2.5 四级获取优先级（prompt 约定，非代码强制）

这是 artist.md 里的核心约束：

```
🥇 search_assets        （MANDATORY FIRST，先搜库自动下载）
🥈 generate_asset       （AIGC，仅搜不到时）
🥉 本地 PIL             （generate_sprite/tileset/ui_element）
❌ godot_execute_command （跑 PIL 脚本，最后兜底）
```

要求「每项资产都必须有 search_assets 调用记录为证据」——但这是 **prompt 约定，代码无强制**（`20261104_01` 明确指出）。

### 2.5.1 asset_library_mcp 工具完整清单（7 个）

代码位置：`game_agent/mcp/asset_library_mcp/tools.py`（ASSET_LIBRARY_TOOLS，198-435 行）。

| 工具 | 类别 | 说明 | 关键参数 |
|---|---|---|---|
| `search_assets` | AIGC 服务 | 搜本地+社区共享资产，自动下载到项目目录，编辑器模式同步 | query / asset_type / limit / auto_download / target_dir |
| `generate_asset` | AIGC 服务 | 调 AIGC（混元等）生成高质量资产，自动保存+注册资产库 | prompt / asset_type / name / width / height / style / wait_for_completion |
| `list_user_assets` | 资产查询 | 列出用户所有资产 | owner_id / asset_type / limit |
| `get_asset_info` | 资产查询 | 获取资产详情（预览图/下载链接/标签） | asset_id |
| `generate_sprite` | 本地 PIL | 像素精灵占位符（player/enemy/item/npc/obstacle 样式，gameboy/nes/pico8 调色板） | style / size / palette / output_path |
| `generate_tileset` | 本地 PIL | 瓦片集（grass/dungeon/space/desert 主题） | tile_size / columns / rows / theme / output_path |
| `generate_ui_element` | 本地 PIL | UI 元素（button/panel/icon/health_bar/dialog_box） | element_type / width / height / output_path |

**遗留 server**：`asset_gen_mcp`（`tools.py`）另有 3 个工具 `generate_sprite` / `generate_tileset` / `generate_ui_element`，与上面 3 个 PIL 工具**完全重叠**——早期资产生成实现，基本废弃（`20261104_01` 列为历史遗留）。

### 2.6 元数据 Schema（PG `assets` 表）

```
id(asset_<12hex>)  name  author_id(FK→users)
type  category(art/ai)  source(ai-generated/uploaded/marketplace)
file_url / preview_url / file_hash / local_path / file_size
prompt  tags(ARRAY)  license  is_shared  status
download_count  is_free/price/token_price(预留定价)
```

## 三、调度机制

### 3.1 Agent 层调度（GameDirector 编排）

```
GameDirector（Lead，只有 Task 工具）
  Phase 1 设计：designer 写 gameplay_tech + art_requirements.md
  Phase 2 资产生成 + 开发（★ 严格串行）
    artist 先（资产先存在）
    developer 后（引用真实资产路径）
  Phase 3 QA → 失败回 Phase 2（≤3 次）
```

**调度约束**：一次只调一个 Agent，等返回再调下一个，禁并行；GameDirector 通过 `<todo_list>`/`<todo_done>` 独占 TODO。

### 3.2 资产层调度（MCP 工具内部）

artist 通过 `asset_library_mcp` 的 7 个工具操作资产，工具内部隐藏了来源差异：

```
Agent(artist)
  → asset_library_mcp.generate_asset(prompt, type)
    → aigc_service.generate() → 提交混元/Suno → 内存 _task_store
    → 轮询 query(task_id) → COMPLETED + file_url
    → register_completed_task_as_asset()
      → AssetService.register() → 写 PG assets 表
      → 下载 file_url 到项目 assets/{subdir}/{name}.ext
      → _sync_file_to_editor() 同步 Godot 编辑器
```

### 3.3 编辑器同步（`_sync_file_to_editor`）

```
HTTP transfer 优先（stage_file_for_download 生成临时 URL → 编辑器 pull_file_from_server）
  ↓ 失败
base64 MCP fallback
（512KB 阈值切换）
```

### 3.4 路径纠偏（`AssetLibraryContext.fix_output_path()`）

把 Agent 传的相对路径/错误绝对路径**强制归位**到当前项目目录，防止 LLM 写到别的项目/宿主盘——这是代码级安全约束。

### 3.5 搜索与复用调度

```
search_assets(query)
  → AssetService.search(include_shared=True)
    → 本人资产 + is_shared=True 社区资产（两次查询）
    → 内存去重合并
  → get_asset_file(asset_id)
    → local_path 缓存命中？ 直接返回
    → 否则拉 file_url + 算 MD5 + 回写 local_path/file_hash + 下载计数+1
```

## 四、资产生命周期

```
生成请求 → AIGCTask(内存 _task_store)
  → 轮询 query() → COMPLETED
  → register_completed_task_as_asset()   # auto_register_asset
    → AssetCreate → register() → PG assets 表
      → 下载到项目 assets/{subdir}/
        → _sync_file_to_editor()
```

关键细节：
- `auto_register_asset`：query() 完成时自动注册，`_asset_id` 写回 `task.params`
- `_registered_asset_tasks` 内存 set 防重注册

## 五、风险点（`20261103_04` 明确列出）

| # | 风险 | 说明 |
|---|---|---|
| 1 | **AIGC 任务态纯内存** | `_task_store = {}`，重启丢失所有 in-flight 任务与 `_asset_id` 关联 —— 最大持久化缺口 |
| 2 | **文件无自有对象存储** | `file_url` 指向第三方临时 URL，可能过期 |
| 3 | **缓存落 home** | `~/MagicDawn/assets`，多实例部署不共享、易漂移 |
| 4 | **标签硬匹配** | `extract_tags_from_prompt` 40 词库，无向量/语义搜索 |
| 5 | **分享无审核** | `is_shared` 仅布尔，无内容审核、无下载频率控制 |
| 6 | **pixel-art 技能失效** | Web 路径未注入（Skills 注入失效的美术版） |
| 7 | **优先级无代码强制** | 四级 fallback 只写 prompt，artist 可跳过 search 直接 AIGC |

## 六、与本系统对标（对称结论）

| 维度 | MagicAI | 本系统 |
|---|---|---|
| 美术 Agent 数量 | 1（artist） | 3（UXAgent/ArtAgent/ArtistAgent） |
| 职责边界 | artist 只做资产获取 | ArtAgent(要什么)/ArtistAgent(从哪来) 分离 |
| 调度方式 | GameDirector Task 委派 + prompt 串行约束 | SOP YAML 状态机 + traits 条件（代码强制） |

- MagicAI 可学本系统：任务态持久化（image_requests 表 vs 内存 dict）、代码强制优先级。

## 七、接入评估：路径纠偏 + 双通道同步（2026-11-05）

### 7.1 路径纠偏（fix_output_path）— 值得做，缺口明确

**本系统现状**（`ue_mcp_server.py::_ue_import_asset_impl`，266-362 行）：

| 校验 | 状态 | 位置 |
|---|---|---|
| UE 内路径白名单（`/Game/` 前缀） | ✅ 已有 | :308 |
| 本地文件存在校验（`.exists()`） | ✅ 已有 | :299 |
| **本地路径归一化（`resolve()`）** | ❌ 缺 | — |
| **本地路径越权拦截（白名单根目录）** | ❌ 缺 | — |
| **路径转义（防注入 UE Python 代码）** | ⚠️ 半缺 | :318 直接 f-string 拼接 |

**风险点**：当 `ART_ASSETS_LOCAL_PATH` 未配置时，`file_path` 被直接当绝对路径用（:287 `elif rel_path: abs_path = rel_path`），无任何目录约束；`abs_path` 又直接 f-string 拼进 UE Python 代码（:318），理论上存在路径注入/越权。

**接入方案**（最小改动，在第 2 步后加）：

```python
from pathlib import Path as _P
from config import DATA_DIR

_p = _P(abs_path).resolve()                      # 归一化
_allowed = []
if settings.ART_ASSETS_LOCAL_PATH:
    _allowed.append(_P(settings.ART_ASSETS_LOCAL_PATH).resolve())
_allowed.append(_P(DATA_DIR) / "session_materials")

if not any(str(_p).startswith(str(r)) for r in _allowed):
    return {"success": False, "message": "文件路径越出资产库/会话素材范围，拒绝导入"}
abs_path = str(_p)
```

对应 MagicAI 的 `fix_output_path()` + `ensure_within_project_dir()`（file_tools.py:628-679）。

### 7.2 双通道同步（HTTP/base64）— 当前不适用，暂缓

**关键判断**：本系统 UE Editor 与后端**同机**运行（`ue_python_bridge.py` UDP 多播发现 + TCP 执行），`AssetImportTask.filename` 直接填本地磁盘绝对路径，UE 自己读文件——**不存在跨进程文件传输需求**。

MagicAI 需要 HTTP/base64 双通道，是因为它的 Godot 编辑器跑在**浏览器 WASM** 里，服务端文件浏览器访问不到，必须主动推给编辑器。两者架构前提不同。

**触发条件**（未来才需要，记入扩展项）：
1. UE Editor 远程化（云 UE / 多机协作 / 远程桌面）
2. 生图在服务端、Editor 在另一台机器

**若未来需要的映射**：
- HTTP transfer → 内部静态文件服务 + UE Python `urllib` 下载（需放宽 UE Python 沙盒网络限制）
- base64 fallback → 小文件 base64 编码后经 `run_python` 的 code 字符串注入（受 remote_execution code 长度限制，base64 膨胀 33%）

**结论**：暂缓，等远程 UE 需求出现。

### 7.3 启发与待办

1. **路径纠偏（可立即做）**：`_ue_import_asset_impl` 补 `resolve()` 归一化 + 白名单根目录拦截 + 路径转义。代价小、收益是堵住越权/注入口。
2. **双通道同步（暂缓）**：当前同机架构不需要，等 UE Editor 远程化再评估。
3. **AIGC 任务态持久化**：MagicAI 反例印证本系统 `image_requests` 表设计正确——异步任务必须落库，不能纯内存。
