## 一、要改的是什么

片段搬家之后，UE 工单「做完这一步写哪个状态」仍写在宿主里，而且按 action 名字分支：

| 位置 | 现在 |
|---|---|
| `orchestrator.py` DevAgent 分支 | `run_engine_compile` 写死 `engine_compile_passed` / `engine_compile_failed`，并直接调用 `_resolve_compile_bug` / `_create_compile_bug` |
| 同文件 | `generate_ue_tests` 单独 return。少了这段会把状态写回 `development_done`，工单空转，还会用 `type=code` 的 artifact 盖掉 `dev_result` |
| 同文件 TestAgent 分支 | `run_playtest` 写死 `play_test_passed` / `play_test_failed`；成功调 `_maybe_openspec_verify`；失败且有 `module_load_errors` 时调 `_try_uproject_heal` |
| 同文件派单处 | `action == "run_engine_compile"` 且是非代码工单时，跳到写死的 `engine_compile_passed` |
| `agents/dev.py`、`agents/test.py` | `execute` 用任务名选择 Action。名字对不上就返回「未知任务」 |

副作用（建 Bug、勾销 Bug、OpenSpec Verify、uproject 自愈）跟状态字符串绑在同一段 `if` 里。只改 YAML 的 `success_status` 不会生效，宿主仍写旧字符串。

本方案把「写状态」收成宿主的一种通用收尾，把「这一步成功或失败后还要做什么」收成片段里的钩子名。钩子的实现放在 `backend/plugins/ue5/pipeline.py`。宿主只保留名字到函数的表，不新增 `if action == "run_engine_compile"` 这类分支。

---

## 二、收尾规则

Agent 返回之后、按 Agent 类型分叉之前，宿主查这个项目 SOP 里 `action` 对应的阶段。

阶段上有 `closeout: status` 时：

1. `result.status == "success"` → 工单状态写成该阶段的 `success_status`，记一条 complete 日志，再按顺序跑 `on_success`。
2. 其他非 `error` 的结果 → 先按顺序跑 `on_failure`。某个钩子返回 `rewind_to_stage` 时，把工单拨到那个阶段在**组合结果**里的 `trigger_on`，然后结束。没有任何钩子要求回跳时，写成 `reject_status`，记一条 reject 日志。
3. 处理完直接 return。不进入 develop 的产物落库，不插入 `type=code` 的 artifact。

`result.status == "error"` 仍走现有的 blocked 分支，发生在收尾之前。缺引擎、缺 UBT、Playtest 超时且没有测试行，这些继续是 `error`，不会变成 `*_failed`。

`closeout` 不写在阶段上时，宿主保持原路径。这次不改：

- `develop` / `rework` / `fix_issues`
- `run_tests`
- `run_h5_typecheck` / `run_h5_playtest`（它们已经在读 SOP 状态，分支留着）
- `run_ci_deploy`（`deploy_ue` 和 `deploy_web` 共用这个 action，不能打上 `closeout: status`）

`success_status` 或 `reject_status` 为空时不写工单状态，打错误日志并 return，避免掉进 develop 收尾。

## 三、回跳写哪个状态

`sop.loader._relink_stage_transitions` 会覆盖片段手写的 `trigger_on`。线性阶段的触发状态等于上一阶段的 `success_status`。

UE 默认顺序是 `ue_test_gen` → `engine_compile` → `play_test`。组合之后，编译阶段的 `trigger_on` 是 `ue_test_gen_passed`，不是 YAML 里写的 `engine_compile_pending`。规则表里没有 `engine_compile_pending` 这个键，也没有阶段 id `engine_compile`。

现在的自愈代码把状态写成 `"engine_compile"`。工单会停在一个没有派单规则的状态上。

自愈成功后应写成编译阶段在组合结果里的 `trigger_on`。按当前片段，这就是 `ue_test_gen_passed`：这个状态的规则启动的是 `run_engine_compile`，不会把测试生成再跑一遍。钩子只返回阶段 id `engine_compile`，由宿主到组合后的阶段列表里取 `trigger_on`。找不到这个阶段时不回跳，试玩按失败收尾。

## 四、片段上要加的字段

字段放在 `stage:` 里面。`compose_sop` 把 `stage` 字典原样放进组合结果，收尾读得到。

`backend/plugins/ue5/fragments/engine_compile.yaml`：

```yaml
stage:
  closeout: status
  skip_when: noncode_ticket
  on_success: [resolve_compile_bug]
  on_failure: [create_compile_bug]
```

`play_test.yaml`：

```yaml
stage:
  closeout: status
  on_success: [openspec_verify]
  on_failure: [uproject_heal]
```

`ue_test_gen.yaml` 只加 `closeout: status`。生成器本来就恒为 success；这个标记的作用是成功后立刻 return，不写 code artifact。

`deploy_ue.yaml`、`ue_content_gen.yaml` 不加。

派单处读 `skip_when`。值为 `noncode_ticket` 且工单命中现有的非代码判断时，跳到该阶段的 `success_status`，不再判断 `action == "run_engine_compile"`，也不再写死跳转目标。UX / 美术的跳过逻辑不动。

## 五、钩子

`backend/plugins/ue5/pipeline.py` 导出 `STAGE_HOOKS`。`plugins.registry.stage_hook(name)` 扫描各插件的 `pipeline.py` 收成一张表。重名时打错误日志，后加载的覆盖先加载的。

| 名字 | 行为 |
|---|---|
| `resolve_compile_bug` | 调用宿主现有的 `_resolve_compile_bug` |
| `create_compile_bug` | 调用宿主现有的 `_create_compile_bug`。日志补上一句「已创建 Bug 记录」 |
| `openspec_verify` | 调用 `_maybe_openspec_verify`，`stage_label` 用阶段 id |
| `uproject_heal` | 没有 `module_load_errors` 时什么都不做。有错误时调用 `_try_uproject_heal`。`healed` 为真则返回 `rewind_to_stage: engine_compile`。没有补上插件时返回一句「已尝试 uproject 自愈，无有效插件可补充」，宿主把它接到失败日志上，状态仍是 `play_test_failed` |

钩子抛错只记警告，不挡住状态写入。失败钩子里第一个成功回跳的生效，后面的钩子不再跑。

Action 名和状态名都不改：`run_engine_compile`、`run_playtest`、`generate_ue_tests`、`engine_compile_passed`、`play_test_failed` 等保持原样。在途工单和反思模块认的是这些字符串。

## 六、Agent 派发

`DevAgent.execute` 和 `TestAgent.execute` 在现有分支之后加一层：`create_action(task_name)` 能建出实例就执行它。建不出才返回「未知任务」。

现有分支留在前面。`run_engine_compile` 仍进 `_do_run_engine_compile`（内部是 `ue_compile_check`），`run_playtest` 仍进现在的 `run_playtest`。这层兜底只给尚未写进 `execute` 的新 Action 用。

`run_ci_deploy` 仍由 `DeployAgent` 按 traits 选 `ci/strategies/`。`ci/strategies/ue.py` 这次不搬进插件。

## 八、验收

- UE 阶段顺序仍是测试生成、编译、试玩、打包。
- `engine:godot4` 和 `engine:unity` 的组合结果里没有 `engine_compile`、`play_test`、`deploy_ue`。
- 三个 UE 阶段带 `closeout: status`。编译阶段带 `skip_when: noncode_ticket` 和两个 Bug 钩子。试玩阶段带 Verify 和自愈钩子。`run_ci_deploy` 的阶段没有 `closeout: status`。
- 编译失败会建 Bug，编译成功会把关联的 `in_dev` Bug 标为 fixed。这两件事由钩子调用现有函数完成。
- 试玩成功会触发 OpenSpec Verify。缺模块且自愈成功时，工单状态是组合后的编译 `trigger_on`（当前为 `ue_test_gen_passed`），不是 `engine_compile`，也不是 `engine_compile_pending`。自愈没有补上插件时，状态是 `play_test_failed`。
- `generate_ue_tests` 成功写成 `ue_test_gen_passed`，并且因为 `closeout: status` 在产物落库前 return。
- 非代码工单跳过编译时，目标状态来自该阶段的 `success_status`。
- `DevAgent` / `TestAgent` 对已注册、但 `execute` 里没有具名分支的 Action 会执行它；完全未注册的任务名仍返回 error。具名分支仍优先：`run_engine_compile`、`run_playtest` 不会被这层兜底截走。

落地时核对过的行为都在 `backend/tests/plugins/test_ue5_closeout.py`。上面这组回归已通过。
