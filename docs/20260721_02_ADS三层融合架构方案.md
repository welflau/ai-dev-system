## 一、背景：三层架构全景

基于《OpenSpec ≠ Harness Engineering》文档，AI 工程化存在三个独立但互补的层次：

| 层级 | 工具 | 职责 | 类比 |
|---|---|---|---|
| **规范层** | OpenSpec | "做什么" — proposal/specs/design/tasks | 产品经理 / 施工图纸 |
| **纪律层** | Superpowers | "怎么做" — TDD/调试/验证/Worktree 铁律 | 施工规范手册 |
| **编排层** | Harness / ADS | 多 Agent 协作、权限、门禁、反馈回路 | 公司制度 / 项目经理 |

**铁律**：没进 OpenSpec 之前，任何人（包括 Agent）不准动手写代码。

**缺哪层就有哪种症状**：

| 缺 | 症状 |
|---|---|
| 缺 OpenSpec | Agent 各做各的，返工率高，无"真相源"文档 |
| 缺 Superpowers | 不写测试不审查，代码质量失控，声称完成但没验证 |
| 缺 Harness | 多 Agent 协作混乱，权限冲突，并行变串行 |

## 二、ADS 当前位置

```
规范层  OpenSpec      ← ADS 没有这层，需求直接进了 Agent
纪律层  Superpowers   ← ADS 没有这层（已打包为 Pack，待注入）
编排层  Harness       ← ADS 本质上是这层，但不完整
```

**ADS 已有**（Harness 已实现部分）：
- 多 Agent 流水线（Architect/Dev/Test/Review/Deploy）
- PermissionGate 权限门禁
- PreToolUse/PostToolUse Hooks
- 评论参与系统（异步人工反馈回路）
- Ticket 时间轴日志

**ADS 缺失**：
- OpenSpec 规范生成与验证
- Superpowers 执行纪律注入（TDD/调试/验证铁律）
- 生成者与评审者分离（ReviewAgent 和 DevAgent 同模型实例）
- 关键里程碑通知
- 三层可观测性

## 三、把关方式：自动化与人工的折中

**不采用 OpenSpec 同步阻塞门禁**（影响自动化速度），而是：

> 人通过工单评论参与，作为**异步非阻塞的人工把关**。

| 触发 | 机制 |
|---|---|
| 关键里程碑 | 系统推送通知，人看一眼决定是否介入 |
| 异常/阻塞 | 自动暂停 + 等待人工评论 |
| 人主动评论 | Agent 以最高优先级响应，调整方向 |

ADS 评论系统 = Harness 反馈回路的人工扩展版：**人发现问题 → 评论 → Agent 收到 → 修正 → 继续**

## 八、一句话原则

> **ADS 负责编排自动化（速度），Superpowers 负责 Agent 纪律（质量），OpenSpec 负责需求对齐（规范），人通过评论+通知参与把关（安全）。四者缺一，则失速、失质、失准、失控。**

> **时间轴 = 过程记录，三层总览栏 = 状态快照，OpenSpec 面板 = 规范对照，思考面板 = 执行细节。四个视角组合，人随时知道"AI 在做什么、依据什么、到哪一步了、有没有出轨"。**
